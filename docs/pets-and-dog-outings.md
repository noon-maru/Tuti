# 선택 반려동물 프로필과 동반 조건

기준: 2026-11-17 코드·개발 DB 적용. 운영 DB 적용·실기기 검증·시설별 조건 확인 완료를 뜻하지 않는다.

현재 추천 판정과 선택 질문은 [2.0.0 현재 장소 한정 정책](./dog-outing-v2-policy.md)을 우선한다.
v1의 부족분 자동 대체와 시간 가점만 사용하던 정책은 v2에서 변경했다.

## 선택 프로필

설정의 `함께하는 반려동물`(`/pets`)에서 이름·종류(반려견/반려묘)·선택 몸무게를 등록·수정·삭제한다.
프로필은 50개까지, 마디 연결은 0~20개까지 허용한다. 기록 작성에는 프로필이 필요하지 않다.
마디 작성의 접힌 선택 항목에서 여러 프로필을 고른다. 초안에도 계정별로 선택 ID를 보존한다.
등록된 프로필이 없으면 같은 선택 항목의 `새 반려동물 등록`에서 작성 화면을 떠나지 않고 등록할 수 있다.
등록은 자동 연결이 아니다. 등록 후 체크한 프로필만 마디 저장 시 연결하며, 프로필 없이도 그대로 저장할 수 있다.
삭제되거나 권한이 없는 프로필이 포함된 저장은 원본 작성 전체를 롤백하고 초안을 유지한다.
선택을 수정하지 않는 기존 수정 요청은 기존 연결을 유지한다.

등록·수정·삭제는 실행 중 재입력을 잠그며 삭제 확인 중에도 저장을 중복 실행하지 않는다.
저장 성공 응답을 받은 프로필은 계정별 Query 캐시에 먼저 반영한다. 이후 목록 재조회 실패를 저장 실패로 표시하지 않는다.
수정 실패 시 입력은 유지하며, 충돌 시 `최신 내용으로 다시 채우기`를 직접 눌러 서버의 revision과 내용을 다시 받는다.
수정 중인 프로필을 삭제하면 수정 상태도 해제한다. 관리 목록은 종류·선택 몸무게를 함께 표시한다.

- 프로필은 작성자나 공유 권한이 아니다. 같은 프로필·이름만으로 다른 사람의 기록을 조회하지 않는다.
- 프로필 목록과 연결 정보는 본인 마디 목록에서만 제공한다. 공동 책·공개 기록·PDF 직렬화에 프로필을 자동 추가하지 않는다.
- 수정은 revision으로 충돌을 감지한다. 프로필 삭제는 연결만 연쇄 삭제하며 원본 마디·책·댓글·이미지·PDF는 유지한다.
- 계정 병합은 두 계정 잠금 안에서 프로필 소유권도 이전한다. 같은 이름이라도 자동 합치지 않는다.
- 계정 삭제는 User FK로 프로필과 연결도 삭제한다. 프로필 단독 삭제는 `pet_deleted` 서명 원장으로 복원 방지한다.
- 기기 초안의 프로필 ID는 본문·사진과 같은 계정별 초안 정리·만료 통제를 따른다. 새 프로필 이름·사진을 책 읽기 캐시에 추가하지 않는다.

## 반려견 동반 추천

화면 명칭은 `나들이`다. 반려견 동반 여부 → 시간 → 차량 순서로 질문하며,
명시적으로 `반려견과 함께 가요`를 선택한 경우에만 동반 카탈로그·제한 판정을 적용한다.
비동반·미응답은 전체 열람 가능 장소를 대상으로 새 엔진을 사용한다. 구 저부담 엔진으로 돌아가지 않는다.
동반 시 카테고리를 복수 선택할 수 있고 마지막 질문의 `조금 더 맞추기`에서 공간·몸무게·준비물을 입력한다.
나들이 메인에는 조건 패널을 상시 표시하지 않으며 메뉴의 `외출 조건 변경`으로 다시 연다.
프로필은 필요하지 않고 미입력은 미준비로 해석하지 않는다. 세부 제한 미확인은 방문 전 확인으로 안내한다.

등록한 반려견이 있으면 목록에서 **이번에 함께 가는 반려견만 선택**하고 `선택한 몸무게 불러오기`를 누른다.
처음부터 자동 선택·반영하지 않으며, 반려묘 프로필은 동반견 선택에 나오지 않는다.
선택한 반려견 중 몸무게가 없는 프로필이 하나라도 있으면 일부만 반영하지 않고 직접 입력을 안내한다.
불러온 뒤에도 몸무게를 자유롭게 수정할 수 있다. 선택한 프로필 ID·이름은 추천 요청에 보내지 않고 몸무게만 초안에 넣는다.
프로필 재조회·수정은 이미 선택한 외출 조건을 자동 변경하지 않는다. 질문 취소 시 기존 추천 조건도 그대로다.

몸무게·필수 준비 조건·선택 카테고리는 후보 적격성이다. 카테고리 복수 선택은 합집합이며 다른 유형으로 부족분을 채우지 않는다.
일반 장소 후보를 고른 후 최종 몇 개만 거르는 것이 아니라,
지역·거리 후보를 읽은 뒤 가점·다양성·대체 후보 선정 전에 적격성 검사를 한다. 장거리도 같은 검사를 적용한다.
검사 조회 실패는 요청 실패이며 일반 추천으로 통과시키지 않는다. 결과가 부족해도 공식 동반 등록 근거가 없는 일반 장소로 채우지 않는다.

| 판정 | 기준 |
| --- | --- |
| 충족 | 유효한 출처·확인 기간이 있고 동반 가능하며, 선택한 모든 반려견과 준비 조건이 제한을 충족 |
| 불충족 | 유효한 자료상 동반 불가, 몸무게 초과 또는 필수 목줄·이동장 조건 불충족 |
| 미확인 | 자료 없음·출처 형식 오류·미래 확인일·유효기간 만료 또는 크기 제한이 있는데 몸무게 미입력 |

운영자 검토 자료는 입력한 조건의 충족 여부로 판정한다. 조건을 선택하지 않았으면 준비 상태 확인 안내를 붙인다.
2026-11-17 사용자 결정에 따라 국문 API의 공식 등록 장소는 세부 조건이
미확인이어도 `동반 등록 장소 · 방문 전 조건 확인 필요`로 구분해 포함한다. 공식 구역 표기가 없거나
오래된 자료, 추출 가능한 몸무게 초과·목줄/이동장 조건 불충족은 제외한다. 별도 검토 자료가 있으면
이를 우선하며, 동반 불가·조건 불충족·만료된 검토 자료를 API 원문으로 우회하지 않는다.

공식 자료는 시설에서 직접 확인한 자료로 승격하지 않는다. 동반견 설명·준비물·추가 조건 원문과 수집일·출처를
표시하며 빈 항목은 미기재로 표시한다. 견종·맹견·예방접종·매장별 구역 등 자유문 조건은 자동 판정하지 않는다.
수집 후 30일은 추천용 원문 신선도 한도이며 시설 정책의 보장 기간이 아니다. 만료되면 재수집 전까지 제외한다.
구 일반 후보 승인·활성·저부담 점수는 새 엔진의 적격 조건이 아니다. 지역·거리와 명시적 운영 제외는 유지한다.

검토 자료는 허용 구역·추가 규칙·몸무게·필수 준비·확인일·출처를 사용자에게 표시한다.
자료는 특정 공간·조건의 안내이지 모든 구역이나 상황의 안전 보증이 아니다. 기록의 장소 자동완성·자유 입력에는
이 동반 필터를 적용하지 않는다.

동반 조건과 계정을 Query 키로 구분하고 현재 추천 목록·순서·선택 위치·조건을 기기에 보존한다.
날짜 변경·새로고침·화면 재진입만으로 목록을 바꾸지 않는다. 명시적 조건 변경·지역 변경·재추천 또는
위치 오차를 제외한 1km 이상 이동이 두 번 확인될 때 갱신한다. 주간 재질문은 유지하되 조건 재사용은 목록을 보존한다.
위치 철회·계정 변경 시 캐시 통제와 이동 판정의 전체 기준은 [현재 추천 목록 유지](./dog-outing-v2-policy.md#현재-추천-목록-유지-2026-11-17)를 따른다.

## 실제 장소 조건 입력

### 공식 API 원문 수집

국문 [TourAPI](https://www.data.go.kr/data/15101578/openapi.do)와
[한국관광공사 반려동물 동반여행 서비스](https://www.data.go.kr/data/15135102/openapi.do)를 수집할 수 있다.
**기본 수집원과 추천 원문은 국문 API다.** 전용 API와 `both`는 비교·보완 목적으로 명시 실행하며 추천에서 자동 대체하지 않는다.
확보한 전용 988건은 국문 자료와 콘텐츠 ID·상세 원문 모두 100% 동일했다. 미수집분 동일성까지 보장하지는 않는다.
두 서비스 모두 기존 `DATA_GO_KR_API_KEY`를 사용하며 별도 환경변수는 추가하지 않는다.

- 국문 `KorService2/detailPetTour2`: 콘텐츠 ID를 생략한 동반 정보 목록을 페이지 단위 수집한다.
- 전용 `KorPetTourService2/areaBasedList2`: 목록을 받은 뒤 각 콘텐츠 ID로 `detailPetTour2`를 조회한다.
- 같은 콘텐츠 ID라도 `source=kor|pet`별 원문과 전용 목록 원문을 따로 보존한다. ID만으로 두 출처를 덮어쓰지 않는다.
- 기존 `Place.source=tourapi`와 `sourceId=contentid`가 정확히 일치할 때만 연결한다. 미매칭 원문도 보존하며 장소를 자동 생성·추천 승인하지 않는다.
- `fetchedAt`은 수집 시각, `providerModifiedAt`은 제공자 수정 표기다. 시설 확인 시각이 아니며 `facilityVerifiedAt`은 null로 남긴다.
- 빈 조건은 미확인이다. 목줄·이동장·견종·몸무게를 자유문에서 임의 추론하거나 누락을 제한 없음으로 바꾸지 않는다.
- 수집은 검토된 `DogPlaceAccess`를 수정하지 않는다. 아래의 조건 확인·입력 단계와 분리한다.

연결 확인과 소량 파일 수집은 DB 없이 가능하다. 실행 환경에 기존 키를 주입하되 키를 명령 인자나 로그에 넣지 않는다.
호스트 `.env`를 사용하는 예시는 다음과 같다. 파일의 원문을 출력하지 않는다.

```sh
node --env-file=.env --import tsx scripts/probe-pet-tourism.ts
node --env-file=.env --import tsx scripts/collect-pet-tourism.ts --source both --pages 1 --rows 10 --max-requests 20
```

기본은 실제 API를 호출해 파일만 저장하는 `artifact-only` 모드다. dry-run이 아니다.
결과는 Git에서 제외한 `.tourism-data/pet-tourism/<실행 ID>/`에 0600 JSONL로 저장한다.
출력 디렉터리는 새로 만들며 0700으로 명시 조정한다. 파일도 DSM 상속 ACL을 고려해 생성 후 0600으로 조정한다.
기존 디렉터리·파일을 덮어쓰지 않는다. 임의 `--output`은 아직 없는 경로를 지정하고 Git 외부의 안전한 경로를 선택한다.
터미널에는 출처·건수·요청 수·다음 페이지·완료 여부만 출력한다. 원문은 파일에서 별도 검토한다.

DB 저장은 새 클라이언트와 `20261116030000_tourism_pet_sources` 마이그레이션 적용 후에만 `--apply`로 실행한다.
`--apply`도 원문 파일을 먼저 동기화하고 페이지 전체 DB 트랜잭션이 성공한 뒤 진행 기록을 남긴다.
저장 오류 시 해당 페이지는 완료 처리하지 않는다. 재시도는 같은 출처·콘텐츠 ID에 중복 행을 만들지 않으며
이전 수집 시각의 응답으로 최신 자료를 덮어쓰지 않는다. 원문 파일 수집만으로 운영 DB가 채워지지는 않는다.
전용 API 상세 수집이 중단된 페이지는 이미 받은 원문을 `pet-partial-page-<쪽>.jsonl`로 별도 보존한다.
이 파일은 DB에 적용하거나 완료 체크포인트로 간주하지 않는다. 재개 시 해당 페이지 전체를 다시 조회한다.

```sh
# 마이그레이션을 적용한 대상 DB와 기존 키를 주입한 실행 환경에서 실행
pnpm tourism:pets:collect --source kor --start-page 1 --pages 100 --rows 100 --max-requests 100 --apply
pnpm tourism:pets:collect --source pet --start-page 1 --pages 9 --rows 100 --max-requests 1000 --apply
```

상한은 페이지 1,000개·페이지당 100건·출처별 요청 1,000회다. `both`이면 요청 상한은 각 출처에 적용된다.
전용 API는 목록 1회와 상세 최대 100회가 한 페이지이므로 위 예시는 최대 909회다.
전체 페이지를 끝낼 호출 예산이 없으면 다음 페이지 조회 전에 중단하며 `complete=false`를 반환한다.
진행 파일의 마지막 `nextPage`부터 **같은 rows 값**으로 새 디렉터리에 이어 수집한다. 페이지 크기를 바꾸면 처음부터 다시 수집한다.
전국 수집은 제공자의 실제 활용 한도를 확인한 뒤 배치별 진행 기록을 기준으로 나눠 실행한다.
자동 예약·무제한 재시도·전국 완료 보장은 추가하지 않았다. 제공 목록이 바뀔 수 있으므로 완료는 해당 실행에서 관측한 페이지 범위의 완료다.

2026-11-16 실제 연결 및 수집 검증: 국문 10건(1회), 전용 10건(목록 1회·상세 10회)을 파일로 저장했다.
관측한 제공자 전체 건수는 각각 9,634건·9,632건이며, 수집 완료 건수나 기존 장소 매칭 건수가 아니다.
두 출처의 합이 서로 다른 장소 수라는 뜻도 아니다. 실제 원문과 진행 기록은
`.tourism-data/pet-tourism/2026-11-16T07-53-57-447Z-c3c54363/`에 보관했다.
운영·개발 DB 마이그레이션과 전국 DB 수집, 시설별 조건 검토·추천 연결은 아직 실행하지 않았다.

### 기존 수집 파일을 DB에 반영

`pnpm tourism:pets:import <국문.jsonl>`은 네트워크·DB 접근 없이 파일 전체의 출처·ID·날짜·중복·해시를 검사한다.
적용은 대상 DB에 세 추가형 마이그레이션과 새 Prisma 클라이언트가 준비된 뒤 다음과 같이 실행한다.

```sh
pnpm tourism:pets:import <국문.jsonl> --apply --expected-sha256 <사전검증에서_확인한_SHA256>
```

기본 출처는 `kor`이며 전용 원문 입력은 `--source pet`으로 별도 지정한다. 전용 원문은 보관만 하며 추천하지 않는다.
동일 파일을 재적용해도 출처+ID로 갱신하고 이전 수집일로 최신 자료를 덮어쓰지 않는다. 파일 전체를 먼저 검증한 뒤
100건씩 트랜잭션으로 반영하며 실패 시 `completedRecords`까지 완료된 범위를 출력한다. 파일 전체가 단일 트랜잭션은 아니다.
미매칭 원문을 보존하되 신규 장소 생성·일반 후보 자동 승인·운영자 검토 조건 덮어쓰기는 하지 않는다.

2026-11-17 개발 DB(Compose에 정의된 호스트 포트 55432)에 세 마이그레이션을 적용하고 국문 9,634건을 입력했다.
779건이 기존 장소와 매칭됐고 8,855건은 미매칭 원문으로 보존됐다. 일반 추천 후보 기준을 충족하는 매칭 장소는 269곳,
예시 조건 `8kg·목줄 착용·이동장 미사용`에서 동반 필터를 통과한 곳은 239곳이었다. 모두 공식 등록의 미확인 표시를 유지했다.

사용자 계정·마디·책을 조회하거나 변경하지 않았다.

### 검토된 조건 입력

공원·카페 분류나 소개의 단어만으로 동반 가능을 추정하지 않는다. 실제 운영 안내를 확인한 자료만

운영자가 준비한 JSON 배열은 각 항목에 `placeId`, `allowed`, `areas`, `rules`, `maxWeightKg`(제한 없으면 null),

```sh
pnpm exec tsx scripts/import-dog-place-access.ts /absolute/path/to/reviewed-dog-access.json
```

위 명령은 전체 형식·장소 존재를 확인하는 dry-run이다. 동일 파일을 검토한 뒤에만 `--apply`를 추가한다.
적용은 전체 트랜잭션이며 기존 자료도 해당 장소의 최신 확인 내용으로 교체하므로 원문·유효기간을 먼저 대조한다.

### 추천 정책 `dog-outing-v1`

공식 등록과 기본 정보 → 지역·직선거리 → 알려진 동반 제한 → 예산 → 가점·다양성 → 최대 6곳 순서다.

거리 반경은 near 5km / short 20km / half 60km / far 200km이며 자동차의 2km 하한은 유지한다.
당일/익일 선택은 장거리 숙박 여부와 예보 시점을 구분하는 데 유지한다.

가점은 검토된 동반 근거 6, 원문에 명시된 반려견 운동 시설 6, 목적 일치 18(산책·카페) 또는 12(나들이),

다시 고르기는 새 후보를 먼저 선정하고 부족분만 이전 후보로 채운다.

최초 응답은 경로·LLM·실시간 날씨 API를 기다리지 않는다. 날씨 캐시가 비면 가점을 주지 않고 응답 후 보충한다.

2026-11-16 네트워크 리스닝을 끈 임시 PostgreSQL 11에서 두 마이그레이션을 실제 적용하고,
