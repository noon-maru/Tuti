## 기록·재열람과 외출 연결

- 첫 화면은 반려동물과 살아가는 기록이라는 고객 설명과 기존 첫 마디 작성 경로를 함께 유지한다. 프로필·책 생성을 작성 조건으로 추가하지 않는다.
- 새 사용자는 약관 동의 다음에 프로필 등록을 먼저 제안받는다. `등록하고 시작하기` 또는 `건너뛰기`로 기존 시작 화면에 이어지며,
  이 단계에서는 기존 프로필을 조회하지 않고 폼을 즉시 표시한다. 이미 시작을 마친 계정에는 반복 요청하지 않는다.
  등록 실패는 입력을 보존하고, 건너뛰기만으로 프로필을 만들지 않는다.
  공유 장소 등에서 시작했으면 원래 URL·작성 의도를 그대로 이어간다. [첫 시작의 범위와 기기별 완료 표시](./pets-and-dog-outings.md#첫-시작)를 따른다.
  이 첫 시작 단계의 관련 회귀 시험 42개와 TypeScript·변경 파일 ESLint·문서 검사를 통과했다.
  기존 화면 톤을 유지한 단일 단계이며 모바일 실기기·키보드 시각 확인과 운영 반영은 별도다.
- 읽는 책의 관리 메뉴에서 `다음에 보낼 하루 찾아보기`로 이동한다. 계정과 선택 책 ID를 함께 전달하며, 작성 시 기존 서버 권한·공유 범위 재검증을 유지한다.
- 추천 장소의 작성 버튼과 출발 후 이어 남기기에 선택 책을 전달한다. 장소는 편집 가능한 제안이며 방문을 자동 확정하지 않는다.
- 책장은 현재 계정에 속한 출발 의도만 안내한다. 출발 후 안내 시각이 지났고 7일 이내인 경우에만 표시하며 나중에로 미룰 수 있다. 과거 계정 정보가 없는 상태는 책장 안내에 사용하지 않는다.
- 저장 후 책에 담은 결과에서 `방금 남긴 쪽 보기`를 제공한다. `focusEntryId`는 읽기 위치일 뿐 연결 추가·방문 생성·접근 허용을 실행하지 않는다.

### 브랜드 UX 점검 후 연결 동선 보완 (2026-11-17)

- 책에 담지 않고 마친 경우에도 완료 화면의 `방금 남긴 마디 보기`로 원본을 다시 읽는다. 마디는 있으나 책이 없는 책장에는 `남긴 마디 N개 보기`를 우선 제공한다. 자동으로 책을 만들거나 마디를 담지 않는다.
- 반려견 동반을 명시적으로 선택한 출발 준비에서는 동반 구역·몸무게·준비물과 확인 필요 안내를 먼저 보여준다. 전체 조건·출처는 펼쳐 읽으며, 공식 등록·별도 검토·미확인·기간 경과를 구분한다. 입장을 보장하거나 새 필수 확인으로 길찾기를 차단하지 않는다.
- 저장 후 담을 책 선택에서는 기존 책이 있거나 검색 결과가 없어도 `새 하루마디 만들어 담기`로 저장된 마디 ID를 이어간다. 다른 책에 담는 중에는 새 책 생성으로 이탈하지 않는다.
- 외출 후 `다녀온 마디 남기기`와 `다녀왔어요 · 기록은 나중에`를 구분한다. 후자는 방문 자기보고만 기록하며 작성 시작으로 집계하거나 작성 화면으로 이동하지 않는다. 장소·선택 책은 계정별 이어쓰기 안내에 보존하고 같은 방문 확인 질문은 다시 띄우지 않는다. 기존 7일 유효 범위와 계정 분리 조건을 유지한다.

이번 범위는 UX 점검의 1·2·4·5번이다. 3번 장소 상세의 비제스처 조작·사진 뷰어 초점 수명은 요청에 따라 변경하지 않았다.
컴포넌트 핸들러·저장 상태·렌더 회귀 시험과 정적 검사를 수행하며, iOS/Android 실기기 배치·키보드·애니메이션 확인 및 운영 배포는 별도다.

## 대표 사례·서비스 소개 정렬 (2026-11-17)

- 첫 화면·이용 방법·하루마디 예시는 반려견과의 동네 산책, 반려묘의 집 안 일상, 보호자 자신의 하루를 함께 다룬다.
  반려동물의 등장·외출·프로필 등록을 기록 조건으로 추가하지 않는다. 예시의 PDF 지면 수치·사진 전용 쪽·쪽 이동은 유지한다.
- 웹 기본/공유 메타데이터·PWA 설명·다운로드 소개는 같은 라이프로그 방향으로 맞췄다.
  대표 예시 사진은 가상 생성물이며 실제 이용자 기록이 아니다. [에셋·프롬프트](../assets/README.md#20-대표-예시-사진-2026-11-17)를 따른다.
- 스토어 소개 준비 문구: “반려동물과 함께한 순간도, 나만의 하루도. 사진과 짧은 이야기로 남기고 한 권의 하루마디로 모아보세요.”
  캡처 구성은 반려견 산책 → 반려묘의 집 안 일상 → 보호자 자신의 하루 → 하루마디 재열람을 기준으로 잡는다.
  이 문구·캡처 방향은 2.0 준비안이며 스토어 등록·기존 출시 노트 변경·업로드를 실행한 것은 아니다.

## 동반 조건·선택 프로필 구현

[상세 동작·권한·자료 입력·배포 순서](./pets-and-dog-outings.md)를 따른다. 동반 조건 테이블·조회·후보 필터와 선택 프로필 등록·수정·삭제·마디 연결 UI/API를 추가했다.
프로필과 연결은 계정 병합·파기·삭제 복원 방지 원장과 함께 처리한다. 카탈로그를 포함한 네 추가형 마이그레이션을 개발 DB에 적용했으며 운영에는 적용하지 않았다.
마디 작성 중 선택 항목에서 바로 프로필을 등록할 수 있고 자동 연결하지 않는다. 등록·수정·삭제 중복 실행,
성공 후 재조회 실패 오안내, 수정 중 삭제된 프로필 상태를 보완했다. 나들이에서는 이번에 함께 가는 반려견을
직접 골라 몸무게만 조건 초안에 불러온다. 기존 수동 입력·프로필 없는 기록·질문 취소 경로는 유지한다.
국문 API를 기본 원본으로 사용한다. 개발 DB에 공식 동반 원문 9,634건을 입력했다.
기존 779곳 외에 기본 정보를 확보한 8,855곳을 신규 등록했고, 좌표 1곳을 복원해 독립 동반 카탈로그의 준비 장소는 9,237곳이다.
공식 등록의 미확인 조건은 방문 전 확인 필요로 표시하며 운영자 검토 자료·수집일·시설 확인일을 구분한다.
일반 후보 승인 상태는 덮어쓰지 않고 별도 카탈로그로 판정한다. 명시적 운영 제외 390곳은 보존했다.
공식 동반 불가 2곳·안내견 전용 1곳은 별도 제외했다. 구역 정보 누락 3곳과 공식 좌표가 비정상인 1곳은 보류다.
공식 등록의 대부분은 개별 쇼핑 매장이므로 외출 목적지와 별도로 집계한다.

## 반려견 중심 독립 추천

현재 품질 수정은 [2.0.0 현재 장소 한정 정책](./dog-outing-v2-policy.md)을 따른다. 아래 v1 설명·실측은 초기 구현 이력이다.

`dog-outing-v1`은 공식 동반 등록·유효 기본 정보·알려진 동반 제한을 먼저 확인하고,
목적·거리·시간 여유·캐시된 날씨·새로움·유형 다양성으로 최대 6곳을 고른다.
구 저부담 점수·상위 180개 선절단·기차/버스 거점은 사용하지 않는다. 이전 엔진은 명시적인 legacy 비교 함수에만 남겼다.
조건 미입력을 목줄·이동장 미준비로 판정하지 않으며, 조건 없이도 동반 장소를 살펴볼 수 있다.
실시간 경로·LLM·날씨 API 응답은 최초 추천에서 기다리지 않는다. 날씨는 유효한 기존 캐시만 가점으로 사용하고 응답 후 보충한다.
추천 캐시 키·감사 로그·관리자 시뮬레이터는 새 버전과 실제 후보 단계·가점 내역을 따른다.

개발 엔진 실측(8kg·목줄 착용·이동장 미사용, 차 없이)에서 서울·부산·제주는 5km와 20km 모두 6곳이었다.
경주 불국동 인근은 5km에서 조건 충족 2곳, 20km에서 33곳 중 6곳이었다. 수를 채우려고 거리·알려진 제한을 풀지 않는다.
8회 단독 엔진 호출은 37~560ms였으며 최초/후속 캐시 상태가 섞인 개발 결과다. 앱·네트워크 전체 지연이나 운영 성능 보장은 아니다.
입력 파일·해시·초기 가점과 운영 선행 작업은 [상세 문서](./pets-and-dog-outings.md)를 따른다.

[실측·발견 사항·수정과 검증 경계](./dog-outing-verification.md)에 정리했다.

상위 표본 29곳의 빈 필드를 보완하고 약관·로그인·저장한 장소·초안·저장 후 복귀에서 선택 책과 장소를 보존한다.

## 남은 검증·확장 범위

1. 대표 이미지·이용 방법·책장 진입점의 전체 정합성과 첫 작성·다른 시점 재열람 UX를 실기기로 검증한다. 하단 내비게이션 위계 재설계는 아직 적용하지 않았다.
2. 수정한 후보 저장·약관/로그인 복귀·작성 후 다시 읽기 연결을 iOS/Android 실제 제공자 화면에서도 교차 확인한다.
3. 공식 원문 신선도·지역별 후보·조건 노출을 운영 전에 확인한다. 기존 일반 장소 엔진은 사용자 추천 경로로 복귀시키지 않는다.
4. 추가형 마이그레이션·실제 DB 경계·백업 복원과 iOS/Android 실기기 UI를 검증한다. 프로필 사진·공동 프로필 관리·기존 마디의 연결 편집 UI는 후속 범위다.

프로필 등록·수정·삭제·작성 중 등록·명시적 동반견 선택은 실제 컴포넌트 핸들러로 검증한다.
격리 PostgreSQL 시험은 본인 프로필 연결·다른 계정 연결 차단·저장 롤백·수정 충돌·프로필 삭제 후 원본 보존·병합 경계를 검증한다.
2026-11-17 대표 예시·프로필·작성·질문·추천 복구/캐시 관련 시험 58개와 TypeScript·변경 파일 ESLint·문서 링크 검사를 통과했다.
입력·확인창·키보드·작은 화면의 최종 배치는 실기기 검증 대상이며 자동 시험 통과를 실기기 확인으로 기록하지 않는다.

속지 선택과 실물 결제·제작·배송은 이번 구현의 선행 조건이 아니다. 기존 마디·책을 새 타깃에 맞춰 자동 변환하거나 삭제하지 않는다.
