# Tuti 위치정보 침해사고 대응 절차

## 1. 적용 사건

다음 중 하나라도 발생하거나 의심되면 이 절차를 시작한다.

- 현재 좌표 또는 사진 촬영 위치가 DB·로그·URL·분석도구에 저장된 경우
- 승인되지 않은 사람이 위치 준수자료나 운영 DB에 접근한 경우
- 관리자·NAS·DB·Cloudflare·스토리지 계정 또는 API 키가 노출된 경우
- 위치 이용·제공·접근 기록의 삭제, 위조, 누락 또는 무결성 오류가 확인된 경우
- 외부 API 사업자가 좌표 처리 관련 사고를 통지한 경우
- 동의·철회 상태와 다르게 위치가 처리된 경우

## 2. 초기 대응

1. 발견자는 즉시 위치정보관리책임자에게 알리고 사건 ID를 만든다.
2. 영향을 받는 API 또는 외부 좌표 전달 모드를 우선 중지한다.
3. 노출된 세션·API 키·관리자 자격증명을 폐기하고 교체한다.
4. 컨테이너·DB·프록시 로그를 보존하되 원본 좌표를 새 문서나 메신저로
   복사하지 않는다.
5. 증거 파일은 읽기 전용 사본과 SHA-256 해시를 만들고 접근자를 제한한다.

## 3. 조사와 영향 평가

- 발생·발견 시각과 지속시간
- 영향을 받은 시스템, 기능과 데이터 항목
- 대상 이용자 범위와 건수
- 원본 좌표 포함 여부와 정밀도
- 외부 유출·제공 여부와 수신자
- 동의·목적·보존기간 위반 여부
- 접근 경로, 원인과 재발 가능성
- 이용자 권리와 안전에 미치는 영향

조사 보고서에는 불필요한 원본 좌표, 토큰, 비밀번호와 API 키를 기록하지 않는다.

## 4. 통지와 신고 판단

위치정보관리책임자는 적용 법령, 신고 당시 제출 내용, 위치정보지원센터 및
관계기관의 최신 지침을 기준으로 이용자 통지와 관계기관 신고 필요성·기한을
즉시 확인한다. 외부 수탁자 사고는 계약상 통지·협조 의무도 함께 확인한다.

법적 판단이 불명확하면 위치정보지원센터 또는 전문 자문기관에 사건의 최소
사실관계를 제공해 확인한다. 확인이 끝날 때까지 관련 로그와 의사결정 기록을
보존한다.

## 5. 복구와 재발 방지

1. 취약점 제거와 비밀정보 교체를 확인한 후 단계적으로 서비스를 복구한다.
2. 누락된 동의·이용·접근 기록을 임의로 소급 생성하지 않고 누락 사실과 원인을
   사고 기록에 남긴다.
3. 코드·인프라·문서·교육의 개선 항목과 담당자·기한을 정한다.
4. 복구 후 수시 자체점검과 감사기록 무결성 검사를 실시한다.
5. 사고 종료는 위치정보관리책임자가 확인한다.
