# Tuti 위치정보 내부관리계획

## 1. 목적과 적용 범위

이 문서는 눈마루가 운영하는 Tuti 위치기반서비스에서 개인위치정보와 위치정보
이용·제공사실 확인자료의 누출, 변조, 훼손과 오·남용을 방지하기 위한 내부
관리·기술 기준을 정한다.

적용 대상은 다음과 같다.

- 브라우저 또는 단말기 운영체제가 제공하는 현재 위치
- 이용자가 선택한 사진에 포함된 EXIF 촬영 위치
- 현재 위치에서 파생된 거리 구간, 이동시간과 경로 결과
- `location_consent_events`의 위치 이용 동의 이력
- `location_usage_logs`의 위치정보 이용·외부 전달 확인자료
- `location_security_audit_events`의 위치정보시스템 접근·권한·점검 기록
- 위치정보를 처리하는 Tuti 서버, PostgreSQL, Docker, NAS, Cloudflare와 외부 API

관광지 자체의 공개 좌표는 개인위치정보가 아니지만, 이용자의 현재 위치와
결합되는 처리 구간은 이 계획의 적용 대상으로 본다.

## 2. 책임자와 취급자

| 구분 | 담당자 | 역할 |
| --- | --- | --- |
| 위치정보관리책임자 | 정연한 대표 | 보호 업무 총괄, 권한 승인, 점검·사고 대응 최종 결정 |
| 위치정보취급자 | 정연한 대표 | 서비스 운영에 필요한 최소한의 처리와 점검 수행 |

새로운 취급자를 지정할 때에는 업무 범위, 접근 시스템, 권한 수준, 부여일과
승인 사유를 먼저 기록한다. 업무 변경·퇴직·계약 종료 시 당일에 권한을
변경하거나 말소하고 변경 이력을 5년간 보관한다.

## 3. 단계별 최소 접근권한

| 처리 단계 | 허용 주체 | 허용 범위 | 금지 사항 |
| --- | --- | --- | --- |
| 취득 | 이용자 클라이언트, Tuti API | 명시적 동의 후 요청에 필요한 좌표 취득 | 백그라운드·지속 추적, 동의 전 EXIF GPS 판독 |
| 이용 | Tuti 애플리케이션 서버 | 추천, 이동시간, 출발계획, 사진 주변 장소 검색 | 원본 좌표의 계정·추천·저널 영구 저장 |
| 외부 처리 | 승인된 Kakao 계열 API | 고지·계약 관계가 확정된 범위의 경로 계산 | 계정 ID·이메일·세션 토큰 동시 전달 |
| 열람 | 위치정보관리책임자 | 이용자 요청 대응, 장애·준수 점검에 필요한 최소 자료 | 원본 좌표 조회, 목적 없는 검색·내보내기 |
| 파기 | 승인된 자동 작업, 위치정보관리책임자 | 보존기간 만료 자료 삭제와 결과 확인 | 보존기간 임의 연장, 확인 없는 수동 삭제 |

관리자 UI 표시 여부와 관계없이 서버가 매 요청의 인증·권한을 다시 확인한다.
운영 DB는 외부 포트를 공개하지 않으며 직접 접속은 장애 대응 또는 승인된
점검에 한정한다.

## 4. 권한 부여·변경·말소

1. 권한은 위치정보관리책임자가 업무상 필요성을 확인한 후 부여한다.
2. 애플리케이션 관리자, NAS, Docker 운영 명령, PostgreSQL, Cloudflare,
   오브젝트 스토리지와 비밀정보 접근 권한을 각각 별도로 관리한다.
3. 공용 관리자 계정을 만들지 않고 개인별 식별 가능한 계정을 사용한다.
4. 권한 변경은 `tuti-location-access-change` 명령 또는 이에 상응하는
   변경 이력으로 기록한다.
5. 기록에는 대상 식별값, 시스템, 이전·변경 권한, 행위, 사유와 시각을
   포함하며 원본 자격증명은 포함하지 않는다.
6. 권한 변경 기록은 최소 5년간 보존한다.
7. 반기마다 현재 권한과 변경 이력을 대조하고 불필요한 권한을 말소한다.

Tuti 관리자 역할 변경은 애플리케이션이 자동 기록한다. NAS, Docker,
PostgreSQL, Cloudflare와 오브젝트 스토리지처럼 애플리케이션 밖에서 이루어지는
권한 변경은 해당 시스템의 자체 로그를 보존하는 것과 함께
`tuti-location-access-change`로 별도 기록한다. 이 수동 기록은 실제 시스템의
권한 설정을 대신하지 않는다.

## 5. 위치정보 처리 절차

### 5.1 현재 위치

1. Tuti 위치기반서비스 이용약관과 만 14세 이상 여부 확인
2. 서버 동의 원장에 상태와 약관 버전 기록
3. 브라우저·운영체제 위치 권한 요청
4. 위치 API가 서버의 최신 동의를 재검증
5. 처리 전에 원본 좌표 없는 이용 확인자료 기록
6. 목적 달성 후 런타임 좌표 제거

### 5.2 사진 촬영 위치

1. 사진을 선택한 이용자에게 촬영 위치 이용 목적과 비저장 방침 고지
2. 이용자가 `촬영 위치 사용하기`를 명시적으로 선택한 경우에만 GPS 판독
3. 서버 동의를 재검증하고 취득경로를 `photo_exif`로 구분하여 기록
4. 장소 검색 후 좌표 제거
5. 업로드 이미지를 재인코딩하여 EXIF 메타데이터 제거

### 5.3 외부 API

외부 좌표 처리 관계가 확인되지 않은 경우 `LOCATION_EXTERNAL_COORDINATE_MODE`
값을 `pending`으로 유지해 전달을 차단한다. 처리위탁으로 확인된 경우 계약·약관,
목적, 보유기간, 재위탁과 파기 조건을 문서화한 후 `processor`를 사용한다.
제3자 제공에 해당하면 별도 동의와 제공사실 통보를 구현하기 전까지 활성화하지
않는다.

## 6. 접근기록과 보존

| 자료 | 최소 보존기간 | 보호 방식 |
| --- | --- | --- |
| 위치 이용·제공사실 확인자료 | 6개월 | 원본 좌표 제외, DB 접근 통제, 만료 자동 파기 |
| 위치정보시스템 접근사실 | 1년 | 자동 기록, HMAC 무결성 서명, 만료 자동 파기 |
| 권한 부여·변경·말소 기록 | 5년 | 자동·수동 변경 기록, HMAC 무결성 서명 |
| 자체점검 결과 | 5년 | 점검 실행 결과와 책임자 확인본 보관 |
| 사고 대응 기록 | 5년 또는 관련 절차 종료 시까지 중 긴 기간 | 사건별 접근 제한, 변경 이력 보존 |

감사 기록에는 원본 위도·경도, 인증 토큰, API 키와 비밀번호를 넣지 않는다.
`LOCATION_AUDIT_HMAC_SECRET`은 애플리케이션과 분리된 운영 환경변수로 관리하며
Git, Docker 이미지와 점검 보고서에 기록하지 않는다.
이 값을 변경하면 기존 서명을 검증할 수 없으므로 임의로 교체하지 않는다. 사고로
인한 교체가 필요하면 변경 전 감사자료와 키의 보관·폐기 결정을 사고기록에 남기고,
새 서명 버전으로 전환하는 코드와 복구 절차를 먼저 마련한다.

## 7. 기술적 보호조치

- 외부 통신은 HTTPS를 사용하고 인증서 오류를 우회하지 않는다.
- 운영 애플리케이션은 비루트 사용자로 실행한다.
- 운영 DB는 Docker 내부망에서만 접근하고 외부 호스트 포트를 열지 않는다.
- 세션·인증코드·감사자료 무결성 값은 단방향 해시 또는 HMAC으로 처리한다.
- 비밀정보는 `.env` 등 배포 환경에서만 주입하고 저장소와 이미지에서 제외한다.
- 관리자 API는 인증과 DB 역할을 모두 확인하며 실패 접근도 감사 대상으로 본다.
- 위치정보시스템 접근기록의 HMAC 서명을 정기적으로 검증한다.
- 운영체제, Docker 이미지와 패키지의 보안 업데이트를 월 1회 이상 확인한다.
- NAS 방화벽과 리버스 프록시는 서비스에 필요한 포트만 허용한다.
- 악성코드 방지 및 NAS 보안 업데이트 상태를 정기점검표로 확인한다.

## 8. 백업과 복구

1. 위치 준수자료를 포함한 운영 DB 백업은 암호화된 저장소에 보관한다.
2. 백업 접근자는 위치정보관리책임자로 제한한다.
3. 백업 파일명·출력에 원본 좌표, 사용자 이메일 또는 토큰을 포함하지 않는다.
4. 분기마다 별도 복구 환경에서 복원 가능성을 시험한다.
5. 원본 자료의 보존기간이 만료되면 해당 자료가 포함된 백업도 백업 순환주기에
   따라 파기하며, 법정 보존기간보다 짧게 제거하지 않는다.
6. 백업·복원·파기 행위는 위치정보시스템 접근기록에 남긴다.

## 9. 자체점검과 교육

- 매년 8월 15일까지 전체 자체점검을 실시한다.
- 접근권한과 보존·파기 상태는 반기마다 추가 점검한다.
- 중대한 코드·인프라·수탁자 변경 후에는 수시점검을 실시한다.
- 점검은 `location-security-self-inspection.md`를 사용하고 자동 점검 결과와
  책임자 서명본을 함께 보관한다.
- 위치정보취급자는 연 1회 이상 약관, 최소처리, 로그 금지정보, 사고 대응과
  권리행사 절차를 교육받고 `location-handler-training-record.md`에
  일시·내용·참석자를 기록한다.

## 10. 사고 대응

위치정보 유출·오사용·무단 접근·로그 위변조가 의심되면
`location-incident-response.md`에 따라 처리한다. 조사 과정에서도 원본 좌표를
새로운 로그나 메신저에 복사하지 않는다.

## 11. 문서 관리

- 시행일: 2026년 8월 15일
- 문서 소유자: 위치정보관리책임자 정연한

- 공개 여부: 내부 운영 문서. 이용자에게는 위치약관과 개인정보 처리방침을 공개
- 증빙 보관 위치: `.compliance-evidence/location-security/`
