# 마디 작성과 보관

기준: 2026-10-29 / 1.5.0 코드. 개별 사진·글을 **마디**라고 부른다.
하루마디·PDF는 [하루마디 문서](./harumadi.md), 공개는 [공유 문서](./journal-sharing.md)를 따른다.

## 화면과 입력

- 목록 `/madi`, 새 작성 `/madi/new`, 상세 `/madi/detail`, 수정 `/madi/edit`.
- 제목은 선택 입력이다. 사진·본문·날짜·장소는 실제 작성 흐름에 맞게 제공하며
  사진이나 장소가 없는 마디도 남길 수 있다.
- 마디의 혼잡도·테마·난이도 입력과 저장 열은 제거했다. 장소 추천 데이터의 분류는 그대로 둔다.
- 현재 UI는 민감정보를 받지 않으며 작은 주의 문구로 안내한다. 준비 중인 민감정보 설정을
  노출하지 않는다. 서버의 기존 보호·철회 API와 사용자에게 제공하는 입력 기능은 구분한다.
- 메인·작은 여행·책 안의 작성은 공통 흐름을 사용한다. 첫 마디 전용 간단 작성은
  전체 마디가 하나도 없는 경우에만 사용하며 안내 문구를 위해 서버 조회를 기다리지 않는다.

## 저장 후 연결

| 시작 위치·상태 | 저장 후 |
| --- | --- |
| 첫 마디이며 기존 하루마디 없음 | 기본 하루마디 생성과 연결을 같은 트랜잭션에서 수행 |
| 특정 하루마디 안에서 작성 | 해당 하루마디에 바로 담고 읽던 책으로 복귀 |
| 책 밖에서 두 번째 이후 작성 | 하루마디 선택 또는 담지 않기 |
| 기존 마디 수정 | 원래 상세 화면으로 복귀 |

실패한 저장을 성공 화면으로 넘기거나 다른 계정의 책에 연결하지 않는다.
첫 마디 자동 책 생성은 계정 잠금으로 중복을 방지한다. 기존 책이 있으면 자동 책을 추가하지 않는다.

## 기기 초안

`src/lib/madiDraft.ts`는 작성 중 이탈·재실행을 위한 기기 초안을 보관한다.
사용자별 최대 5개·7일·3MiB 제한을 적용하며 서버 자료의 원본이나 기기 간 동기화가 아니다.
사진을 포함한 로컬 초안의 용량·유효기간이 끝나거나 저장소를 지우면 사라질 수 있다.

- 저장 성공 시 해당 초안을 지운다. 작성 취소·페이지 이탈은 명시적 선택과 경고를 따른다.
- 로그아웃·계정 삭제 시 해당 계정의 초안을 정리한다. 다른 계정으로 넘기지 않는다.
- PDF 제작 초안과 키·수명·정책이 다르므로 혼동하지 않는다.

## API와 삭제

내부 모델·API는 기존 `JournalEntry` 계열과 `/api/journal-entries`를 사용한다.
UI 용어 변경만을 위해 적용된 마이그레이션·감사 이벤트·동의 원문의 이름을 고치지 않는다.
서버에서 소유권·일반약관·위치 처리 조건·민감정보 보호 조건을 확인한다.

마디 삭제는 사진·연결·공개 상태와 원장을 기존 삭제 절차로 정리한다. 하루마디의 틀과
이미 저장한 일반 PDF 사본은 별개이며 민감정보 철회의 연관 PDF 삭제는 별도 보호 절차다.
완료 여부는 API·파일·원장 결과를 확인하며 로컬 캐시 삭제만으로 서버 파기 완료를 표시하지 않는다.
