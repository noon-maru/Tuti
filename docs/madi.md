# 마디 작성과 보관

기준: 2026-11-06 코드. 개별 사진·글을 **마디**라고 부른다.
하루마디·PDF는 [하루마디 문서](./harumadi.md), 공개는 [공유 문서](./journal-sharing.md)를 따른다.

## 화면과 입력

- 목록 `/madi`, 새 작성 `/madi/new`, 상세 `/madi/detail`, 수정 `/madi/edit`.
- 제목은 선택 입력이다. 사진·본문·날짜·장소는 실제 작성 흐름에 맞게 제공하며
  사진이나 장소가 없는 마디도 남길 수 있다.
- 마디의 혼잡도·테마·난이도 입력과 저장 열은 제거했다. 장소 추천 데이터의 분류는 그대로 둔다.
- 현재 UI는 민감정보를 받지 않으며 작은 주의 문구로 안내한다. 준비 중인 민감정보 설정을
  노출하지 않는다. 서버의 기존 보호·철회 API와 사용자에게 제공하는 입력 기능은 구분한다.
- 메인·작은 여행·책 안의 작성은 공통 흐름을 사용한다. 첫 마디 전용 간단 작성은
  전체 마디가 하나도 없는 경우에만 사용하며 안내 문구를 위해 서버 조회를 기다리지 않는다.
- 특정 하루마디에서 작성하면 실제 책 이름과 개인·공유 범위를 표시한다. 책 조회 실패 시
  입력을 유지한 채 재시도하며, 저장 대상을 확인하기 전에는 저장하지 않는다.
- 작성·수정 모두 사진 바꾸기·빼기를 제공한다. 사진만 빼도 제목·이야기·날짜·장소는 보존한다.
- 장소는 직접 입력·검색·빼기를 함께 제공한다. 직접 고치거나 비우면 기존 장소 ID를 해제한다.
- 장소 제안은 입력창 위로 겹쳐 펼치며 폼의 높이·스크롤 위치를 바꾸지 않는다. 최근 개인 장소가
  입력창에 가장 가까운 목록 하단에 놓이고, 일반 장소는 그 위에 표시된다. 새 결과도 하단부터 보여준다.
  폼 스크롤 영역 밖 레이어에 표시하되 PC 앱 목업과 키보드를 제외한 가용 공간 안에서 높이를 제한한다.
  빈 입력창에서는 최근 장소만 보여주며, 제안을 고르지 않아도 직접 입력한 이름으로 저장할 수 있다.
  작성·수정이 같은 입력창을 사용한다. 개인 이력은 본인 소유의 일반 마디에서만 조회하고
  민감정보·철회 기록은 제외한다. 다른 참여자의 이력은 섞지 않는다.
  `GET /api/places/suggestions`는 인증된 계정으로 조회하고 캐시하지 않는다. 일반 장소는 기존
  승인 장소 DB에서 찾으며 외부 검색 API나 사용자 좌표를 사용하지 않는다. DB 변경은 필요 없다.
- 제목 80자·이야기 4,000자·장소 120자 제한을 클라이언트와 서버에서 공유한다. 날짜와
  필드별 문제는 입력 옆에 안내하며, 처음부터 빈 필드를 빨간 오류로 표시하지 않는다.
  기존 제목·장소만 있는 마디의 수정 허용 조건과 민감정보 동의 보호는 유지한다.

## 저장 후 연결

| 시작 위치·상태 | 저장 후 |
| --- | --- |
| 첫 마디이며 기존 하루마디 없음 | 기본 하루마디 생성과 연결을 같은 트랜잭션에서 수행 |
| 첫 마디이며 기존 빈 하루마디 있음 | 마디 저장 후 담을 하루마디 선택 또는 담지 않기 |
| 특정 하루마디 안에서 작성 | 해당 하루마디에 바로 담고 읽던 책으로 복귀 |
| 책 밖에서 두 번째 이후 작성 | 하루마디 선택 또는 담지 않기 |
| 기존 마디 수정 | 원래 상세 화면으로 복귀 |

실패한 저장을 성공 화면으로 넘기거나 다른 계정의 책에 연결하지 않는다.
첫 마디 자동 책 생성은 계정 잠금으로 중복을 방지한다. 기존 책이 있으면 자동 책을 추가하지 않는다.
작성 응답의 `savedHarumadi`는 트랜잭션에서 확인한 실제 연결 결과다. 이 값이 없으면 첫 마디도
담기 선택으로 이어진다. 중복 저장 요청의 재응답은 현재 연결·접근 권한을 다시 확인하며,
기본 책에 자동 연결된 경우에는 선택을 반복하지 않는다. 수정의 보호 설정 조회 실패도
입력·초안을 지우지 않고 같은 화면에서 다시 확인할 수 있다.

## 기기 초안

`src/lib/madiDraft.ts`는 작성 중 이탈·재실행을 위한 기기 초안을 보관한다.
사용자별 최대 5개·7일·3MiB 제한을 적용하며 서버 자료의 원본이나 기기 간 동기화가 아니다.
사진을 포함한 로컬 초안의 용량·유효기간이 끝나거나 저장소를 지우면 사라질 수 있다.

- 저장 성공 시 해당 초안을 지운다. 작성 취소·페이지 이탈은 명시적 선택과 경고를 따른다.
- 로그아웃·계정 삭제 시 해당 계정의 초안을 정리한다. 다른 계정으로 넘기지 않는다.
- PDF 제작 초안과 키·수명·정책이 다르므로 혼동하지 않는다.

## API와 삭제

목록 캐시는 `['journal-entries', userId]`로 계정별 격리한다. 계정 전환 시 이전 계정의
요청과 캐시만 취소·제거한다. 작성·수정·삭제·공개 변경은 요청 시작 당시 세션을 변수에
함께 보관하고, API 응답 본문 해독과 캐시 반영 시 계정·토큰을 다시 확인한다.
화면 재렌더로 mutation 콜백이 교체돼도 새 계정의 세션이나 캐시로 결과를 넘기지 않는다.
이 요청은 401 후 새 익명 계정으로 자동 재전송하지 않는다.

내부 모델·API는 기존 `JournalEntry` 계열과 `/api/journal-entries`를 사용한다.
UI 용어 변경만을 위해 적용된 마이그레이션·감사 이벤트·동의 원문의 이름을 고치지 않는다.
서버에서 소유권·일반약관·위치 처리 조건·민감정보 보호 조건을 확인한다.

마디 삭제는 사진·연결·공개 상태와 원장을 기존 삭제 절차로 정리한다. 하루마디의 틀과
이미 저장한 일반 PDF 사본은 별개이며 민감정보 철회의 연관 PDF 삭제는 별도 보호 절차다.
완료 여부는 API·파일·원장 결과를 확인하며 로컬 캐시 삭제만으로 서버 파기 완료를 표시하지 않는다.

일반·관리자 삭제는 마디 행 잠금 뒤 최신 사진 키를 읽고 DB 삭제와 외부 정리 예약을
같이 커밋한다. 도중의 사진 교체나 소유권 변경으로 정리 대상을 잃지 않게 한다.
공개 변경은 사용자·마디 순서로 잠근 뒤 관리자 숨김과 계정 공개 제한을 다시 확인한다.
