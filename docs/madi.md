# 마디 작성과 보관

기준: 2026-11-11 코드. 개별 사진·글을 **마디**라고 부른다.
하루마디·PDF는 [하루마디 문서](./harumadi.md), 공개는 [공유 문서](./journal-sharing.md)를 따른다.

## 화면과 입력

- 목록 `/madi`, 새 작성 `/madi/new`, 상세 `/madi/detail`, 수정 `/madi/edit`.
- 전체 마디는 카드·목록 보기를 선택하고 `아직 담지 않은 마디`로 좁힐 수 있다. 보기와 필터는
  URL에 유지한다. 미담기 여부는 접근 가능한 하루마디 전체의 연결 ID를 확인한 뒤 판정하며,
  목록 확인 실패·진행 중에는 빈 책장으로 간주하지 않는다. 카드 메뉴와 목록의 `담기`는
  원본을 새로 만들지 않고 기존 마디를 선택한 하루마디에 연결한다.
- 하루마디를 읽다가 본인 마디의 `마디 메뉴 → 이 마디 수정`으로 이동할 수 있다.
  읽던 마디·분할 쪽을 먼저 보관하고 수정·취소 후 같은 책으로 돌아간다. 함께 채우기에서도
  다른 참여자의 마디에는 수정 메뉴를 제공하지 않는다.
- 장소 상세의 `이 장소에서 마디 남기기`를 직접 누른 경우에만 장소명과 ID를 채운다.
  공유 장소 열람은 동의 없이 유지하며 실제 작성에는 기존 동의 절차가 적용된다.
  로그인 후에도 선택한 장소를 복원한다. 일반 작성은 보고 있던 장소를 방문지로 추정하지 않는다.
- 제목은 선택 입력이다. 사진·본문·날짜·장소는 실제 작성 흐름에 맞게 제공하며
  사진이나 장소가 없는 마디도 남길 수 있다.
- 마디의 혼잡도·테마·난이도 입력과 저장 열은 제거했다. 장소 추천 데이터의 분류는 그대로 둔다.
- 현재 UI는 민감정보를 받지 않으며 작은 주의 문구로 안내한다. 준비 중인 민감정보 설정을
  노출하지 않는다. 서버의 기존 보호·철회 API와 사용자에게 제공하는 입력 기능은 구분한다.
- 메인·작은 여행·책 안의 작성은 공통 흐름을 사용한다. 첫 마디 전용 간단 작성은
  전체 마디가 하나도 없는 경우에만 사용하며 안내 문구를 위해 서버 조회를 기다리지 않는다.
- 특정 하루마디에서 작성하면 실제 책 이름과 개인·공유 범위를 표시한다. 책 조회 실패 시
  입력을 유지한 채 재시도하며, 저장 대상을 확인하기 전에는 저장하지 않는다.
  상단 제목은 `우리의 작은 하루에 남길 마디`처럼 실제 책 이름을 사용하고 16px로 표시한다.
  긴 이름은 생략하지 않고 줄바꿈하며 바로 아래에는 책 이름을 반복하지 않고 공유 범위만 안내한다.
- 책장 선택 책의 작성 동작은 `이 하루마디에 남기기`, 공통 하단 작성은 `새 마디 남기기`로 구분한다.
  하단 작성에 선택 책을 암묵적으로 지정하지 않으며 일반 작성에는 저장 후 담을 책을 고른다고 안내한다.
  첫 마디 안내와 자동 책 생성, 지정 책의 직접 저장, 스와이프·탭 동작은 유지한다.
- 작성·수정 모두 사진 바꾸기·빼기를 제공한다. 사진만 빼도 제목·이야기·날짜·장소는 보존한다.
- 사진 맞추기에서 가로 4:3·정방형 1:1·세로 3:4·원본 비율을 선택한다. 비율 변경 시 확대와
  이동을 초기화하고 새 작업 영역 측정이 끝나기 전에는 저장하지 않는다. 출력은 긴 변 1200px
  이내로 제한하고 작은 원본을 확대하지 않는다. 초안은 잘라낸 이미지 자체를 보존한다.
- 작성·수정·목록·검색·책장·골라 담기·정렬의 사진 미리보기는 4:3 프레임을 사용한다.
  실제 마디 상세와 공개 상세는 서버가 확인한 `imageWidth`·`imageHeight` 비율을 사용하고 세로로 스크롤한다.
  잘라낸 사진 자체를 4:3으로 다시 저장하는 것은 아니다. 크기가 없는 기존 사진은 4:3으로 표시한다.
- 사진 저장·교체 시 서버의 실제 WebP 출력 크기를 사진 키와 같은 DB 쓰기로 보존하고 제거 시 둘 다 비운다.
  클라이언트가 제출한 크기를 신뢰하지 않는다. 기존 사진은 일괄 재가공하지 않으며 과거에 잘린 부분은 복원하지 못한다.
- 장소는 직접 입력·검색·빼기를 함께 제공한다. 직접 고치거나 비우면 기존 장소 ID를 해제한다.
- 장소 제안은 입력창 위로 겹쳐 펼치며 폼의 높이·스크롤 위치를 바꾸지 않는다. 최근 개인 장소가
  입력창에 가장 가까운 목록 하단에 놓이고, 일반 장소는 그 위에 표시된다. 새 결과도 하단부터 보여준다.
  폼 스크롤 영역 밖 레이어에 표시하되 PC 앱 목업과 키보드를 제외한 가용 공간 안에서 높이를 제한한다.
  빈 입력창에서는 최근 장소만 보여주며, 제안을 고르지 않아도 직접 입력한 이름으로 저장할 수 있다.
  작성·수정이 같은 입력창을 사용한다. 개인 이력은 본인 소유의 일반 마디에서만 조회하고
  민감정보·철회 기록은 제외한다. 다른 참여자의 이력은 섞지 않는다.
  `GET /api/places/suggestions`는 인증된 계정으로 조회하고 캐시하지 않는다. 일반 장소는 기존
  승인 장소 DB에서 찾으며 외부 검색 API나 사용자 좌표를 사용하지 않는다. DB 변경은 필요 없다.
- 제목 80자·이야기 4,000자·장소 120자 제한을 클라이언트와 서버에서 공유한다. 날짜와
  필드별 문제는 입력 옆에 안내하며, 처음부터 빈 필드를 빨간 오류로 표시하지 않는다.
  기존 제목·장소만 있는 마디의 수정 허용 조건과 민감정보 동의 보호는 유지한다.
- 작성은 사진/글 선택과 입력의 두 단계다. 입력 화면에서 바로 저장할 수 있고 미리보기는 선택이다.
  두 저장 버튼은 같은 검증·중복 방지·저장 실패 보존 경로를 사용한다. 지정 책의 이름·공유 범위는
  입력 화면의 저장 버튼 근처에도 표시한다. 미리보기에서 뒤로가면 작성 내용 그대로 돌아온다.

## 저장 후 연결

담을 하루마디가 없으면 `새 하루마디 만들어 담기`로 바로 생성한다. 저장한 마디 ID를
생성 화면에서 유지하고 책을 만든 뒤 기존 담기·권한 검증 경로로 연결한다. 책 생성과 담기는
서로 다른 요청이며 담기에 실패해도 저장한 원본은 지우지 않는다. 빈 전체 마디 목록과
책의 골라 담기 화면은 첫 마디 작성으로 직접 연결한다.

| 시작 위치·상태 | 저장 후 |
| --- | --- |
| 첫 마디이며 기존 하루마디 없음 | 기본 하루마디 생성과 연결을 같은 트랜잭션에서 수행 |
| 첫 마디이며 기존 빈 하루마디 있음 | 마디 저장 후 담을 하루마디 선택 또는 담지 않기 |
| 특정 하루마디 안에서 작성 | 해당 하루마디에 바로 담고 읽던 책으로 복귀 |
| 책 밖에서 두 번째 이후 작성 | 하루마디 선택 또는 담지 않기 |
| 기존 마디 수정 | 원래 상세 화면으로 복귀 |

실패한 저장을 성공 화면으로 넘기거나 다른 계정의 책에 연결하지 않는다.

작성 시작 화면은 사진 선택 외에 `사진 없이 글로 시작하기`를 독립된 버튼으로 제공한다.
글 시작은 사진 권한을 요청하지 않고 입력 단계로 이동하며, 이후 사진을 추가할 수 있다.

- 담기 화면은 `이 하루마디에 담기`와 `지금은 담지 않기`로 선택을 나눈다. 원본 저장 완료 표시는
  유지하며, 연결 성공 또는 담지 않기 선택 후 완료 화면에서 마치거나 다음 마디를 작성할 수 있다.
  연결한 책이 있으면 다음 작성도 그 책으로 이동한다. 최신 책·접근권·공유 범위 확인과 책별 초안 격리를 다시 거친다. 연속 작성 모드에서는
  저장 후 같은 책에 다음 마디를 쓰거나 책으로 돌아갈 수 있다. 평소 책 안 작성의 자동 복귀는 유지한다.
- 첫 마디 자동 책 생성 후에도 실제 연결된 책으로 다음 작성을 시작할 수 있다. 담지 않고 다음 작성은
  계속 책 밖 작성이다. 새 마디를 시작할 때 저장 요청 ID도 초기화해 같은 내용을 별개 마디로 남길 수 있다.
- 담기에는 본인이 실제 마디를 담은 최근 하루마디 최대 3권을 먼저 제안한다. 기존에 보존 중인
  `madi_added`·`madi_created` 성공 사건만 사용하고 보관기간·계측 항목을 늘리지 않는다.
  다른 사람의 수정·열람은 최근 순서에 반영하지 않으며 삭제된 책·종료된 참여·접근 불가 책은 제외한다.
  전체 목록 캐시에 여전히 있는 최근 책만 제안하며 일반 목록과 중복하지 않는다. 자동 선택하지 않는다.
  `GET /api/harumadis/recent`는 인증·약관·접근권과 private/no-store를 적용한다. 개인 순서는
  기기에 영속 저장하지 않으며 선택 화면의 계정별 캐시는 이탈 시 정리한다. 최근 조회가 실패하거나
  1.2초를 넘기면 일반 목록으로 진행한다. DB·환경변수 변경은 필요 없다.
- 담기 직전에 책을 다시 조회하고 선택 당시와 공유 범위가 다르면 새 연결 없이 재선택을 요청한다.
  이미 담긴 마디의 재시도는 중복 연결하지 않는다. 최근 제안 순서는 연결 권한을 대신하지 않는다.

첫 마디 자동 책 생성은 계정 잠금으로 중복을 방지한다. 기존 책이 있으면 자동 책을 추가하지 않는다.
작성 응답의 `savedHarumadi`는 트랜잭션에서 확인한 실제 연결 결과다. 이 값이 없으면 첫 마디도
담기 선택으로 이어진다. 중복 저장 요청의 재응답은 현재 연결·접근 권한을 다시 확인하며,
기본 책에 자동 연결된 경우에는 선택을 반복하지 않는다. 수정의 보호 설정 조회 실패도
입력·초안을 지우지 않고 같은 화면에서 다시 확인할 수 있다.

## 기기 초안

`src/lib/madiDraft.ts`는 작성 중 이탈·재실행을 위한 기기 초안을 보관한다.
사용자별 최대 5개·7일·3MiB 제한을 적용하며 서버 자료의 원본이나 기기 간 동기화가 아니다.
사진을 포함한 로컬 초안의 용량·유효기간이 끝나거나 저장소를 지우면 사라질 수 있다.

- 저장 성공 시 해당 초안을 지운다. 작성 취소·페이지 이탈은 명시적 선택과 경고를 따른다.
- 로그아웃·계정 삭제 시 해당 계정의 초안을 정리한다. 다른 계정으로 넘기지 않는다.
- 신규 작성은 책 밖 초안과 하루마디별 초안을 분리하며, 같은 책도 개인·함께 채우기 상태별로 분리한다.
  다른 책·다른 공유 범위의 초안을 자동으로 가져오거나 현재 목적지에 덮어쓰지 않는다.
  계정별 책장·열람·작성 캐시에서 이름을 즉시 표시하고 접근권·공유 범위는 백그라운드로 확인한다.
  확인 전에도 작성할 수 있지만 저장은 제한하며, 실패 시 입력을 유지하고 다시 확인하기를 제공한다.
  초안 범위는 작성 진입 시 고정한다. 캐시가 없으면 별도의 unknown 범위를 사용하고, 로컬 초안
  복원 중에만 입력을 잠시 제한한다. 확인·재시도는 화면을 재생성하지 않는다. 계정·대상 책 전환만
  새 화면을 만든다. 개인·공유 범위가 바뀌면 초안을 유지한 채 책에서 다시 열도록 안내하며 자동 공유하지 않는다.
  저장 요청에는 확인된 공유 범위를 포함하고 서버도 책 잠금 아래에서 재검증해 변경 시 409로 거절한다.
  기존 공통 초안은 삭제하지 않고 책 밖 작성에서만 복원하며, 저장 후 담을 책은 명시적으로 고른다.
  초안에는 책 제목·참여자 이름을 추가로 보관하지 않고 기존 개수·수명·용량 제한을 유지한다.
- PDF 제작 초안과 키·수명·정책이 다르므로 혼동하지 않는다.

## API와 삭제

비율 지원은 `20261110020000_add_madi_image_dimensions`의 nullable 크기 열 추가가 필요하다.
서버 배포 전에 대상 DB에 마이그레이션을 적용해야 하며, 개발·운영 적용과 앱 배포는 별도 작업이다.
이미지 크기는 응답용 메타데이터이며 요청의 임의 크기 값으로 저장하지 않는다.

전체 마디에서 검색할 때 결과는 날짜·장소·제목·본문 일부·작은 썸네일이 있는 목록으로 보인다.
각 행을 눌러 상세로 바로 이동하며 검색을 지우면 기존 카드 보기를 유지한다.
검색 결과 없음은 검색 지우기로 복구하고 원본이 삭제됐다고 안내하지 않는다.

원본 삭제 확인은 모든 책(함께 채우기 포함)에서 해당 마디가 빠지는 영향과 PDF 사본의 독립성을
명시한다. 책 삭제·함께 채우기 종료·나가기·내보내기·책에서 빼기는 각각 다른 안내를 사용한다.
참여 종료 시 해당 책의 연결과 댓글 본문을 정리하지만 각자의 원본과 저장한 PDF는 보존한다.
민감정보 철회는 기존의 더 넓은 파기 범위를 별도로 안내한다.

목록 캐시는 `['journal-entries', userId]`로 계정별 격리한다. 계정 전환 시 이전 계정의
요청과 캐시만 취소·제거한다. 작성·수정·삭제·공개 변경은 요청 시작 당시 세션을 변수에
함께 보관하고, API 응답 본문 해독과 캐시 반영 시 계정·토큰을 다시 확인한다.
화면 재렌더로 mutation 콜백이 교체돼도 새 계정의 세션이나 캐시로 결과를 넘기지 않는다.
이 요청은 401 후 새 익명 계정으로 자동 재전송하지 않는다.

내부 모델·API는 기존 `JournalEntry` 계열과 `/api/journal-entries`를 사용한다.
UI 용어 변경만을 위해 적용된 마이그레이션·감사 이벤트·동의 원문의 이름을 고치지 않는다.
서버에서 소유권·일반약관·위치 처리 조건·민감정보 보호 조건을 확인한다.

마디 삭제는 사진·연결·공개 상태와 원장을 기존 삭제 절차로 정리한다. 하루마디의 틀과
이미 저장한 일반 PDF 사본은 별개이며 민감정보 철회의 연관 PDF 삭제는 별도 보호 절차다.
완료 여부는 API·파일·원장 결과를 확인하며 로컬 캐시 삭제만으로 서버 파기 완료를 표시하지 않는다.

일반·관리자 삭제는 마디 행 잠금 뒤 최신 사진 키를 읽고 DB 삭제와 외부 정리 예약을
같이 커밋한다. 도중의 사진 교체나 소유권 변경으로 정리 대상을 잃지 않게 한다.
공개 변경은 사용자·마디 순서로 잠근 뒤 관리자 숨김과 계정 공개 제한을 다시 확인한다.
