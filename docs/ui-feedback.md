# 사용자 확인과 결과 안내

2026-10-30 코드 기준. 운영·스토어 반영과 브라우저·실기기 검증은 별도다.

## 표시 원칙

- 삭제·철회·차단·계정 변경·작성 중 이탈: 앱 확인 모달을 사용한다. 기존 경고 범위와 취소 분기를 유지한다.
- 복사·공유 결과와 간단한 실패: 화면을 막지 않는 토스트를 사용한다. 재시도 동작과 긴 안내가 필요한 경우 기존 화면 내 오류 표시를 유지한다.
- PC의 앱 화면에서는 목업 내부에 표시한다. 관리자·공개 페이지처럼 앱 영역이 없으면 브라우저 화면에 표시한다.
- 탭 닫기·새로고침의 미저장 경고는 브라우저 `beforeunload`로 유지한다. 기기 권한 요청·공유 시트 같은 OS UI는 이 원칙의 교체 대상이 아니다.

## 공통 구현

`src/shared/ui/AppDialogFrame.tsx`는 배경 비활성화, 취소 기본 포커스, 포커스 순환·복원, Esc·안드로이드 뒤로가기를 담당한다. 함께 채우기의 작업 중 확인 모달도 같은 프레임을 사용한다.

`src/shared/ui/FeedbackHost.tsx`를 루트에서 한 번 연결한다. 일반 확인은 `await confirmAction(message, options)`의 참 응답 이후에만 실행한다. 호스트 부재·중복 확인·취소·화면 이탈·계정 전환에서는 거짓으로 끝나며 파괴적 작업을 대기열에 넣지 않는다. 확인 도중 경로·계정이 바뀐 늦은 응답도 허용하지 않는다.

토스트는 `showToast` 또는 `showErrorToast`로 표시한다. 최신 한 건만 유지하고 일반 안내는 6초, 오류는 10초 뒤 닫힌다. 포인터나 포커스를 올리면 닫기 시간을 멈추며 직접 닫을 수 있다. 화면 이동 후에도 결과 안내는 읽을 수 있지만 계정 변경 시에는 지운다.

확인 메시지·응답과 토스트는 메모리에만 두며 저장소·로그·분석으로 수집하지 않는다. UI 확인은 서버의 소유권·권한·동의·삭제 검사를 대신하지 않는다.

## 회귀 검사

`test/system-dialogs.test.ts`는 사용자·관리자 코드에 시스템 `alert`, `confirm`, `prompt`가 다시 추가되지 않도록 검사한다. 모든 `confirmAction` 호출이 `await`되는지 검사해 Promise를 참으로 해석해 취소가 무시되는 실수를 막는다. `test/feedback.test.ts`는 한 번의 응답·경로/계정 변경·호스트 해제·이전 토스트 타이머의 경계를 검증한다.
