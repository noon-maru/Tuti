# 이전 추천 엔진 성능 관측

대상: 2026-10-01~02, 구 v22/v23 엔진. 현재 정책은 [2.0 추천 정책](../dog-outing-v2-policy.md),
측정 기준은 [추천 성능](../recommendation-performance.md)을 따른다. 이 문서의 숫자는 현재 SLO가 아니다.

## 당시 변경

운영 릴리스 `0867987`에서 `1e57b06`으로 바꾸며 초기 비핵심 페이지 선조회 4개를 제거하고,
카드 이미지 요청 대상을 최대 6장에서 3장으로 줄였다. 출발 준비는 교통수단 하나의 경로부터
조회하고 상세·주변 장소는 뒤로 분리했다. 중복 거리 계산과 운영 상세 후속 조회도 줄였다.
당시 도입한 180곳 후보 상한과 v23 점수는 2.0의 후보·점수 기준으로 사용하지 않는다.

## 2026-10-02 관측

변경 전 서울 영등포구의 초기 추천은 조건별 단일 요청 0.291~1.050초,
위치 없는 종로구 지정은 0.212초였다. 반복 측정과 직접 비교할 표본이 아니다.

변경 후 `1e57b06`, 종로구 지정 조건:

| 경로 | 표본 | 구간 | p50 | p95 |
| --- | ---: | --- | ---: | ---: |
| 공개 도메인 비로그인 | 20 | 서버 추천 | 22.3ms | 27.4ms |
| 공개 도메인 비로그인 | 20 | 외부 전체 왕복 | 313.6ms | 451.2ms |
| NAS 내부 인증 | 10 | 서버 추천 | 19.4ms | 32.5ms |
| NAS 내부 인증 | 10 | 스냅샷 저장 | 67.0ms | 845.7ms |
| NAS 내부 인증 | 10 | 서버 전체 응답 | 88.2ms | 875.5ms |

단일 변경 전 요청과 변경 후 p50으로 직접 개선율을 계산하지 않는다.
이후 분석 스냅샷을 서버 `after()`로 분리했지만, 위치 이용 확인자료는 응답 전 동기 저장을 유지했다.
당시 인증·비로그인 요청의 차이를 현재 동의·인증 보호를 우회할 근거로 사용하지 않는다.

## 2026-11-13 추가 조회

새로움 가점은 개발 DB의 이력 없는 합성 계정·공개 후보 100개에서 10회 측정했다.
중앙값 9.1ms·최대 46.1ms·가점 생략 0회였다. 빈 이력의 추가 SQL 비용이며
실제 이용자 이력이 많은 운영 추천 전체의 지연을 보장하지 않는다.

완료된 세부 체크리스트와 당시 구현 순서 전문은 Git 이력의 `docs/recommendation-performance.md`에서 복구할 수 있다.
