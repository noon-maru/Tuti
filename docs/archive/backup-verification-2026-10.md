# 10월 백업 검증과 격리 복원 이력

대상: 2026-10-20~21. 현행 실행·자원 한도·복원 보호는 [운영 명령](../operations.md)을 따른다.
아래 사본의 성공은 현재 모든 사본의 무결성이나 운영 복구 재개 시험을 대신하지 않는다.

## 객체 목록 누락

`20261020-224729` 사본에 `objects.manifest.json`이 없었다. pnpm의 `--` 인자 전달로
객체 자료가 마운트 경로 대신 임시 컨테이너 내부에 저장될 수 있음을 재현했다.
백업·복원을 tsx 직접 호출로 고치고 필수 파일 검사를 추가했다. 기존 불완전 사본에 현재 객체를
덧붙여 동일 시점 백업으로 위장하지 않았다. 운영 DB·객체 원본 삭제가 발생했다는 의미는 아니다.

새 `20261020-233213`은 파일 28개·객체 24개(3,011,665바이트)와 덤프 헤더·TOC 무결성 검사를 통과했다.
이 단계는 실제 복원 성공이 아니었으며 이후 격리 복원을 별도로 진행했다.

## 격리 복원에서 발견한 병목

| 당시 관측 | 보완과 한계 |
| --- | --- |
| 연결 중단 | 초기 임시 서버가 아닌 최종 PostgreSQL 서버 준비 확인, 고정 소켓·빈 DB 사용 |
| 시험 공간 부족 | RAM 기반 데이터 영역 2GiB가 가득 찼고 공유메모리는 충분함을 확인. NAS 전용 임시 폴더로 분리 |
| 600초 시간 초과 | 압축 약 314MB와 실제 DB·인덱스 크기를 구분. 세 단계 시간·진행 관측 추가 |
| pre-data 권한 오류 | 읽기 전용 아카이브 접근 검사, 서버는 postgres·복원 클라이언트만 root로 읽기 |

오류 분류만으로 근본 원인을 단정하지 않았고 시험 자원만 정리했다.
용량·시간 한도 상향이나 오류 문구 소멸을 복원 완료로 기록하지 않았다.
