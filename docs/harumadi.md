# 하루마디와 PDF

기준: 2026-11-04 코드. 실제 배포·스토어 공개 여부와 실기기 결과는 별도 확인한다.
개별 기록은 **마디**, 이를 채우는 편집 가능한 책은 **하루마디**, 내보낸 파일은 **PDF 사본**이다.
마디 작성·초안은 [마디 문서](./madi.md), 방향·미구현 상품은 [제품 방향](./product-direction.md)과
[BM 계획](./harumadi-bm-validation-plan.md)에서 관리한다.

## 책장과 생성

홈 `/`는 표지 가판대, 책등 책장, 중앙 한 권을 중심으로 주변 책이 겹쳐지는 한 권씩 보기를 제공한다.
상단 현재 보기 버튼의 팝오버에서 `한 권씩 / 표지 / 책등`을 선택한다. 계정별로 기기에 저장하며 기본은 한 권씩이다. 기존에 선택한 보기는 유지한다. 책등은 화면 너비에 맞춰
선반당 권수를 조정하고 제목을 세로로 보여준다. 사진·본문을 추가 조회하지 않고 목록 메타데이터만 쓴다.
세 보기 모두 같은 목록 순서·페이지네이션·점 세 개 메뉴·펼치기·히스토리를 공유한다.
헤더는 현재 보기 선택·새 하루마디·책장 더보기 메뉴를 한 줄로 제공하고 제목·권수는 반복하지 않는다. 화면의 접근성 이름은 `내 책장`이다. 생성 버튼은 14px·500으로 유지한다.
상단의 가로 점 세 개 `책장 메뉴`에서 `전체 마디 보기`·`저장한 PDF`·`설정`으로 이동한다. 공용 팝오버와 최소 44px 누름 영역을 사용한다. 개별 책의 세로 점 메뉴와 구분하고 하단의 별도 보관함 행은 두지 않는다.
상단 여백은 읽기 화면 헤더와 같이 안전 영역에 40px(높이 620px 이하에서는 24px)를 더하고, 하단 구분선은 공통 내비게이션에만 둔다.
보기 버튼은 현재 이름과 아래쪽 셰브론만 표시한다. 공용 팝오버의 선택 표시·키보드 이동·닫기 동작을 재사용하며 버튼 누름 영역은 최소 44px로 유지한다.
한 권씩 보기는 설명·작성 안내·쪽 이동 및 추가 목록 안내의 실제 높이를 반영해 책 전시 영역을 계산한다.
책 전시는 남는 높이를 채우고 책 자체는 전시 영역의 세로 중앙에 둔다. 하단 설명 높이를 책 중심에 더하지 않는다. 안내·제목·넘기기 행은 기존 하단 배치를 유지한다. 제목은 메뉴 옆 독립 열에 왼쪽 정렬한다. 책 설명과 넘기기 행은 24px 간격을 두며 실제 높이 측정에 포함한다. 짧은 화면은 최소 전시 영역과 터치 크기를 유지하며 스크롤한다.
표지·책등은 목록이 적을 때 남는 높이의 위아래 여백을 나눠 중앙 배치한다. 목록이 길면 자동 여백 없이 위에서부터 스크롤하고 마지막 선반의 불필요한 아래 여백은 남기지 않는다.
한 권씩 보기는 좌우 스와이프·마우스 드래그·방향키·이전/다음 버튼으로 선택하고 중앙의 펼친 속지를 눌러 연다.
책 미리보기 영역을 위로 쓸어 올리면 현재 선택한 하루마디의 `/madi/new?from=library&harumadiId=...`로 이동한다.
아래의 `위로 쓸어 마디 남기기` 버튼으로도 같은 동작을 실행한다. 저장은 기존 책 지정 작성 경로를 그대로 사용한다.
최초 방향이 정해지면 좌우 이동·위로 쓰기를 전환하지 않으며, 미세 이동·취소·도중 선택 변경은 작성을 실행하지 않는다.
책 영역은 단일 터치를 제스처에 사용하고 핀치 확대는 허용한다. 설명·하단 버튼 등 책 바깥 영역의 세로 스크롤은 유지한다.
터치 캡처가 자식에서 책 영역으로 이전될 때 버블링하는 해제 이벤트는 무시하고, 영역 자체의 캡처 소실은 취소한다.
선택한 책의 왼쪽·오른쪽 끝 20%는 이전·다음 책으로 이동하며, 가운데 60%와 키보드 클릭은 읽기를 연다.
선택한 책만 기존 계정별 콘텐츠 조회·권한 검증을 사용하며, 실제 첫 두 쪽을 공통 지면 컴포넌트로 축소해
보여준다. 주변 책은 표지만 유지한다. 빈 책은 첫 마디 안내와 뒷표지를 보여주며 조회 실패 시 가짜 내용을 넣지 않는다.
공동작성 책은 서버 재검증 전 저장된 내용으로 미리보기를 표시하지 않는다.
개인 책은 한 권씩 미리보기에서도 열람 화면과 같은 기기 캐시를 먼저 복원하고 서버 조회를 병렬로 계속한다.
처음 보는 책이나 캐시가 없는 책은 서버 응답을 기다린다. 현재 공유된 책에는 이전 개인 책 캐시도 먼저 노출하지 않는다.
미리보기 내용이 준비되면 표지가 책등 축을 중심으로 돌아가고 왼쪽 속지가 펼쳐지는 900ms 애니메이션을
재생한다. 백그라운드 갱신에는 반복하지 않으며 동작 줄이기 설정에서는 바로 펼친 상태로 표시한다.
펼친 미리보기를 누르면 동일한 두 지면이 화면 안에서 최대 16% 확대되며 620ms 동안 첫 쪽 읽기로
교차 전환한다. 가로·세로 비율을 유지하고 두 쪽을 한 쪽 읽기 폭에 강제로 맞추지 않는다.
표지를 다시 덮거나 회전하지 않으며, 표지·책등 보기에서는 기존 표지 열기를 유지한다.
드래그 위치에 크기·기울기·겹침이 따라가며 손을 놓으면 한 권 단위로 정렬한다. 주변 표지만 제한해
렌더하고, 마지막 권의 다음 동작은 다음 목록을 불러온다. 실패 안내는 공통 책장 재시도 UI를 쓴다.
하단 공통 내비게이션에서 마디 작성과 작은 여행으로 이동한다. 책장만 열어서는 위치·추천을 요청하지 않는다.

- 빈 계정은 `첫 마디 남기기`를 안내한다. 첫 저장 시 하루마디가 없다면 기본 책도 함께 만든다.
- `새 하루마디`로 이름·표지를 먼저 정해 빈 틀을 만들 수 있다. 제작 자체는 PDF를 생성하지 않는다.
- 같은 이름도 허용하며 ID로 구분한다. 중복 이름으로 생성하거나 실제 이름을 변경한 경우에는
  보조 정보가 표시된다는 토스트를 저장 후 안내한다. 이름이 그대로인 표지 수정에는 반복하지 않는다.
  본인·활성 초대 책 전체를 기준으로 동명을 판단해 다음 목록의 책도 포함하며, 다른 사람의 비공개 책은 조회하지 않는다.
  동명이 있는 책만 세 책장 보기와 담기 선택 화면에 한국시간 생성일·시각을 추가한다. 제목에 번호는 강제로 붙이지 않는다.
- 한 권에 담는 마디 수의 고정 상한은 두지 않는다. 원문·사진을 복제하지 않고 참조한다.
  향후 실제 이용량을 확인해 개수 정책을 재검토한다. 요청 크기·PDF 처리량 보호는 별개다.
- 표지는 흰색·연두색과 사진 유무의 조합이다. 사진 표지는 현재 마디 순서의 첫 사진을 사용한다.
- **속지 타입은 없다.** 사진·글 유무로 자동 배치한다. UI·API·DB의 속지 필드는 제거했다.
- 세로 공간이 충분하면 생성 화면에 여백을 두고, 앱 높이 720px 미만이면 표지와 이름을 나란히
  배치한다. 620px 이하·너비 340px 이하를 추가 조정한다. 키보드·확대 글꼴에서는 스크롤을 허용한다.
- 생성·설정의 작은 표지 미리보기는 의도적으로 과장한다. 사진 없는 표지는 중앙 큰 제목,
  사진 표지는 PDF와 같은 210:170 비율에 1.5배 사진, 공통 위치의 하단 Tuti를 사용한다.
  실제 책·PDF 레이아웃을 이 미리보기 크기로 바꾸지 않는다.

## 펼치기·읽기·설정

표지를 누르면 펼침 애니메이션 뒤 책 지면으로 읽는다. 책장 위에서 연 상태는 브라우저
히스토리와 연결하며, 직접 주소는 `/harumadi?harumadiId=…`다. 권별 세로 점 메뉴에서 설정한다.

- 좌우 버튼·지면 가장자리·스와이프로 쪽을 넘긴다. 사진·글의 실제 조합을 보여준다.
- 셰브론·관리가 있는 헤더의 위쪽 패딩은 40px+상단 안전 영역이다(앱 높이 620px 이하에서는 24px).
  읽기 지면은 좌우 36px(앱 너비 340px 이하에서는 28px)+안전 영역, 위아래 12px의 별도 영역에 배치한다.
  지면·공동작성 서명·쪽 이동 행을 한 묶음으로 읽기 영역의 세로 중앙에 맞춘다. 쪽 이동은 지면/서명 바로 아래 12px에 배치한다.
  실제 버튼 높이와 공동작성 서명을 반영해 아래 조작부가 넘치지 않도록 지면 크기를 정하고, 종이 안쪽 여백과 PDF는 유지한다.
  화면이 지나치게 낮으면 읽기 영역에 최소 높이를 확보하고 그 영역만 스크롤해 종이와 쪽 이동이 잘리지 않게 한다.
  마디 남기기·함께 채우기는 읽기 영역 밖의 별도 하단 조작부이며 좌우·하단 16px+안전 영역을 사용한다.
- 하루마디·PDF 보관함의 뒤로가기도 다른 화면과 같은 공용 셰브론 버튼을 사용한다.
  책장 복귀·하루마디 복귀 목적지는 접근성 이름으로 제공하며 저장 중 차단과 덮기 애니메이션은 유지한다.
- 공동작성 마디의 작성자는 종이 바로 아래 왼쪽 서명으로 표시하고 쪽수와 분리한다.
  표지·뒷표지·빈 지면에는 표시하지 않으며 전환 중 지면 크기가 바뀌지 않도록 공동작성 책 전체에
  같은 서명 공간을 확보한다. 이 공간도 화면 쪽 나눔 계산에 반영하며 인쇄용 PDF는 바꾸지 않는다.
- 책장의 작은 표지와 읽기용 표지는 구분한다. 펼치기·덮기는 읽기 권한이 확인된 본문의
  `buildHarumadiCoverPage`·`HarumadiPageSheet`를 공유해 날짜 범위·첫 사진·제목·색상·로고 위치를 맞춘다.
  별도 표지 요청이나 생성일 기반 임시 표지는 사용하지 않는다. 확대·회전 좌표는 목업 축소 전 CSS 크기로 환산한다.
- 화면 지면은 목업 축소 전 CSS 크기와 로딩된 Pretendard의 글자 너비로 나눈다.
  글꼴 로딩 후 재계산하며 단어·줄바꿈·공백을 보존한다. 측정 불가 시 보수적 추정값을 쓴다.
  사진·글 간격은 화면용 22–36px 안에서 실제 글 높이에 맞춰 연속 조정하고,
  그래도 담기지 않을 때만 다음 쪽으로 잇는다. 화면 본문 글자 크기는 줄이지 않는다.
  글 전용 첫 쪽은 짧은 글의 중앙 프레임과 장문의 상단 정렬 구조별로 실제 본문 폭·메타/제목 높이·여백을 계산한다.
  사진 위 장소는 두 줄까지 표시하고 해당 높이를 사진 배치와 쪽 분할에 함께 반영한다. 장소가 없으면 장식점·구분점도 생략한다.
  이어지는 쪽에는 원래 제목·날짜·장소와 작은 사진을 표시한다. 원문·저장 순서와 인쇄용 PDF는 바꾸지 않는다.
  앱 읽기는 A5 비율·기본 여백을 PDF와 공유하지만 화면용 글자·세로 글 배치·쪽 나눔은 별도다.
  PDF의 사진·글 간격 66/30pt와 인쇄 배치는 화면용 간격 변경의 영향을 받지 않는다.
- 마지막 뒷표지는 `다음 쪽` 대신 `덮기`다. 상단 `내 책장`과 같은 경로로 표지를 덮은 뒤 홈으로 간다.
- 본문에서 닫기는 560ms 표지 회전 후 180ms 정리 애니메이션을 사용한다. 앞표지에서 닫기는
  추가 표지나 회전 없이 현재 화면을 180ms 페이드아웃한다. 중복 입력·이탈 때 취소하고,
  동작 줄이기·API 미지원에서는 즉시 복귀한다. 브라우저 popstate의 즉시 닫기와 구분한다.
- 뒷표지는 준비된 문구 중 하나를 생성 시 한 번 저장한다. 혼자 쓴 책에도 맞는 문구를 포함한다.
  사용자가 수정·다시 고르기·빈 문구로 저장할 수 있고 읽기·PDF가 같은 값을 사용한다.
- 삭제는 일반 설정과 분리한 주의 영역·최종 확인으로 제공한다. **틀 삭제는 복구할 수 없지만
  원본 마디와 기존 PDF 사본은 유지한다.** 마디 삭제는 연결만 제거하고 틀은 남긴다.

## 마디 순서 바꾸기

하루마디를 펼친 뒤 하단 `순서 바꾸기`에서 사진·제목·날짜를 확인하며 손잡이를 끌거나
위·아래 버튼으로 옮긴다. 키보드에서는 손잡이의 위·아래 방향키도 사용한다.
`이 순서로 저장하기`를 눌러 확정하며 돌아가기는 저장하지 않는다. 두 개 이상 담긴 온라인 책에서 제공한다.

드래그 중 잡은 마디는 손을 잡은 지점을 유지하며 포인터를 따라 움직인다. 이웃 마디의 중앙을
지날 때 미리보기 위치만 바꾼다. 드래그 중 React의 실제 DOM 순서는 고정하고 이웃 행의
CSS transform만 양방향 같은 420ms cubic-bezier 이징으로 이동시켜 재삽입으로 인한 끊김을 피한다.
실제 편집 순서는 손을 놓을 때 한 번 반영하며, 진행 중인 이웃 이동은 현재 보이는 위치에서
최종 슬롯으로 이어간다. 취소는 부모 순서를 변경하지 않은 채 원위치로 돌아간다.
위·아래 버튼과 방향키 이동도 두 행을 고정 DOM에서 CSS로 먼저 교차시킨 뒤 순서를 확정한다.
썸네일 번호는 손을 놓기 전에도 드래그 미리보기 순서를 따르며, 이웃 마디의 번호도 함께 바뀐다.
드래그를 취소하면 원래 번호로 돌아가고 실제 편집 순서는 손을 놓을 때만 갱신한다.
저장할 편집 순서는 버튼 입력 즉시 갱신하므로 이동 중 저장하더라도 이전 순서를 저장하지 않는다.
연속 버튼 입력은 기존 노드의 목표 위치와 종료 타이머만 갱신하고, 동작 줄이기는 즉시 반영한다.
사진·글 미리보기와 쪽 순번을 한 장처럼 묶고, 손잡이와 보조 화살표는 오른쪽에 모았다.
자리 이동량은 목록 내부 좌표로 계산하며 순서 편집 영역의 스크롤 앵커링을 끈다.
DOM 재배치 때 화면 스크롤이 보정되더라도 밀려 내려가는 행의 이동량이 상쇄되지 않도록 한다.
손을 놓으면 빈자리에 정착하며 취소·Escape·창 이탈은 해당 드래그 전 순서로 복구한다.
움직이는 행이 아니라 고정 목록에 포인터 캡처를 두어 재배치 중 끊김을 방지한다.
가장자리 자동 스크롤·높이가 다른 행·축소된 PC 목업 좌표를 처리하며, 동작 줄이기는
포인터 추적만 유지하고 자리 이동·정착 애니메이션을 생략한다.

- 개인·공동작성 모두 만든 사람만 전체 순서를 바꾼다. 참여자는 저장된 순서로 읽는다.
- `HarumadiEntryLink.position`에 권별 위치를 저장한다. 원본 마디·작성자·연결 ID는 변경하지 않는다.
  **기본은 담은 순서**이며 새로 담거나 다시 담은 마디는 마지막에 놓는다. 첫 마디·골라 담기·함께 채우기·
  여러 마디 추가 모두 DB 삽입 트리거가 책 행 잠금 안에서 위치를 부여한다. 사용자 수동 정렬은 유지한다.
  과거 담은 시각은 저장하지 않았으므로 이전 이력을 추측하지 않으며, 기존 마디는 현재 표시 순서를 위치로 고정한다.
- 순서 API는 인증·약관·소유권·전체 연결 목록·리비전을 확인한 뒤 책 행 잠금 안에서 위치를 갱신한다.
  마디 추가·제거·다른 순서 변경과 충돌하면 409로 거절하며 오래된 화면으로 덮어쓰지 않는다.
- 책 목록·본문·설정 표지·새 PDF는 같은 순서를 따른다. 표지 날짜 범위는 최소·최대 방문일이며
  순서를 거꾸로 놓아도 날짜가 역전되지 않는다. 이미 저장한 PDF 사본은 바뀌지 않는다.
- 저장 성공 시 책·책장·표지 캐시를 갱신한다. 입력·충돌 거절은 편집 화면에 표시하고 최신 내용 확인을 요청한다.

적용에는 추가형 마이그레이션 `20261102180000_harumadi_entry_order`가 필요하다.
담은 순서 기본값은 `20261103010000_harumadi_append_order`에서 기존 위치를 보존·정규화하고
모든 새 연결에 마지막 위치를 부여한다. 이전되지 않은 null 연결만 종전 날짜·ID 순서로 읽는다.
격리 DB에서 위치 제약·소유자 전용 권한·동시 수정 충돌·기존 연결 보존을 검증한다.
운영 마이그레이션·웹 배포·앱 업로드와 실기기 드래그 검증은 별도다.
2026-11-03 개발 DB에 두 마이그레이션을 적용하고 개발 서버를 갱신했다.
운영에는 초기 순서 편집(`beca86f`)만 배포했으며, 담은 순서 기본값·드래그 모션 개선은 아직 반영하지 않았다.

## 서버 원본과 기기 캐시

서버가 원본이다. 소유자별 읽기 캐시는 빠른 재열람용이며 접근 권한·동의 영수증이 아니다.

- `src/lib/harumadiReadCache.ts`: 최대 5권, 7일, 권당 3MiB. 썸네일을 포함한다.
- 화면에 캐시를 먼저 표시해도 서버에서 다시 확인한다. 다른 계정 캐시를 재사용하지 않는다.
- 캐시 열람 안내는 지면을 밀지 않는 공용 토스트로 1.8초간 표시한다. 빠른 갱신은 생략하고 같은 열람 중 상태별로 한 번만 알린다. 확인 전 편집 제한은 유지하며 헤더에서 최신 내용을 다시 확인할 수 있다.
- 미리보기와 열람은 공통 복원 경로를 사용한다. 늦은 파일 응답은 최신 서버 응답·권한 거절·세션 교체·삭제 무효화를 덮지 않는다.
- 합성 회귀 시험은 서버 요청을 대기시킨 상태에서 캐시 표시 전후의 펼침 준비 상태와 최신 응답 반영을 확인한다.
  이는 실기기 속도 실측이 아니다. 전체 콘텐츠 API 경량화나 900ms 펼침 시간 변경은 이번 캐시 연결에 포함하지 않는다.
- 생성·수정·삭제·마디 변경, 인증·권한·민감정보 상태 변경에 따라 무효화한다.
- 표지 사진도 인증 API의 축소 이미지를 사용한다. 공용 HTTP 캐시에 넣지 않는다.
- 앱 데이터·브라우저 저장소 삭제 시 캐시는 없어져도 서버의 원본은 유지된다.

## PDF 저장과 레이아웃

`PDF로 저장하기 → 미리보기 → PDF 파일 저장하기`는 책 편집과 별도 흐름이다.
저장한 PDF는 `/harumadi/pdfs`에서 열며, 원본 변경 후에도 저장 당시 사본을 유지한다.
기존 PDF의 작은 표지도 해당 PDF 첫 쪽에서 만들며 현재 마디로 재구성하지 않는다.

- A5 지면 수치는 `src/shared/harumadi/pdfLayout.ts`에서 관리한다. 실제 읽기와 예시 지면은
  사진·날짜·장소·제목·본문·쪽번호 등 공유 수치를 사용한다. 표지 설정 미리보기의 과장과 구분한다.
- 사진만·글만·사진과 글 모두 지원한다. 긴 본문은 이어지는 지면으로 처리하며 원문은 바꾸지 않는다.
- 제목·첫 장 글·뒷표지 문구와 실제 원본을 바탕으로 서버에서 렌더한다. 미리보기 승인과
  원본 변경·소유권·철회 상태를 저장 시 다시 확인한다.
- Pretendard와 PDF.js Worker·폰트·WASM은 [PDF 폰트](./pdf-fonts.md) 및 `pnpm pdf:assets`로 준비한다.
  PDF.js는 동적 로드하고 화면 주변 캔버스만 유지한다. 사용자 자료를 외부 PDF 서비스로 보내지 않는다.
- 미지원 글리프는 PDF에서 대체할 수 있으며 원문은 유지한다. 컬러 이모지 재현을 보장하지 않는다.

## API·데이터·접근 제한

| 대상 | 모델·테이블 | API |
| --- | --- | --- |
| 편집 가능한 책 | `Harumadi` / `harumadis` | `/api/harumadis` |
| 저장 PDF | `HarumadiPdf` / `harumadi_pdfs` | `/api/harumadi-pdfs` |
| 개별 마디 | Journal 계열 | `/api/journal-entries` |

PDF 미리보기는 `POST /api/harumadi-pdfs/preview`다. 인증 소유자의 DB 자료만 읽으며
클라이언트가 지정한 임의 사진 URL을 서버에서 가져오지 않는다.

- 요청 본문 최대 16KiB, PDF 원문 텍스트 합계 최대 60,000자. 마디 개수의 고정 상한은 없지만
  큰 책은 요청 크기나 PDF 처리량 보호에 따라 한 번에 저장·출력되지 않을 수 있다.
- 이미지당 최대 5MiB·16,000,000픽셀. 이미지 변환 후 렌더한다.
- PDF 파일은 최대 20MiB·100쪽의 기존 처리 보호를 유지한다. 마디 개수 제한과는 별개다.
- 미리보기 분당 6회, 서버 프로세스당 PDF 생성 1건. 작업 중 추가 요청은 429로 제한한다.
- PDF 응답은 `private, no-store`, 소유자에게만 조회·삭제를 허용한다.
- 저장 객체는 `harumadi-pdfs/<ownerId>/<harumadiPdfId>.pdf`. 계정 삭제·병합·민감정보 철회는
  기존 파일 정리·원장 경로를 따른다. 이미 다운로드한 사본은 원격 회수하지 못한다.

## 이전 작업과 배포 주의

기존 PDF 초안은 책장의 `이전 PDF 작업 이어가기`와 `/harumadi/pdf/create`에서만 복원한다.
사용자별 한 개의 `tuti-harumadi-pdf-v1:<userId>` 초안에 선택 ID·제목·편지·필터·단계를 저장한다.
원문·사진·PDF 파일은 복사하지 않는다. 새 마디 초안의 저장 정책과는 다르다.
이전 객체 키·서명 원장 호환 읽기는 `src/shared/harumadi/legacy.ts`에 고정되어 있다.

`20261028120000_remove_harumadi_inner_style` 적용 후 구 이미지로 단순 롤백할 수 없다.
배포·롤백 보호 장치는 `com.tuti.harumadi-layout=automatic` 호환성을 확인한다.
DB·삭제 원장을 과거로 되돌려 우회하지 않는다. 뒷표지 열 추가는 별도 마이그레이션이다.
자세한 절차는 [운영 명령](./operations.md)을 따른다.

## 예시와 실물 관심

예시는 `/harumadi/example?page=…`의 독립 화면이며 이전 히스토리로 돌아간다. 직접 진입만 홈으로
복귀한다. 표지 → 사진과 글 → 사진만 → 글만 → 시작 안내 순서이고 마지막은 책 지면이 아닌 CTA다.
초기 안내를 완료해 홈·작은 여행에 도달한 계정은 일반 흐름에서 `/entry`로 돌아가지 않는다.

실물 관심 버튼은 준비 중 안내·관심 이벤트용이다. 주문·결제 성공이 아니며 제거한 첫 화면
구매 버튼의 과거 이벤트도 실제 구매로 재해석하지 않는다. 계측 원문은 최소 필드와 보관기한을 따른다.
