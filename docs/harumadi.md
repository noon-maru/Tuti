# 하루마디 제작과 계정 보관

## 메인 책장 크기와 여백 (2026-10-27)

- 메인은 제목 28px, 주요 행동·권별 제목 16px, 보조 정보 13~15px를 중심으로 키운다. 책장 표지 제목은 균형을 위해 16px로 조절하며, 권별 설정은 44px 터치 영역, 상단 설정은 48px, 하단 작성은 52px 높이를 확보한다.
- 크기를 확보하기 위해 여백을 줄이지 않는다. 기존 2열·열 간격 24px·책장 좌우 20px + 안쪽 8px를 유지한다. 제목은 최대 두 줄이며 보조 정보는 실제 제목 높이에서 8px 아래에 배치한다. 108px 제목 영역과 행 사이 36px를 확보해 선반도 같은 높이에 정렬한다. 설정 버튼은 첫 줄 옆에 두고 그 공간은 제목에만 적용한다. 한 화면에 보이는 양보다 기존의 여유 있는 밀도를 우선한다.
- 표지 크기는 홈 전용 CSS 변수로 조정하고 하단 내비게이션의 크기는 `MainNavigation` 내부에서만 관리한다. 홈·작은 여행 모두 라벨 12px, 작성 버튼 14px·52px 높이, 탭 56px 높이, 아이콘 24px로 표시한다. 첫 마디 여부도 같은 계정의 책장 목록 캐시를 공유해 판정하며 조회 전·실패 시 빈 계정으로 추정하지 않는다. PDF/예시 지면 크기는 변경하지 않는다. 좁은 사진 표지에서도 제목과 사진이 겹치지 않도록 사진 영역에 상한을 둔다.
- 높이 620px 이하의 빈 책장에서는 글자 크기를 유지하면서 장식 그림과 세로 간격을 줄여 예시 링크가 하단 보관함 뒤에 걸리지 않도록 한다.

## 책장에서 펼쳐보기와 권별 설정 (2026-10-27)

- 각 하루마디 제목 옆의 세로 점 버튼은 해당 권의 설정을 바로 연다. 표지 버튼과 별개의 버튼이며 설정 저장 후에는 책장으로 돌아와 변경된 제목·표지를 반영한다.
- 표지를 누르면 경로를 바꾸지 않고 책장 위에서 읽기 화면을 연다. 선택한 표지가 원래 위치에서 중앙으로 이동하고 책등을 축으로 열리며 지면을 드러낸다. 기존 색상·서체·표지 컴포넌트를 재사용하고 transform/opacity만 애니메이션한다.
- 읽기는 세로 마디 목록이 아니라 표지 → 각 마디 → 뒷표지로 한 쪽씩 표시한다. 책장에서 표지를 열면 첫 본문(빈 책은 첫 마디 안내)부터 보이며 이전 쪽으로 표지를 볼 수 있다. entry 예시와 실제 마디는 `HarumadiSheet`의 종이·서체·사진/글 배치 및 PDF의 A5 수치를 공유한다. 사진만 있으면 사진 지면, 글만 있으면 글 지면, 둘 다 있으면 사진과 글을 함께 자동 배치하며 선택 제목이 없으면 임의 제목을 넣지 않는다.
- 이전/다음 쪽, 지면 좌우 22% 영역, 좌우 스와이프·마우스 드래그, 방향키로 이동한다. 예시의 정방향/역방향 대칭 쪽 넘김을 재사용하고 전환 중 중복 입력을 막는다. 작성·골라 담기·PDF 저장은 지면 아래 도구로 분리했다.
- 긴 본문은 원문을 누락하지 않고 이어지는 쪽에 나눠 표시한다. 지면 수치는 PDF와 공유하지만 브라우저 줄바꿈을 위한 보수적인 분할이므로 긴 글의 쪽 경계·총 쪽 수가 PDF와 동일하다는 보장은 하지 않는다. PDF 생성·영구 저장은 읽기와 별개이며 책을 열 때마다 PDF를 생성하지 않는다.
- 화면 읽기의 글자 크기는 인쇄 pt 비율 축소와 분리한다. 본문 16px, 사진 본문 14px, 제목 16~18px, 날짜·장소 11px로 표시하고 사진의 제목·본문은 위아래로 배치한다. PDF 출력과 인쇄 지면을 보여주는 entry 예시의 원래 크기는 변경하지 않는다. 책장·설정·쪽 이동·작성 도구의 안내도 12~16px 중심으로 키웠다.
- 읽기 화면은 실제 지면 너비를 관찰해 글자 크기에 맞게 본문을 분할한다. 좁은 화면이나 긴 제목은 별도 지면으로 이어가며 제목·본문을 삭제하지 않는다. 화면 크기에 따라 읽기의 쪽 수는 달라질 수 있다.
- 책장을 언마운트하지 않아 닫은 뒤 스크롤 위치가 유지된다. 펼쳐진 동안 배경은 inert 처리하고 키보드 포커스를 내부에 유지한다. 뒤로가기와 Esc는 내부 편집 단계·저장 중 보호를 유지하며, 읽기 상태에서는 책장으로 복귀한다. 로딩·실패 상태에서도 닫을 수 있다.
- PC에서도 앱 목업 영역 안에서만 펼친다. 동작 줄이기 설정에서는 표지 회전·이동을 생략한다. 기존 `/harumadi?harumadiId=...` 직접 접근과 마디 작성 후 연결은 유지하며 캐시 읽기 전용·권한 검사는 동일한 `HarumadiFlow`를 사용한다.
- 합성 데이터 브라우저 검증: 경로 유지, 펼치기 애니메이션, 설정 저장, Esc, 320/390/1280px 화면, 동작 줄이기. Android/iOS 실기기 동작 검증은 별도다.

## 하루마디 읽기 캐시 (2026-10-27)

- 서버가 원본이다. 한 권을 열면 로컬 사본을 먼저 표시하고 `GET /api/harumadis/:id/content`로 해당 권과 연결된 마디만 함께 재조회한다. 전체 마디 목록·PDF 정책 조회는 선택·설정·PDF 작업 시에만 한다.
- 캐시는 최근 5권, 권당 최대 3MiB, 7일 유효다. 만료 사본은 접근·갱신 시 정리하며 앱을 사용하지 않는 동안 정확히 7일째 물리 삭제되는 예약 작업은 아니다. 네이티브는 Filesystem `Directory.Cache`, 웹은 해당 플러그인의 IndexedDB를 사용한다. OS가 캐시를 비우면 서버에서 다시 읽는다.
- 일반 마디로 명시된 데이터만 저장한다. 민감정보·분류 미확정·철회 마디는 저장하지 않는다. 사진은 최대 640px JPEG 사본만 저장하고 원본 사진·서명 URL·인증 토큰·동의 영수증은 저장하지 않는다. 외부 사진은 새로 내려받지 않으며 일부 사진이 없으면 이를 안내한다. 앱 자체 암호화 저장 기능은 아니다.
- 계정과 로그인 세션별로 분리한다. 로그아웃·계정 전환·계정 삭제·마디 변경/삭제/민감정보 동의 변경 시 무효화한다. 계정 캐시 삭제 실패 시 영속 차단 표시로 재사용을 막는다. 이전 비동기 사진 작업이 최신 사본이나 삭제 결과를 덮지 않도록 세대를 검사한다.
- 서버 확인 전과 통신 실패 시에는 읽기만 허용하고 편집·삭제·PDF 생성은 막는다. 401/403/404/409 등 확정적인 거절은 기존 본문을 숨기고 사본을 무효화한다. 오프라인 작성·동기화나 책장 전체의 오프라인 진입을 제공하는 변경은 아니다.
- WebCrypto를 사용할 수 없으면 영속 캐시를 생략한다. 새 통합 조회 API와 썸네일 처리를 포함한 서버 배포가 필요하며 DB 마이그레이션은 없다.

검증: 합성 데이터·모의 API를 사용한 Chromium에서 캐시 선표시, 서버 본문 갱신(책 revision 동일), 통신 실패 시 읽기 전용, 403 시 본문 제거, 민감 마디 미저장, 로그아웃 시 사본 제거를 확인했다. 개발 서버의 앱 내 재진입에서 서버 응답을 보류한 채 캐시 본문이 약 138~209ms에 표시됐다. 개발 환경 두 차례 측정이며 운영 성능 보장은 아니다. Android/iOS 실기기 검증은 별도로 필요하다.

## 사용자에게 쓰는 말

### 뒷표지 문구

- 새 하루마디 생성 시 준비된 문구 12개 중 하나를 서버에서 한 번 골라 `harumadis.back_cover_text`에 저장한다. 혼자 남긴 하루와 함께한 하루의 문구를 섞었으며, 첫 마디로 자동 생성되는 기본 하루마디에도 적용한다.
- 설정의 ‘뒷표지 문구’에서 직접 수정하거나 ‘다른 문구 보기’로 교체한다. 최대 120자·3줄이며, 빈 값은 문구 없는 뒷표지다. 다른 문구 보기는 현재 문구를 제외하고, 설정 저장 전에는 서버 값을 바꾸지 않는다.
- 읽기 화면과 해당 하루마디로 만드는 PDF 모두 저장된 동일 문구를 사용한다. 열기·새로고침·PDF 재생성 시 무작위로 바꾸지 않는다. 이미 저장한 PDF 파일은 바꾸지 않는다.
- `20261028150000_add_harumadi_back_cover_text`는 기존 하루마디에 ‘오늘 가능한 만큼만,’을 유지한다. 문구를 보내지 않는 기존 설정·마디 연결 요청도 저장된 문구를 덮어쓰지 않는다. 뒷표지 수정은 표지 제목과 같은 자유 입력 확인 정책을 따른다.

### 새 하루마디 화면

- 새로 만들 때는 중앙 표지 → 이름 입력란의 여유 있는 세로 배치를 기본으로 하고, 남는 높이는 요소 사이 여백에 분산한다. 앱 영역 높이가 720px 미만일 때만 표지와 이름을 나란히 배치하며 표지·여백을 줄인다. 브라우저 전체가 아닌 앱 영역 기준이며, 높이 620px 이하·너비 340px 이하에서는 압축 배치를 더 다듬는다.
- 생성 버튼은 본문 밖 하단에 유지하며 입력 글자 16px·표지 선택 조작 영역 44px은 줄이지 않는다. 보통의 작은 세로 화면에서는 스크롤 없이 구성하고, 키보드·확대 글꼴·오류 안내로 공간이 모자라면 본문 스크롤로 모든 입력과 안내에 접근할 수 있다. 기존 하루마디 수정·PDF·마디 선택 화면의 스크롤은 유지한다.
- 생성·수정의 표지 미리보기는 `HarumadiPageSheet`와 같은 표지 데이터를 사용하되, 작은 크기에서도 구분되도록 미리보기 전용으로 강조한다. 사진 없는 표지는 큰 제목을 중앙에, 사진 표지는 날짜를 생략하고 사진 영역을 크게 표시한다. 실제 표지·PDF의 배치와 크기는 바꾸지 않는다. 실제 마디가 있으면 같은 날짜 범위와 첫 사진을 사용하고, 새 책에는 가짜 날짜나 예시 사진 대신 빈 책 상태와 사진 자리의 대체색을 표시한다. 표지 전용 추가 API 요청은 하지 않는다.
- 미리보기의 하단 Tuti는 사진 유무와 관계없이 같은 위치에 고정한다. 사진은 PDF의 210:170 비율을 공유하고 기존 PDF 비례 크기의 1.5배로 표시하며, 남는 영역에 맞춰 세로로 늘리지 않는다.

### 메뉴와 마디

- 장소 추천 메뉴 이름은 **작은 여행**이다. `다음 마디가 될 작은 여행`과 `가까운 곳에서, 남기고 싶은 하루를 만나보세요.`로 다음에 남길 경험을 발견하는 역할을 설명한다. 진입은 `작은 여행 찾아보기`, 작성 후 복귀는 `작은 여행으로 돌아가기`로 맞춘다. `/explore` 경로와 내부 계측 이름은 유지하고, 실제 장소를 살펴보는 일반 동사 ‘둘러보기’는 치환하지 않는다.
- 사진과 짧은 이야기로 남기는 개별 콘텐츠는 **마디**, 마디를 골라 채우는 한 권은 **하루마디**다. 장소가 없는 글·사진도 마디가 될 수 있다.
- 첫 진입은 “사진 한 장, 짧은 이야기로 우리의 첫 마디를 남겨보세요”와 “첫 마디 남기기”로 안내한다. 빈 하루마디에는 “첫 마디를 채워보세요”를 사용한다.
- 일반 작성은 “마디 남기기”, 목록은 “나의 마디”, 기존 콘텐츠 선택은 “마디 골라 담기”로 구분한다. 저장 뒤 계속 작성할 때는 다시 “첫 마디”라고 부르지 않는다.
- 하루마디 안에서 시작한 작성은 “이대로 마디 남기기” 한 번으로 저장 후 원래 하루마디에 바로 연결·복귀한다. 별도 완료 화면이나 “하루마디에 담기” 버튼을 거치지 않는다. 홈·작은 여행 등 하루마디 밖에서 작성한 두 번째 이후 마디만 저장 후 하루마디 선택·담지 않기를 제공한다.
- 페이지·쪽·PDF는 실제 지면과 파일을 가리킬 때 유지한다. 이용·접속·감사 기록, 공고된 약관과 정책의 정식 명칭·동의 문안은 치환하지 않는다.
- 이번 변경은 사용자 문구에 한정한다. `journal` API·모델·계측 식별자와 저장된 사용자 제목·본문은 변경하지 않는다.

## 내부 명칭과 이전 (2026-10-26)

- 편집 가능한 본체는 `Harumadi`/`harumadis`, 저장 시점의 PDF 사본은 `HarumadiPdf`/`harumadi_pdfs`로 구분한다.
- API는 `/api/harumadis`와 `/api/harumadi-pdfs`다. 본체 응답 키는 `harumadi`/`harumadis`, PDF 응답 키는 `harumadiPdf`/`harumadiPdfs`다.
- 화면 경로는 `/harumadi`, `/harumadi/pdfs`, `/harumadi/pdf/view`, 이전 PDF 초안 도구는 `/harumadi/pdf/create`다.
- 적용된 80번째 마이그레이션은 보존하고, 81번째 마이그레이션으로 임시 명칭에서 `harumadi`로 테이블·연결 열·인덱스·활동 enum 및 제품 관심 집계 이름을 이전한다. 사용자·원본 기록·PDF 행과 객체 키는 삭제하거나 재작성하지 않는다.
- 신규 PDF 객체와 기기 초안은 새 이름으로 저장한다. 이전 객체 경로·기기 초안·승인 비밀값 이름·서명된 삭제 원장은 `src/shared/harumadi/legacy.ts`의 고정 식별자로 호환 읽기한다.
- 이전 초안 읽기와 삭제/새 저장이 경합할 때 과거 내용으로 되돌리지 않는다. 이전 서명 원장의 종류·대상 HMAC은 수정하지 않고 새 이름의 자료와 함께 재파기한다.
- 적용된 마이그레이션과 승인·공고된 약관 원문은 이 변경에서 수정하지 않는다. 과거 백업 격리 검증과 운영 객체 대조는 이전 물리 테이블 이름도 조회할 수 있다.
- **이전 API 경로는 제거했다.** 새 앱 빌드와 서버·DB 전환을 함께 준비해야 하며, 이 작업만 운영에 단독 배포해서는 안 된다. 구 앱의 기존 PDF 접근도 새 경로로 바뀐다.
- 개발 DB에서 이름 변경 전후의 행 수 보존과 새 Prisma 관계 조회를 확인했다. 개발 앱은 모델 캐시 갱신을 위해 재시작해야 한다. 운영에는 반영하지 않았다.
- 전체 검사 576개 중 574개 통과·2개 건너뜀. 타입·린트·새 경로의 빈 하루마디 생성→기록 선택→책장 복귀를 확인했으며, 이 동선은 PDF를 생성하지 않는다. 임시 명칭의 초안·PDF·계측·서명 원장 호환도 검증했다.

현재 구현은 표지를 먼저 정해 빈 하루마디를 만들고, 기록을 채운 뒤 필요할 때 별도로
PDF를 저장하는 방식이다. 편집 가능한 하루마디와 저장 시점의 PDF는 별개로 보관한다. 디지털 하루마디는
무료이며 결제·실물 제작·공개 링크는 제공하지 않는다.

실물 하루마디 단건 판매는 이 무료 기반 위에서 가장 먼저 검증할 BM 가설이다.
기관 연계 프로그램은 개인 상품 검증 뒤의 후순위 기회다. 제품 방향은
[제품 방향과 우선 고객 가설](product-direction.md), 구현·검증 순서는
[하루마디 BM 적용·검증 계획](harumadi-bm-validation-plan.md)을 따른다.

## 사용자 흐름

최초·미동의 사용자가 일반 화면으로 진입하면 약관 확인 결과에 따라 `/entry`로 이동한다. `/entry`에서 약관 동의 후 시작 안내로 이어지고, 기존 동의 완료 사용자는 `/` 책장에서 시작한다. 계정 삭제 완료의 “처음부터 다시 시작하기”도 `/entry`로 연결한다. 로그인·문의와 기존 세션의 자료 열람·삭제·철회 경로는 이 이동에서 제외한다.

최초 동의 화면은 “동의하고 시작하기” 클릭을 만 14세 이상 확인과 서비스 이용약관·중요 내용에 대한 명시적 동의로 안내한다. 미리 체크하지 않아도 버튼을 누르면 필수 두 항목이 차례로 체크되고, 서버에 동의가 저장·검증된 뒤 진입한다. 이미 체크한 항목은 다시 재생하지 않으며 동작 줄이기에서는 애니메이션을 생략한다. 위치기반서비스 약관은 별도 **선택** 항목으로 기본 미선택이며 자동 체크하지 않는다. 미선택 시 위치 동의·거부를 자동 생성하지 않고 바로 마디·하루마디 이용으로 이어진다. 선택한 경우 일반약관 저장 뒤 같은 계정에 위치 동의를 별도 저장하되, 선택 동의의 저장 실패만으로 시작을 막지는 않는다. 기기 위치 권한 요청·좌표 수집은 장소 탐색에서 현재 위치를 요청할 때만 수행한다. 기록 화면에서 위치 미동의 상태를 이유로 지역 선택창을 자동 표시하지 않는다.

홈(`/`)은 편집 가능한 하루마디의 표지를 진열한 가판대형 책장이다. 장소 추천은 `/explore`로
분리하며, 책장 진입만으로 추천 조회나 위치 요청을 시작하지 않는다. 책등 뷰와 한 권씩
넘기는 캐러셀은 후속 범위이며 현재는 가판대형만 제공한다.

하루마디 예시는 `/harumadi/example?page=…` 독립 화면이다. 홈·시작 안내·이용 가이드에서 같은 화면을 열며, 쪽 이동은 현재 히스토리를 교체한다. 닫기·ESC·안드로이드 뒤로가기는 실제 이전 페이지로 돌아가고 이전 기록이 없는 직접 진입만 홈으로 이동한다. 시작 안내에서의 펼치기 애니메이션 좌표는 일회성 메모리로 전달한다.

예시 순서는 표지 → 사진과 글 → 사진만 → 글만 → 시작 안내다. 지면 예시와 실제 PDF는 `src/shared/harumadi/pdfLayout.ts`의 A5 크기·여백·사진 크기·글자 수치·쪽번호 좌표를 공유한다. 사진만 있는 지면도 실제 PDF처럼 날짜·장소·쪽번호와 고정 높이의 사진(`cover`)을 표시한다. 마지막 시작 안내는 기록집 지면이 아니라 서비스 CTA다.

`내 책장 → 새 하루마디 만들기 → 이름·표지 설정 → 빈 하루마디 저장 → 기록 작성/선택 → 기록 채우기`

- 메인은 빈 계정이어도 `/entry`로 자동 이동하지 않는다. 첫 마디 작성을 취소하면 홈(하루마디에서 시작했다면 해당 하루마디)으로 이동한다. 소개 화면으로 보내는 경로는 최초 약관 진입·계정 삭제 후 새 시작 및 소개 내부 가이드 이동에만 남긴다.
- 메인 책장이나 둘러보기(`/explore`)에 도달하면 계정별 완료 이력을 기기에 저장한다. 이후 `/entry`·이용 가이드 주소로 돌아오면 소개를 다시 표시하지 않고 홈으로 이동한다. 단순 소개 열람과 완료 이력은 구분한다. 둘러보기로 나갈 때는 히스토리를 교체한다. 최초 약관 동의는 이 소개 이력으로 건너뛰지 않으며, 계정 삭제 후 새 계정은 별도 이력으로 시작한다.
- 빈 책장은 예시 표지 없이 `첫 마디 남기기`를 안내한다. 첫 마디를 저장할 때 하루마디가 없다면 `우리의 작은 하루`(흰색 표지)를 함께 만들고 그 마디를 담는다. 마디·하루마디·연결은 같은 트랜잭션에서 저장하고 계정별 잠금으로 중복 생성을 방지한다. 기존 마디나 직접 만든 하루마디가 있는 계정에는 자동 생성하지 않는다.
- 기록이 없어도 이름과 표지만 정해 빈 하루마디를 저장할 수 있다. 저널의 제작 카드는 제거하고 메인에서만 새 하루마디를 만든다.
- 표지를 누르면 `/harumadi?harumadiId=…`에서 하루마디를 열고 페이지를 채우거나 설정을 변경한다.
- 표지는 흰색·연두색과 사진 유무를 조합한다. 사진 표지는 담긴 기록 중 날짜순 첫 사진을 사용하며 사진을 담기 전에는 비워둔다.
- 속지 타입 선택은 없다. 화면과 PDF는 마디의 실제 사진·글 유무로 자동 배치하며 사진을 임의로 숨기지 않는다. 타입·API·DB의 속지 설정은 제거하고, 기존 읽기 캐시는 스키마를 올려 다시 받는다. 이미 저장한 PDF는 변경하지 않는다.
- `20261028120000_remove_harumadi_inner_style`은 설정 열 하나만 삭제한다. 원문·사진·PDF는 삭제하지 않는다. 적용 뒤 이전 속지 필드를 조회하는 구 이미지로 단순 롤백할 수 없으므로 운영 반영은 코드·스키마 전환을 함께 조정해야 한다. 사용자 데이터나 삭제 원장을 과거 DB로 되돌리는 방식으로 우회하지 않는다.
- 하루마디는 최대 12개 기록을 참조하며 원문·사진을 복제하지 않는다. 새 기록을 작성해 담거나 기존 기록을 선택한다. 기록 삭제 시 FK cascade로 연결만 제거하고 빈 하루마디 틀은 유지한다.
- 하루마디를 삭제해도 원본 기록과 이미 저장한 PDF는 유지한다. 계정 삭제 시 틀·연결은 함께 삭제되며, 틀 삭제는 기존 하루마디 삭제 원장으로 복원 후에도 재이행한다.
- 같은 하루마디의 동시 수정은 revision 충돌로 거절한다. 구형 일괄 테스트 계정 정리 도구는 새 하루마디가 있는 계정을 제외한다.
- 홈·작은 여행은 공통 하단 바 `하루마디 / ＋ 마디 남기기 / 작은 여행`을 사용한다. 양쪽 탭은 현재 선택 상태를 표시하고 히스토리를 교체하며, 가운데 작성은 별도 화면을 연다. 빈 홈에서는 `첫 마디 남기기`로 안내한다. 작은 여행의 기존 상단 내 책장 이동은 제거했다. 하위 화면은 하단 바 없이 셰브론으로 복귀하며, 개별 마디 목록은 홈의 `전체 마디 보기`로 들어간다.
- 둘러보기의 아래 방향 드래그·휠은 전체 마디 목록 대신 `/madi/new?from=explore` 작성 화면으로 연결한다. 미리보기는 비활성 작성 화면이며 정책·목록을 조회하지 않는다. 추천 장소를 방문했다고 추정해 자동 입력하지 않고, 저장·취소 뒤에는 둘러보기로 돌아간다.
- 전체 마디 화면은 `/madi`, 작성·상세·수정은 `/madi/new`·`/madi/detail`·`/madi/edit`를 사용한다. 목록의 위로 쓸어 나가기 제스처는 없애고 상단 셰브론으로 실제 이전 화면에 복귀한다. 직접 진입으로 이전 히스토리가 없으면 홈으로 돌아가며 카드 넘기기 동작은 유지한다. 기존 `journal` API·모델·계측 이름은 바꾸지 않는다.
- 민감정보 보관 기능이 비활성화되었거나 정책 확인 전이면 기존 마디 수정 화면의 추가 설정과 민감정보 동의 질문을 숨기고 작은 주의 문구만 표시한다. 기존 민감정보 마디는 일반 마디로 자동 전환하지 않으며, 기능 비활성화 시 수정 차단·상세 메뉴의 철회 안내를 유지한다.
- 모든 새 마디는 진입 위치와 무관하게 `MadiCreateScreen`의 사진 → 이야기 → 미리보기 → 저장 흐름을 사용한다. `첫 마디` 안내는 전체 마디 조회 성공 후 개수가 0개일 때만 표시하며, 이어 쓰기는 새 마디로 안내한다. 진입 위치는 취소·완료 후 복귀 화면만 결정한다. 간편 작성은 일반 마디로 저장하고 정책 조회·추가 설정 없이 작은 주의 문구를 표시하며, 기존 마디 수정의 민감정보 보호 기능은 별도로 유지한다.
- 제목은 선택 입력(최대 80자)이며 미리보기·저장·하루마디/PDF에 반영한다. 사진·이야기 없이 제목만으로는 새 마디를 저장하지 않는다. 마디의 혼잡도·테마·난이도는 작성·수정·상세·웹 공개·공유 이미지·관리자·API·DB에서 제거했다. 장소 추천·설명의 혼잡도·분위기·이동 부담 정보는 유지하며, 마디 테마를 이용하던 보조 추천 가중치는 제거하고 연결된 방문 장소의 분위기만 참고한다. 자유 글에서 새롭게 취향을 추론하지 않는다.
- 82번째 마이그레이션(`20261027120000_remove_journal_classification`)은 `journal_entries`의 `crowd`·`theme`·`difficulty` 열과 기존 값을 삭제한다. 새 서버 코드와 함께 적용해야 하며, 삭제 후 이전 서버로 되돌리려면 DB 호환 복구가 필요하다. 과거 마이그레이션·승인 약관·이미 생성된 PDF/공유 이미지·보관 사본은 재작성하지 않는다.
- 2026-10-27 개발 DB에 82번째 마이그레이션을 적용했다. 기존 마디 3개의 나머지 열 값은 전후 해시로 보존을 확인했고 장소의 혼잡도 열도 유지했다. 새 Prisma 클라이언트로 선택 제목 생성·재조회를 검증한 시험 행은 트랜잭션 롤백으로 남기지 않았다. 개발 서버를 재시작하고 DB·객체 저장소 readiness를 확인했으며, 운영 DB에는 적용하지 않았다.
- 목록은 12권씩 더 불러오며 작은 표지는 화면 근처에서만 요청한다. 로딩·실패·빈 상태를 구분한다.

### 홈 표지와 접근 보호

목록에는 설정·기록 연결 ID만 포함하고 사진이나 PDF는 포함하지 않는다. 사진 표지는 소유한
비철회 기록의 사진을 인증 API에서 축소해서 제공하며 제목과 표지 색은 실제 컴포넌트로 렌더한다.
민감정보 열람 조건도 원본과 동일하게 확인한다. 공유 캐시에 저장하지 않으며 브라우저 캐시도 계정별로 나눈다.

### 별도 PDF 저장

하루마디 내부의 `PDF로 저장하기 → 미리보기 → PDF 파일 저장하기`로만 PDF를 생성한다.
하루마디 생성·기록 추가·설정 저장 자체는 PDF를 만들지 않는다. 미리보기 승인 해시와 원본 변경
검사를 거친 PDF를 별도로 보관하고 다운로드·OS 공유를 제공한다. 사진이 있는 마디는 본문에도
사진을 포함한다. 사진 표지 사용 여부는 본문의 사진 표시와 별개다.

메인 가판대는 제목·설정을 한 줄로 묶고, 상단의 `새 하루마디`에서 이름과 표지를 준비한다.
두 열의 표지 아래에 얇은 선반과 제목·마디 수를 표시하며, 빈 책장에서는 첫 마디 작성을 안내한다.
`전체 마디 보기`와 `저장한 PDF`는 목록 아래 보조 동선으로, 공통 내비게이션은 최하단에 유지한다.

이전 PDF도 메인의 `저장한 PDF`(`/harumadi/pdfs`)에서 그대로 열 수 있다. PDF는 저장 시점의
사본이므로 이후 하루마디 수정과 동기화되지 않는다. 보관 PDF의 작은 표지는 해당 PDF의 실제 첫 쪽으로
만들며 현재 기록으로 과거 PDF를 재구성하지 않는다. 배포 시 두 신규 마이그레이션이 필요하다.

### 기존 PDF 작업 호환

이전 기기의 제작 초안은 메인의 `이전 PDF 작업 이어가기`에서만 이어간다. `/harumadi/pdf/create`의
기존 제작 흐름은 이 초안 복원용으로 유지하고 저널에는 진입 버튼을 두지 않는다. 아래는 이 기존 도구의 상세다.

### 2026-10-26 로컬 검증

- 개발 DB의 79번째 마이그레이션까지 적용했다. 운영 DB·운영 객체는 변경하지 않았다.
- 전체 테스트 568개 중 566개 통과·2개 건너뜀. 표지/속지 입력, 빈 틀 저장, 소유권,
  수정 번호 충돌, 민감정보 철회, 삭제 원장 복원 재반영과 실제 PDF의 사진 포함 여부를 확인했다.
- 격리된 브라우저/API fixture로 빈 하루마디 생성 → 기존 기록 선택 → 본문 표시 → 책장 복귀를 확인했다.
  생성·기록 연결 동안 PDF 요청이 없었으며 320px·390px·PC 목업을 점검했다. 실제 운영 계정 시험은 아니다.
- 개발 PostgreSQL의 롤백 트랜잭션에서 기록 삭제 시 연결만 제거되고 틀은 남는지,
  계정 삭제 시 틀·연결이 cascade로 제거되는지 확인했다. 시험 데이터는 커밋하지 않았다.
- Android/iOS 실기기·네이티브 저장/공유와 앱 재빌드는 별도 검증이다.

### 이전 도구의 상세

- 1~12개 기록을 선택하며 기본 순서는 날짜순이다. 날짜 필터를 바꾸어도 선택은 유지한다.
- 제목은 최대 80자, 선택적인 첫 장 글은 최대 1,200자다. 글을 비워두면
  첫 장 글 페이지는 PDF에 넣지 않는다.
- 표지는 흰색·연녹색 배경을 먼저 고르고, 사진 포함 여부를 다음에 고른다.
  사진이 없는 기록은 선택한 배경에 맞는 색 면으로 대신한다.
- 사진은 전체가 보이게 배치한다. 긴 본문은 페이지를 추가해 이어 쓰며 원본 기록을 수정하지 않는다.
- 생성 PDF에는 쪽 번호를 넣지 않고, 화면 미리보기에서만 각 페이지 아래에 작은
  숫자로 순서를 표시한다.
- 미리보기에는 표지·편지·본문 전체와 페이지 수를 표시한다. 각 페이지의 글을 별도로 읽을 수 있다.
- `하루마디 완성하기`를 누르면 미리보기 때 승인한 PDF·소유권·원본 변경 여부를 서버에서 다시 검증해 계정에 보관한다.
- 완성한 하루마디는 같은 계정으로 로그인한 웹·iOS·Android에서 다시 열 수 있다.
- 웹에서는 PDF를 내려받고 앱에서는 운영체제 저장·공유 화면으로 전달한다.
- 완성한 하루마디는 사용자가 직접 삭제할 수 있으며 원본 기록을 지워도 완성 PDF는 유지된다.
- 없는 기록을 초안에서 발견하면 알리고, 해당 기록을 제외하는 동작을 제공한다.
- 자동 저장 실패와 PDF 생성 실패에는 재시도 동작을 제공한다.

## 초안 저장

Capacitor Preferences에 사용자 ID별로 한 개의 초안을 저장한다. 웹에서는
동일 플러그인의 브라우저 저장소를 사용한다. 저장 키는
`tuti-harumadi-pdf-v1:<userId>`다.

초안에는 선택한 기록 ID, 표지 기록 ID, 제목, 편지, 날짜 필터, 현재 단계만
포함한다. 원본 기록의 본문·사진과 생성 PDF는 로컬 초안에 복사하지 않는다.
연속 입력의 저장 순서가 바뀌지 않도록 사용자별 쓰기를 직렬화한다.

같은 기기·같은 사용자로 다시 열면 이어 만들 수 있다. 초안은 기기 간 동기화하지
않지만, 완성한 하루마디는 서버에 보관되어 같은 계정의 모든 기기에서 볼 수 있다.
익명 사용자에서 다른 계정으로의 초안 이전과 여러 초안 관리는 현재 범위에 없다.
앱 데이터 삭제·재설치·브라우저 저장소 삭제 시 초안이 사라질 수 있다.
계정 삭제 흐름에서는 해당 기기의 초안도 삭제한다.

## PDF 요청과 데이터 접근

`POST /api/harumadi-pdfs/preview`는 기존 Bearer 세션과 CORS 규칙을 사용한다.
본문은 선택한 기록 ID, 제목, 첫 장 글, 표지 스타일·기록 ID로 제한하며 사용자 ID나
원본 본문·사진 URL을 신뢰하지 않는다.

서버는 인증한 사용자 소유 기록만 DB에서 조회한다. 요청한 모든 기록이
조회되지 않으면 404를 반환하고 PDF를 만들지 않는다. 이미지도 조회한 기록의
내부 저장소 키로만 읽는다. 요청자가 지정한 URL을 서버에서 가져오지 않는다.
하루마디 화면의 조회 캐시도 사용자 ID별로 분리한다.

- 요청 본문 최대 16 KiB, 기록 최대 12개, 원본 텍스트 합계 최대 60,000자
- 이미지당 최대 5 MiB, 디코딩 최대 16,000,000픽셀
- sharp로 방향·크기를 정리하고 JPEG로 변환
- 기존 API 제한에 미리보기 분당 6회 정책 추가
- 서버 프로세스당 PDF 생성 1건, 작업 중 새 요청에는 429 반환
- 생성 실패 후 처리 슬롯을 반환해 재시도 가능
- 응답은 `application/pdf`, `Cache-Control: private, no-store`

미리보기 PDF는 저장하지 않는다. 사용자가 완성을 요청하면 서버가 소유권을 다시
검증해 PDF를 생성하고 `harumadi-pdfs/<ownerId>/<harumadiPdfId>.pdf`에 비공개로 보관한다.
DB에는 소유자, 제목, 선택 기록 ID, 페이지 수와 저장 키만 둔다. 파일 조회·삭제
API는 인증된 소유자에게만 허용한다. 계정 병합 시 완성본 소유권도 함께 이동하며,
계정 삭제 시 저장 PDF도 함께 삭제한다.

## 폰트와 PDF.js

[PDF 폰트 설정](pdf-fonts.md)의 Pretendard를 서버에서 등록한다. 지원하지
않는 글리프는 PDF에서 `□`로 대체하며 미리보기 화면에 안내한다. 원본 글은
변경하지 않는다. 컬러 이모지를 충실히 표시하려면 별도의 후속 작업이 필요하다.

PDF.js는 미리보기에서 동적으로 로드한다. Worker·표준 폰트·WASM 파일은
`pnpm pdf:assets`로 설치된 `pdfjs-dist` 버전에서 복사한다. 외부 CDN이나
사용자 기록을 받는 외부 PDF 서비스는 사용하지 않는다.

생성 경로는 `public/pdfjs/<version>/`이며 Git에서 제외한다. `dev`,
`build:web`, `build:app` 명령이 준비 스크립트를 자동 실행한다. 앱 정적
산출물에도 같은 파일이 포함되므로 Worker가 WebView와 같은 출처에서 로드된다.

페이지는 화면 주변에서만 캔버스로 렌더링하고 멀어지면 캔버스 버퍼를 비운다.
기기 픽셀 비율은 최대 2로 제한하며 화면 폭 변경에 맞춰 다시 렌더링한다.

## 첫 진입과 실물 하루마디 관심 계측 (개발 브랜치)

- 신규 사용자의 `/entry`는 `함께한 순간들이, 한 권의 추억이 되도록.` 메시지와 실제 A5 하루마디 양식의 본문 예시 한 장만 보여준다. 표지는 펼쳐보기에서 제공한다. 주요 행동은 `우리의 첫 페이지 만들기`다. 기존 추천 이용자도 루트에서는 책장을 보며 추천은 별도 탐색에서 이어간다.
- 본문 예시는 약 3.8초 주기로 12px 떠올랐다 가볍게 한 번 더 튀는 애니메이션으로 조작 가능함을 알린다. `눌러서 펼쳐보기` 표시는 페이지 아래에 분리하며 본문과 겹치지 않는다. 버튼의 클릭 영역은 고정하며 마우스 오버·키보드 포커스 시에는 멈춘다. 동작 줄이기 설정에서는 애니메이션 없이 표시만 유지한다.
- 엔트리는 스크롤 없이 헤더·메시지·중앙 비주얼·하단 버튼을 한 화면에 표시한다. `기록은 어떻게 남기나요?`는 `/entry?mode=guide&step=0`으로 이동하며, 사진·이야기·하루마디를 각각 별도 화면에서 안내한다. 각 안내도 스크롤 없이 표시하고 이전/다음 및 브라우저·안드로이드 뒤로가기를 지원한다.
- `가까운 공간 둘러보기`는 첫 화면과 마지막 안내 화면의 보조 진입으로 유지한다. 설명을 모두 읽거나 질문에 먼저 답해야 기록을 시작할 수 있는 구조는 아니다.
- 첫 기록은 `/madi/new?from=welcome`에서 사진 선택(앨범·카메라·글로 시작) → 짧은 이야기와 날짜·선택 장소 → 하루마디 페이지 모양 미리보기 → 기존 API 저장 → 첫 페이지 완성으로 이어진다. 혼잡도·난이도·테마는 묻지 않고 기존 구조의 `미정`으로 저장한다.
- 첫 기록에는 외출 질문·현재 위치 권한·로그인을 요구하지 않는다. 사진의 GPS는 읽지 않고 촬영일만 선택적으로 사용한다. 기존 일반 기록 편집 화면의 사진 위치 동의·분류 기능은 유지한다. 첫 기록은 서버가 저장 성공을 반환해야 완성 화면으로 전환되며, 실패하면 입력과 미리보기를 유지하고 재시도할 수 있다.
- 첫 기록 완성 후에는 `내 기록 모음 보기`와 `새로운 추억 남기기`를 제공하고 구매를 권하지 않는다. 모음 보기와 루트 진입은 책장으로 연결하고, 개별 기록 목록·일반 기록 편집은 별도 화면으로 유지한다.
- 장소 탐색을 선택한 경우 `/explore`에서 기존 시간·차량 질문과 위치 안내로 이어진다. 이전 `/entry?mode=questions` 링크는 `/explore?mode=questions`로 연결하며, 첫 질문의 뒤로가기는 책장으로 복귀한다.
- 첫 화면의 생성형 포토북 목업과 `하루마디 콘셉트 · 실물 제작 준비 중` 문구는 제거했다. 하루마디 예시는 `WelcomeHarumadiSample` HTML 컴포넌트로 표지·날짜·사진·제목·본문·쪽번호를 배치한다. A5 PDF의 비율·42pt 본문 여백·250pt 사진·66pt 짧은 글 간격·10pt 세미볼드 제목·9pt 본문을 기준으로 크기에 맞게 비례 조정한다. 전체 페이지 스크린샷과 생성 스크립트는 제거했으며 사진만 이미지다. 첫 진입 시 PDF 생성이나 사용자 기록 조회는 없고, 첫 화면과 펼쳐보기에서 같은 컴포넌트를 사용한다.
- 예시의 글은 샘플 데이터이고, 사진은 기존 AI 생성 예시를 사용한다. 실제 사용자 기록이나 판매 중인 실물 상품으로 표시하지 않는다. 사진 생성 프롬프트와 과거 목업 이력은 `assets/welcome-generation.json`에 기록하며, 펼쳐보기에서도 예시 사진임을 알린다.
- 첫 화면과 예시 하루마디에는 구매 버튼을 노출하지 않는다. 하루마디 비주얼을 누르면 `/entry?mode=harumadi&page=1`의 별도 화면으로 이동한다. 눌렀던 본문 페이지의 위치·크기에서 확대되고 제본선을 따라 펼쳐지는 약 760ms 애니메이션을 재생한다. 표지(0)·사진과 글 예시(1)·글만 남긴 예시(2)·마지막 CTA(3)의 총 4페이지다. 추가 예시는 실제 하루마디의 짧은 글 레이아웃을 따른다. 마지막에는 `다음 페이지는, 우리 이야기로.`와 `우리의 첫 페이지 만들기`만 배치한다. 해당 CTA는 첫 기록 화면으로 이동하고 기존 `welcome_record_started`를 집계한다. 작은 세로 화면에서도 스크롤 없이 보이고 낮은 가로 화면은 문구·CTA를 2열로 배치한다. 화면의 뒤로가기·Escape·안드로이드 뒤로가기는 원래 첫 화면/마지막 이용 안내로 돌아가고, 브라우저 뒤로가기도 지원한다. 직접 URL 진입은 위치 정보 없이 펼침 애니메이션을 사용하며 동작 줄이기에서는 즉시 전환한다.
- 이전·다음 쪽 모두 왼쪽 회전축·18도 범위·520ms를 공유하며 프레임과 가속 곡선을 정확히 역재생한다. 다음 쪽은 새 페이지를 아래에 고정하고 현재 페이지가 0도→-18도·불투명도 1→0으로 사라진다(45% 지점 -8도·0.65). 이전 쪽은 현재 페이지를 아래에 유지하고 이전 페이지가 위에서 -18도→0도·불투명도 0→1로 펼쳐진다(55% 지점 -8도·0.65). 배경 페이지가 없어지는 공백을 만들지 않는다. 양쪽 모두 넘기는 중 연속 쪽 이동을 막고 보존 레이어를 접근성 트리·탭·클릭에서 제외한 뒤 종료/취소 시 제거한다. 최초 확대 진입·닫기·동작 줄이기는 별도로 유지한다.
- 하루마디 페이지의 왼쪽 22%·오른쪽 22% 영역도 각각 이전·다음 쪽 이동을 지원한다. 중앙은 넘김 영역이 아니며, 구매 등 본문 내 실제 버튼이 겹치면 해당 버튼이 우선한다. 첫 쪽의 왼쪽과 마지막 쪽의 오른쪽은 비활성화하고, 넘김 애니메이션 중에는 양쪽 영역 모두 비활성화한다. 하단 텍스트 버튼은 그대로 유지하며 영역 버튼도 키보드 포커스·접근성 이름을 제공한다.
- `실물 하루마디 구매하기`는 기존 하루마디의 완성 화면에서만 유지한다. 첫 진입 예시의 구매 클릭은 실제 소장 의향과 구분하기 어려워 제거했으며, 신규 구매 관심 집계는 `surface=completed_harumadi`에서만 발생한다. 인접한 문구로 준비 중임을 알리고, 누르면 준비 중 모달만 열리며 주문·결제·배송정보 입력은 발생하지 않는다. 디지털 하루마디와 PDF 기능은 유지한다.
- `welcome_viewed`, `welcome_record_started`, `welcome_explore_started`, `harumadi_purchase_clicked`를 기존 시스템 로그의 `product` 범주에 저장한다. 추가 DB 마이그레이션은 필요 없다.
- 클릭마다 별도 UUID를 사용하며, 같은 이벤트의 네트워크 재전송은 동일 ID로 멱등 처리한다. 구매 버튼을 다시 누르면 별도 클릭으로 저장한다. 화면 노출은 페이지 실행 중 계정별 중복을 제거한다.
- 전송에 실패한 큐는 최대 100건·7일 동안 로컬에 보관하고 다음 실행·온라인 복귀 시 재전송한다. 계정이 바뀌면 이전 계정의 대기 항목은 전송하지 않는다. 세션 생성 자체가 실패했으면 모달의 `다시 전송`으로 재시도한다. 연결 복구·재실행 전에 앱 삭제/저장소 삭제가 발생한 경우에는 복구할 수 없다.
- 서버에는 계정 식별자·행동·진입 화면·플랫폼·서버 수신시각만 저장한다. 새 계측에 기록 본문·사진·원본 IP·User-Agent는 포함하지 않는다. 180일이 지난 항목은 기존 인증자료 파기 작업에서 삭제한다.
- 관리자 `사업 지표 → 첫 화면과 실물 하루마디 관심`에서 선택 기간의 고유 계정 수와 구매 버튼 클릭 횟수를 확인한다. 과거 예시 하루마디 구매 클릭(`surface=welcome`)은 삭제하거나 완성한 하루마디 클릭으로 재분류하지 않고 별도 이력으로 유지한다. 관리자와 통계 제외 계정은 기존 기준대로 제외한다.
- 구매 버튼 클릭은 관심 신호일 뿐 구매·결제 전환이나 지불의사 확정값이 아니다. 익명 계정 수는 실제 사람 수와 다를 수 있으며, 지연 재전송은 서버 수신일 기준으로 집계된다.
- 이번 변경이 배포된 이후의 새 이벤트만 집계한다. 과거 방문을 새 첫 화면 노출·구매 버튼 선택으로 소급 생성하지 않는다. 원본 목업은 `feat/lifelog-first-entry`, 최신 main 기반 통합 작업은 `feat/lifelog-entry-integration` 브랜치에 있으며 운영 반영 전이다.

### 통합 점검 및 리팩토링

- 2026-10-26 최신 main 통합에서는 약관 캐시·재동의·권리 행사 전용 경로를 유지했다. 첫 기록에도 기존 기록 작성과 같은 민감정보 분류·별도 선택 동의를 연결하며, 정책 조회 실패나 필수 확인 누락 시 저장하지 않는다.
- 관심 계측은 현행 클라이언트 규약과 계정 고정 전송을 사용하고 일반약관 미동의 시 서버에서 차단한다. 기존 관리자 기록 접근 감사의 2년 보관 정리를 제거하지 않고 관심 계측 180일 정리와 병행한다.

- 기록 시작 버튼은 첫 화면·예시 마지막 CTA에서 같은 진입/계측 함수를 사용한다. 하루마디의 좌우 터치와 하단 버튼도 하나의 페이지 경계 규칙을 사용한다.
- 첫 기록의 화면 버튼·안드로이드 뒤로가기는 같은 단계 전환 함수를 사용한다. 사진 촬영일은 자르기 확정 뒤에만 반영하며 취소·재선택·화면 이탈 후에는 오래된 비동기 결과를 무시한다. GPS는 계속 읽지 않는다.
- 관심 계측 큐는 저장·만료·재전송 정책을 별도 모듈로 분리했다. 인증 헤더는 해당 이벤트 소유자의 세션으로 고정하고 401을 다른 계정으로 자동 재전송하지 않는다. 매 전송마다 계정·7일 만료 여부를 재검사하며 복원 시 허용 필드만 남긴다.
- 관리자 관심 지표는 선택한 기간에 필요한 이벤트만 조회하며 제거한 첫 화면 구매 버튼은 과거 수집 이력으로 표시한다. 기존 이력은 삭제하거나 실제 구매로 재해석하지 않는다.
- 전체 자동 테스트 281개와 타입 검사, 브라우저의 텍스트/사진 기록 저장·저장 실패 재시도·사진 선택 취소·예시 넘김·CTA 연결을 확인했다. 운영 배포와 네이티브 실기기 검증은 별도다.
