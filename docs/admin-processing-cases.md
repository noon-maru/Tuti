# 관리자 처리 요청 번호

사용자 기록 조회의 수동 처리 번호 입력을 등록된 처리 요청 선택으로 대체한다.

- 해당 사용자의 조회 화면에서 처리 목적을 고르고 **새 요청 등록·번호 자동 발급**을 누른다.
- 서버는 관리자 인증·출처·대상 사용자·목적을 검증한 뒤 PostgreSQL 시퀀스로 `CASE-000001` 형식의 전역 순번을 발급한다. 날짜별 초기화는 하지 않는다.
- 동시 등록에도 중복되지 않는다. 실패·롤백으로 생긴 결번은 재사용하지 않는다.
- 같은 문의·사고의 후속 조회는 기존 요청을 선택한다. 페이지 이동마다 번호를 새로 만들지 않는다.
- 서버는 번호가 해당 사용자에게 등록되어 있고 목적이 일치하는지 검사한 후에만 기록을 읽는다. 일반 사용자에게 발급·목록·조회 권한은 없다.
- 번호 발급 자체는 마디 원문 조회나 문의 답변·사고 해결을 의미하지 않는다. 외부 문의 시스템과의 자동 연동은 아니다.

처리 요청에는 번호·대상 사용자 ID·등록 관리자 ID·목적·등록 시각만 저장한다. 자유문, 이름, 이메일, 사진을 받지 않는다. 최근 2년 내 요청을 최신 100건까지 선택할 수 있다. 요청은 생성 후 2년 기준으로 기존 인증·감사 정리 작업에서 삭제하고, 대상 계정 삭제 시에도 함께 정리한다. 별도 조회 감사는 기존 2년 보존 규칙을 유지하며 요청 삭제로 지워지지 않는다. 기존 감사의 수동 번호를 소급 변환하거나 허구의 요청을 만들지 않는다.

배포에는 `20261101000000_add_admin_processing_cases` 추가 마이그레이션이 필요하다. 구버전 관리자 화면의 임의 번호는 새 서버에서 거절하므로 배포 후 관리자 화면을 새로고침한다. 시퀀스는 전체·핵심 백업 모두 기본 포함 대상이다.

검증: 처리 요청 API·조회 API 단위 시험, 감사 보존 정리 시험, 격리 PostgreSQL 시퀀스·결번·목적 제약·계정 삭제 연계 시험.
