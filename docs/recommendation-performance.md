# 나들이 추천 성능

현재 알고리즘·조건·캐시 정책은 [2.0 추천 정책](./dog-outing-v2-policy.md),
자료 준비와 환경별 품질 검증은 [추천 검증 기록](./dog-outing-verification.md)이 기준이다.
구 v22/v23의 180곳 선절단·피로도 점수·실측을 현재 엔진 설명에 재사용하지 않는다.

## 현재 응답 경계

- 홈 책장은 추천을 호출하지 않는다. 나들이도 기존 추천을 복원할 때는 새 추천 요청을 만들지 않는다.
- 최초 추천은 공식 자료·공간/목적/시간/동반 조건과 저장된 근거를 사용한다.
  전체 후보의 실시간 길찾기·LLM·날씨 API 응답을 기다리지 않는다.
- 실제 이동시간은 활성 카드, 상세는 사용자가 열 때 조회한다. 실제 경로와 추정 시간을 구분한다.
- 위치 동의 확인과 이용·외부 처리 확인자료는 응답 전에 처리한다. 성능을 이유로 생략·비동기화하지 않는다.
- 분석용 추천 스냅샷과 날씨 보충은 서버 `after()`로 응답 이후 처리한다.
  클라이언트의 별도 무응답 전송으로 넘기지 않으며 사용자 기록 저장 트랜잭션과 혼동하지 않는다.

`Server-Timing`의 `recommendation`은 추천 경로, `snapshot_schedule`은 후속 작업 등록 비용이다.
후자는 실제 DB 저장시간이 아니다. 프로세스 비정상 종료 때 분석 스냅샷이 누락될 수 있으므로
완전한 수집이 필요한 규모에서는 영속 outbox/큐를 별도 설계한다.

새로움 가점은 후보 ID에 제한한 내부 이력 SQL 한 번을 사용한다. SQL 100ms·연결 대기 100ms·
트랜잭션 1초 상한이며 실패하면 가점만 생략한다. 위치·본문·사진을 새로 분석하지 않는다.
세부 사건·만료 기준은 [행동 루프](./recommendation-action-loop.md)를 따른다.

## 운영 관측

2026-11-19 공개 좌표 4지역×3시간 조건의 운영 단독 엔진 검사는 42~2,063ms였다.
최초/후속 캐시가 섞인 12회 점검이며, HTTP 왕복·UI 표시 시간·p50/p95·SLO가 아니다.
추천 준비 9,235곳은 전국 카탈로그 수이지 한 요청의 목적·동반·시간 통과 수가 아니다.
[관측 조건과 결과](./dog-outing-verification.md#운영-적용-관측-2026-11-19)를 함께 읽는다.

## 이후 측정 기준

1. 릴리스·DB 자료 시점·지역·질문·위치 동의·캐시 상태를 고정하고 반복 측정한다.
2. 새 추천 생성, 기기 목록 복원, 활성 카드 이동시간, 출발 준비를 나눠 측정한다.
3. 서버 계산·스냅샷 작업·외부 HTTP 왕복·첫 카드 표시를 다른 구간으로 기록한다.
4. p50·p95와 표본 수를 함께 남기고 실제 결과 수·목적·거리·제한 조건도 확인한다.
5. 성능 개선을 위해 미확인을 허용으로 바꾸거나 부족한 후보를 다른 유형으로 채우지 않는다.
6. 사용자의 좌표·원문·토큰을 측정 로그나 문서에 남기지 않는다.

10월 구 엔진의 변경 전후 실측은 [이전 추천 성능 기록](./archive/recommendation-performance-2026-10.md)에 보존했다.
그때의 코드별 요청 감소율은 현재 엔진의 성능 개선율이 아니다.
