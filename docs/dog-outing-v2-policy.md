# 2.0.0 추천 품질 수정 — 현재 수집 장소 한정

2026-11-17 사용자 결정: 2.0.0은 현재 수집한 장소만 사용한다. 신규 장소 확보·큐레이터 채용은
출시 선행 조건으로 두지 않으며 후속 2.1.0/2.2.0 등에서 확대한다. 이번 작업은 새 API 수집·
장소 등록·운영 배포·앱 버전 변경을 하지 않았다. 개발 DB 조회는 공개 장소만 읽었다.

## 적용 정책 `dog-outing-v2`

반려견 동반(`petCompanion=dog`) 시 시간 선택은 **한두 시간 · 반나절 · 오늘 하루**만 제공한다.
최초 질문과 주간 재질문에서 한 시간 안에 선택은 숨기며, 동반 기본값과 기존 동반 `near` 값은
`short`(왕복·체류 포함 120분)로 보정한다. 서버 추천 엔진도 같은 정책을 적용한다.
비동반·미응답은 기존의 한 시간 안에 기본값과 선택지를 유지한다.

### 현재 추천 목록 유지 (2026-11-17)

- 추천은 날짜·경과 시간·화면 재진입·웹 새로고침·앱 재실행만으로 재생성하지 않는다.
  현재 계정의 목록·순서·보던 장소와 반려견 세부 조건을 기기 Preferences에 보관한다.
- 주간 재질문은 추천 보유 여부와 관계없이 유지한다. 7일 후 조건을 다시 확인하되,
  **이대로 볼게요/질문 생략**은 기존 목록·출발 기준점·반려견 세부 조건을 보존하고 다음 확인일만 연장한다.
  같은 조건으로 제출해도 재추천하지 않으며 실제 조건 변경 또는 별도 재추천 버튼으로만 목록을 갱신한다.
- 변경 사유는 명시적인 외출 조건/추천 지역 변경, 메뉴의 재추천 버튼, 기준점에서의 유의미한 이동이다.
  찜 추가·마디 저장·질문 답변 재사용은 자동 재추천 사유가 아니다.
- 위치 사용자는 메뉴에서 **지금 위치에서 다시 추천**, 위치 미제공/직접 지역 선택 사용자는
  **선택한 지역에서 다시 추천**을 누른다. 후자는 위치 권한이나 기기 위치 조회를 요청하지 않는다.
- 마지막 GPS 위치 자체는 기존처럼 메모리에만 둔다. 다만 재실행 후 이동 비교를 위해 **현재 추천 한 건의
  출발 기준 좌표·수평 오차**를 목록과 함께 기기에 보관한다. 이동 이력을 누적하지 않으며 계정 전환,
  동의 철회·중지·거절·동의 세대 변경, 초기화 시 위치 기반 목록/기준점도 지운다.
  위치 미제공 사용자의 지역 목록은 동의 상태 재조회만으로 지우지 않는다.
- 작은 여행에 진입/복귀할 때와 화면을 보고 있는 동안 5분 간격으로 이미 허용된 위치를 조용히 확인한다.
  새 권한 팝업은 자동으로 띄우지 않으며 백그라운드 위치 추적은 하지 않는다. 위치 조회 실패 시 기존 목록을 유지한다.
- 기준 좌표와 현재 좌표 사이 거리에서 양쪽 수평 오차를 제외해도 1km 이상일 때 이동 후보로 본다.
  수평 오차(`accuracy`)는 기기 내부 판정용이며 추천·출발 계획·경로·이동시간·주변 장소 API에는 위도·경도만 전송한다.
  자동 갱신은 두 번의 새 위치 조회가 모두 기준을 넘고 두 측정점도 500m 이내일 때만 확정한다.
  근거리 이동 때는 기준점을 계속 옮기지 않는다.
- TanStack Query는 `staleTime: Infinity`, 자동 mount/focus/reconnect 재조회 비활성화,
  비활성 메모리 캐시 정리 1시간이다. 메모리 정리 후에도 기기의 현재 목록을 복원하므로 재추천하지 않는다.
  계정 ID·조건·추천 세대·출발 기준점으로 조회를 구분하며 위치·조건이 변경되기 전에 시작한 응답의 재저장을 차단한다.
- 초기 스냅샷 포맷이 없는 과거 추천은 한 번 새로 생성한다. 삭제/철회 통제와 서버의 기능별 권한 확인은 그대로 유지한다.

1. 선택한 카테고리 중 하나에 맞는 장소만 반환한다. 카페가 1곳이면 1곳, 없으면 0곳이다.
   다른 카테고리를 자동 보충하지 않는다. 복수 선택은 합집합이며, 쇼핑을 직접 선택한 경우에만
   개별 매장도 허용한다. 쇼핑 상호를 카페·공원으로 분류하지 않는 원칙은 유지한다.
2. 공간은 `상관없어요 / 실내 / 야외·테라스`의 선택 조건이다. 기본적으로 실내를 요구하지 않는다.
   특정 공간을 고르면 그 구역의 동반 허용이 원문에서 확인되는 장소만 포함한다.
   ‘전구역 동반가능’이라는 등록 분류만으로 공간의 실내·야외 속성을 만들지 않는다.
3. 준비물은 `미정 / 사용 / 미사용`이다. 목적만 선택해도 미준비로 오해하지 않는다.
   여러 원문 필드의 명시적 몸무게 상한(이하·미만·이내), 최대 마릿수, 필수 준비 표현을 대조한다.
   원문에 근거를 남기며 견종·복잡한 조건부/대체 준비물 표현 등 해독하지 못한 제한은 확인 필요다.
   실내 전용 이동장 규칙을 야외 이용자 전체에게 강제하거나 A 또는 B를 A와 B로 바꾸지 않는다.
   전역 동반 불가와 실내만 불가를 구분한다. 시설 정책의 전체 해독이나 입장 보증을 주장하지 않는다.
4. 왕복 이동·최소 체류·여유의 예상 총시간이 시간 예산을 넘는 후보는 선발하지 않는다.
   실제 경로가 없을 때는 기존 교통수단별 거리 추정과 체류 프로필을 사용한다. 확정 소요시간이 아니다.
   발견 단계에서는 밤 검색 시각 때문에 개장까지 대기하는 시간을 예산에 넣지 않는다.
   방문 날짜를 선택한 경우 그 날짜의 알려진 휴무는 차단하고, 익일 날씨와 운영 날짜를 통일한다.
   실제 출발 시각·경로의 도착 후 마감 여부는 기존 출발 준비에서 다시 확인해야 한다.
5. 같은 분류기로 정답을 생성하는 검사 외에 별도로 원문을 검토한 고정 정답을 추가했다.
   `data/dog-quality-benchmarks/2026-11-17.json`의 11개 기존 장소 사례는 쇼핑 상호 오분류·
   카페·숙박 정체성을 대조한다. 이는 초기 평가 자료이며 전국 품질 인증이나 시설 확인 자료는 아니다.
   알려진 적합 후보를 모두 누락하는 빈 결과도 시험에서 실패하도록 검사한다.

감사 집계는 목적·동반·예상 시간 통과 수를 분리한다. 신규 조건은 계정과 함께 Query 키에 들어가며
클라이언트·서버 알고리즘 버전을 갱신했다. DB 스키마·기존 장소 데이터·수동 편집은 변경하지 않았다.
Impeccable의 간결한 선택·빈 결과 복구 기준으로 기존 UI를 확장했으며 새로운 화면 체계는 만들지 않았다.

## 단일 목적 기준 기존 관측 — 복수 선택 도입 전

공개 대표 좌표, 한두 시간·차 없이·8kg·목줄 사용·이동장 미사용·공간 지정 없음 조건:

| 지역 | 산책 | 카페 | 나들이 |
| --- | ---: | ---: | ---: |
| 서울 중심 | 6 | 2 | 6 |
| 경주 불국동 인근 | 2 | 0 | 3 |
| 제주시 중심 | 2 | 1 | 4 |

모두 요청 목적에 맞는 결과만 표시한다. 앞선 버전의 ‘모든 조합에서 6곳’과 달라지는 것이 의도다.
서울 카페 원문 재검토에서 카페우리는 ‘보조견 동반 입장 가능’만 명시돼 일반 반려견 추천에서 제외했다.
서울 표본의 남은 카페도 구역 근거가 없어 실내·야외를 특정하면 0곳이었다. 공간이 실제로 없다는 뜻이 아니라
현재 원문으로 특정 구역의 이용 가능성을 판정할 수 없다는 뜻이다. 장소 유형이나 사진으로 이를 만들어 넣지 않았다.
4지역×3반경 회귀와 별도 3지역×10조건 조합은 통과했으며 최초 추천의 외부 API 요청은 0회다.
엔진 단독 실측은 36~703ms였고 첫 호출·캐시 상태가 섞인 개발 수치다. 앱 전체 지연이나 운영 SLA가 아니다.

## 동반 질문·복수 선택·검색

- 질문 순서는 **반려견 동반 여부 → 외출에 쓸 시간 → 차량 여부**다. 실제 km 질문으로 바꾸지 않는다.
  오늘 하루의 출발 시점 질문은 유지하고, 반려견 동반 시 장소 카테고리를 추가로 선택한다.
- 카테고리: 쇼핑, 카페, 공원·산책, 바다·자연, 문화·전시, 체험·놀이. 여러 개 또는 미선택을 허용한다.
  미선택은 기존 외출 목적지 범위이며, 개별 매장 전체를 자동으로 넣는 뜻은 아니다.
- 동반하지 않는 경우 기존 열람 가능 후보를 동일한 시간·거리·예산 판정으로 평가하되 동반 제한은 적용하지 않는다.
  옛 저부담 점수 엔진으로 돌아가지 않는다. 새 반려동물 종류 지원은 추가하지 않았다.
- 최초 질문과 재질문 바텀시트 모두 같은 순서·복수 선택을 지원한다. 동반 해제 시 이전 카테고리는 제거한다.
  저장된 답변·서버 요청 검증·추천 Query 키에 새 조건을 반영하며, 카테고리 클릭 순서만으로 캐시를 구분하지 않는다.
- 추천 메인에는 세부 외출 조건 패널과 장소별 동반 고지를 상시 표시하지 않는다. 세부 조건은 동반 시 질문의
  마지막 카테고리 단계에서 선택하며, 메뉴의 ‘외출 조건 변경’으로 다시 설정한다. 초안은 질문 완료 시 반영하고
  취소 시 기존 조건을 유지한다. 장소별 동반 구역·제한·출처 안내는 장소 상세에 유지한다.
  질문의 선택 정보는 `ExplorePreferences`의 ‘조금 더 맞추기’ 한 곳으로 통합했다. 반려견 조건·동행·입장료는
  모두 유지하되, 별도 적용 버튼·중복 상태 설명·접기 안의 추가 스크롤은 제거했다. 입력은 초안에 바로 반영하고
  마지막 질문 완료로 한 번만 적용한다. 잘못된 몸무게는 완료를 차단하며, 접은 요약에도 입력 확인을 표시한다.
  등록한 반려견이 있으면 이번 동반견을 직접 골라 몸무게를 불러올 수 있다. 자동 선택하지 않으며,
  선택한 모든 반려견의 몸무게가 있어야 불러온다. 미입력 프로필은 일부 제외하지 않고 직접 입력하도록 안내한다.
  프로필 없이도 입력할 수 있고 프로필 ID·이름은 추천 조건으로 보내지 않는다.
  상세의 동반 구역·대상·준비물은 펼치지 않아도 읽을 수 있게 하고 긴 시설·추가 안내만 접는다.
  수집일·확인일·공식 출처·미기재 경고는 제거하지 않았다. 기존 Pretendard·파랑/연두 조작부를 유지하는 정리다.
  후속 디자인 통합은 관련 34개 시험·타입·린트·문서 링크 검사와 레이아웃 기계 검사를 통과했다.
  UI 시험은 정적 렌더링·입력 핸들러 기준이며 모바일 실기기 시각 검증을 대체하지 않는다.
  사진을 보존한 후속 상세 본문 개편은 [장소 상세 레이아웃](./place-detail-layout.md)에 정리했다.
- 작은 여행 좌측 상단 검색 아이콘은 화면 위 공용 다이얼로그로 펼쳐진다. 카드·본문을 밀지 않고,
  앱 뷰포트 안에서 포커스·Escape·닫기·감속 모션을 지원한다. 닫힌 상태와 빈 입력에서는 검색 요청을 하지 않는다.
- 검색은 **명시적으로 ‘반려견과 함께 가요’를 선택한 경우에만** 반려견 동반 카탈로그의 준비 완료 장소로 제한한다.
  비동반·미응답은 동반 여부와 관계없이 전체 열람 가능 장소를 검색한다. 숨김·수동 제외 등 기존 공개 정책은
  두 범위 모두 유지한다. 동반 검색은 쇼핑 선택 여부와 무관하게 카탈로그 안의 개별 매장도 검색한다.
  추천의 이동 범위·몸무게·준비물 등 개인 조건으로 검색을 제한하지는 않으며, 등록 자체가 세부 조건 적합이나
  입장을 보증하지 않는다는 점은 방문 전 확인 안내로 구분한다. 동반 검색·전체 검색의 안내와 Query 키를 분리해
  답변 변경 시 이전 범위의 검색 결과가 섞이지 않게 한다. 2026-11-17 개발 DB의 동반 검색 대상 관측은 9,237곳이며,
  전체 검색의 장소 수나 운영 적용 수량을 뜻하지는 않는다.
  이름·지역 검색을 250ms 지연하고 이전 질의는 취소한다. 최대 8곳을 반환하며 결과는 같은 작은 여행 안에서
  상세로 열린다. 상세 닫기는 원래 추천으로 돌아가며, 장소를 담은 마디 작성과 현재 하루마디 맥락을 보존한다.
  기존 마디 장소 자동완성의 후보 범위·응답은 유지한다.

개발 DB 서울 중심·한두 시간·차 없이·8kg·목줄 사용·이동장 미사용·공간 미지정 관측:

| 선택 | 반환 | 목적 일치 후보 |
| --- | ---: | ---: |
| 쇼핑 | 6 | 1,734 |
| 카페 | 2 | 2 |
| 공원·산책 | 6 | 12 |
| 쇼핑 + 카페 | 6 | 1,736 |
| 바다·자연 | 4 | 4 |
| 문화·전시 | 0 | 0 |
| 체험·놀이 | 0 | 0 |

복수 선택 결과에 쇼핑·카페가 함께 포함됨을 확인했다. 동반하지 않는 조건은 6곳을 반환하고 동반 허용 주장을
표시하지 않았다. 이 숫자는 해당 좌표·조건의 개발 관측이며 전국 공급량·이용 성공 보증이 아니다.
새 데이터 수집·DB 변경·운영 반영·앱 빌드는 하지 않았다. 시각·동작의 최종 실기기 검증은 별도로 필요하다.

## 남은 출시 검증

동반 질문·복수 선택·검색 반영 후 전체 회귀 1,230개 중 1,228개 통과·2개 건너뜀·실패 0개를 확인했다.
TypeScript·변경 파일 ESLint·문서 링크 검사를 통과했다. 최초/재질문 핸들러, 카테고리 합집합·캐시 키,
검색 범위·빈 입력·전송·오류·기존 자동완성 호환을 검사했다. 검색의 포커스·감속 모션 계약은 코드로 확인했으며,
실제 화면의 배치·터치·키보드·애니메이션이 모두 기기에서 확인됐다는 뜻은 아니다.
승인 약관 문안은 이번에 변경하지 않았다.
현 단계는 개발 브랜치 구현·검증이며 main 통합·운영 배포·스토어 업로드는 하지 않았다.

- 고정 평가 11곳은 편향된 초기 표본이므로 지역·목적·공간·동반 조건을 확장한 독립 검증은 계속 필요하다.
- 특정 구역 미확인, 자유문 조건 미해독, 실제 경로 미확인은 현재 자료의 한계로 표시한다.
- 실제 보호자의 선택 만족·방문 전 확인·시설 이용 성공은 코드 시험만으로 입증되지 않는다.
- iOS/Android 실기기와 서버·앱 통합 검증 및 운영 반영은 이번 개발 시험과 별도다.

따라서 구현과 회귀 통과를 ‘2.0.0 출시 품질 확정’으로 기록하지 않는다. 장소 확장은 하지 않되
현재 자료에서 요청 조건을 어기는 결과가 없는지와, 부족한 경우의 설명·복구를 출시 전에 확인한다.
