# 실물 하루마디 검증 계획

상태: **미구현 상품의 검증 계획**, 2026-11-20 정리.
2.0 고객·브랜드는 [브랜드 정의서](./brand-definition.md)를 따른다.
아래 조건은 후속 검증을 위한 경계이며 새 상품·가격·일정·수집 항목을 승인하는 문서가 아니다.

## 현재와 목표의 경계

현재 제공하는 것은 마디·디지털 하루마디·함께 채우기·서버 PDF 보관과 파일 내보내기다.
`실물로 소장하기`는 준비 중 안내와 관심 이벤트다. 주문·결제·인쇄·배송·매출로 세지 않는다.
실제 기능은 [하루마디](./harumadi.md), 성과 정의는 [관리자 지표](./admin-lifelog-metrics.md)를 따른다.

검증할 가치는 이미 남긴 시간을 적은 수고로 소장할 만한 한 권으로 만드는 것이다.
더 자주 외출하거나 기록하도록 압박하지 않고, 기존 무료 기능을 불편하게 만들어 구매를 유도하지 않는다.
반려묘의 집 안 일상·보호자 자신의 기록도 상품 검증에서 배제하지 않는다.

## 검증 순서

| 단계 | 먼저 확인할 것 | 다음 단계로 넘어가기 전 남길 근거 |
| --- | --- | --- |
| 공급·샘플 | 소량 인쇄 업체 사양·1권 원가·납기·불량/재제작 조건 | 한 가지 규격과 합성/동의받은 자료의 실제 샘플, 품질 확인 |
| 준비 상태 | 현재 사진·글로 인쇄가 가능한지, 어떤 자산이 부족한지 | 규칙 버전, 최소 품질·사진 해상도·쪽 구성 기준 |
| 거래 리허설 | 계정·원본 권한·견적·승인 산출물·결제 귀속·취소/환불 | 중복/실패/복귀를 포함한 격리 E2E와 운영 책임자 확인 |
| 소수 수요 검증 | 실제 목표 고객의 정상가 구매·비구매 이유 | 모집·가격·관찰 기간·판정 기준을 결과 확인 전에 고정 |
| 이행·반복 | 실제 원가·사람 시간·불량·배송 만족·다음 구매 | 주문별 관측 비용과 성숙 코호트, 수동 지원 여부 구분 |

SKU·가격·모집 수·최소 마진·납기·판정선은 확정하지 않았다.
과거의 2~3만 원, 24,900원, 30~50명·20건·50건 등 비교용 숫자를 현행 판매 조건으로 재사용하지 않는다.
개인 상품의 수요·이행이 확인되기 전 기관 포털·구독·다품종 커머스를 선행 개발하지 않는다.

## 인쇄·거래의 최소 보호 조건

- 현재 웹용 사진을 인쇄 원본으로 간주하지 않는다. 희소 기록·긴 글·반복 사진·작은 글자·
  사진 비율과 색상으로 샘플을 확인한다. 필요한 페이지만 원본 재선택을 검토하고 무료 기록 전체의
  원본 보관을 자동 확대하지 않는다.
- 초안·proof·견적을 보여준 뒤 사용자 승인으로 내용·순서·표지/속지·템플릿·자산 버전·규격을 잠근다.
  그 승인본에서 print master를 만들고 preflight와 해시 기록에 성공한 뒤에만 주문·결제를 연다.
- 원본 수정·삭제 이후에도 주문 산출물을 임의 변경하지 않는다. 디지털 삭제, 제작 중 취소,
  거래자료·인쇄 자산 보존은 출시 전에 별도 정책과 코드로 정한다.
- 가격·통화·수량·배송비·견적 만료·주문 상태는 서버를 원본으로 둔다. 결제 callback의
  `success`만으로 결제 완료를 표시하지 않는다. 공급자 검증 또는 승인된 정산 대조가 필요하다.
- 중복 주문·중복 결제·결제 이벤트 재전송·순서 역전·부분 환불을 멱등적으로 처리한다.
  운영자 수동 발주를 하더라도 승인본·주문·실제 납품물 연결과 처리 이력을 남긴다.
- 기록 소유자·편집자·결제자·수령인을 구분한다. 선물·함께 채우기·기관 비용 부담이
  타인의 비공개 원문 열람이나 인쇄 동의가 되지 않는다.
- 배송지·연락처·공급사 전달·거래메일·보관기한·계정 병합/삭제·진행 중 주문 처리를
  실제 판매 방식이 정해진 뒤 별도로 설계한다. 원문·주소·연락처를 분석 이벤트에 복사하지 않는다.
- 실제 결제수단·판매 채널·위탁 관계·취소/환불 고지와 마켓 정책은 상품 출시 전 다시 검토한다.
  현재 확정 약관이나 동의 해시를 이 계획에 맞춰 조용히 덮어쓰지 않는다.

## 성과를 혼합하지 않는 방법

| 축 | 구분 |
| --- | --- |
| 원천 | 제안 전에 Tuti에 축적 / 책을 만들며 가져옴 / 혼합 |
| 나들이 연결 | 실제 추천과 연결된 마디 / 일반 기록. 책 판매만으로 추천 루프가 성립하지 않음 |
| 구매 맥락 | 본인 소장 / 선물, 구매 계기, 개인 / 기관 결제 |
| 가격·지원 | 정상가 / 할인 / 무료 / 기관 지원, 자발적 이용 / 운영자 도움 |
| 사실 | 준비 가능 / 실제 제안 노출 / 관심 / 결제 / 배송 / 재구매 |

가상 페르소나·구매 의향·버튼 선택은 결제 증거가 아니다. 내부·테스트 계정과 수동 대리 작업을 분리한다.
재구매율은 관찰창과 분모가 성숙한 경우에만 계산하며, 분석을 위해 기존 보관기한을 임의 연장하지 않는다.

수익성은 예상과 관측을 구분한다. 실제 정산매출에서 인쇄·포장·배송·결제 수수료·실제 재제작 비용을
뺀 값과, 검수·문의·발주의 사람 시간까지 뺀 값을 각각 본다.
주문별 흑자를 전체 사업의 흑자로 해석하지 않고 무료 제공비·획득비·합의한 고정비도 대조한다.
이미 발생한 재제작 비용과 미래 충당을 중복 차감하지 않는다.

## 중단 조건과 다음 결정

타인의 기록·주소 노출, 승인하지 않은 책 제작, 잘못된 수령인, 중복 결제·금액/통화·주문 귀속 오류는
신규 주문을 멈추고 원인·영향 범위·필요한 통지/환불/재제작을 확인할 사유다.
같은 사고의 회귀 검증과 책임자 확인 전 재개하지 않는다.

먼저 할 일은 공급사 사양·실물 샘플·원가표·준비 상태 정의·검증 기준을 정하는 것이다.
이번 문서 정리는 해당 실험의 실행이나 새 개인정보 처리·운영 DB 집계를 승인하지 않는다.
기관 프로그램·자동 초안의 상세 모델/API·과거 페르소나 전문은 Git 이력으로 보존하고
실제 개발을 결정할 때 새 범위로 설계한다. [이전 사업모델 요약](./archive/business-model-exploration.md)을 참고한다.
