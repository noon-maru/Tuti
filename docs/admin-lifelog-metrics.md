# 라이프로그 관리자 지표

기준: 2026-10-30. 구현 브랜치 `feat/admin-lifelog-metrics`.
운영 배포·실제 환경 파일 수정은 이 개발 작업에 포함하지 않는다.

## 기준

- 관리·분석 제외 계정은 제품 지표에서 제외한다. 운영·권리 감사에서는 숨기지 않는다.
- 날짜는 한국 시간, 범위는 `[start, end)`. 현재 시각 뒤 사건은 제외한다.
- 원본 마디·책·참여자·PDF는 서로 다른 단위다. 자동 첫 책 생성은 수동 생성과 구분한다.
- 반복 기록은 최근 30일 서로 다른 2개 저장일의 새 원본 마디다. 사용자가 입력한 방문일은 사용하지 않는다.
- 첫 마디 전환은 동의 후 관측된 신규 계정의 진입 이후 7일 이내 저장이다. 미성숙 코호트는 집계 중이다.
- 실제 공동작성은 최소 2인의 원본이 담긴 책이다. 초대 발급·수락만으로 성공으로 세지 않는다.
- 서버 PDF 보관·기기 내보내기·실물 구매 관심을 분리한다. 현재 주문·매출 기능은 없다.
- 현재 보유량, 새 계측의 성공 사실, 클라이언트 관측을 구분한다. 삭제 전 과거를 소급 복원하지 않는다.
- 구버전·수집 전·분모 없음은 0%가 아니라 미계측 또는 집계 불가로 표시한다.

## 순서와 완료 조건

1. 구현: 공통 분석 대상·기간·지표 정의와 한국 자정·월말·빈 분모 시험.
2. 구현: 현재 상태 SQL 스냅샷과 관리자 API. 전체 사용자 활동 요약은 100개 페이지와 독립적이다.
3. 구현: 별도 `LifecycleEvent`·같은 트랜잭션의 성공 사건·요청 ID 재시도. 중복 삽입은 DB에서 무시한다.
4. 구현: 홈·작성·책 펼침·초대·구매 노출, 30분 비활성 세션·일별 활동·계정 병합·180일 파기.
5. 구현: 기록·초대·작은 여행의 시간 순서와 7일 창, 첫 저장 이후 W1/W4 재기록·재열람 코호트.
6. 구현: 사업 요약·기록·공동작성·소장 화면. 기존 관광·PDF 사건 의미는 유지한다.
7. 구현: NAS 고정 작업의 정제된 단일 스냅샷을 게시해 조회. 웹은 DB 행만 읽고 작업 실행 권한은 없다.
8. 로컬 회귀·격리 SQL·실제 Prisma 어댑터·타입·린트·문서 검사 후 커밋. 웹·앱 릴리스 빌드는 Actions 전용이다.

계측은 약관·인증 게이트를 우회하지 않는다. 원문·사진·좌표·이메일·초대 토큰을 수집하지 않는다.
제품 사건은 기존 제품 활동과 같은 180일 보관·계정 삭제에 연결한다. 탈퇴 이후에도 개인 사건을
몰래 보존하지 않으며, 잔존 계정 기준의 코호트임을 표시한다.

## 계측 계약

기존 `ProductActivityEvent`의 `main_viewed`와 `harumadi_*`를 새 홈·책 생성 의미로
재사용하지 않는다. 새 사실은 원본 ID·연결 세대·초대 ID·PDF ID의 발생 키로 중복 제거한다.
동일 마디 요청 ID의 보존 기간 내 재전송은 같은 원본을 반환한다. 내용이 달라지거나 원본이
삭제·철회됐으면 재생성하지 않는다. 오래된 요청 재시도를 영구 보장하는 장부는 아니다.

클라이언트 관측은 실제 보임·상호작용에서만 발생한다. 캐시 책 열람은 포함하고 polling·prefetch는
제외한다. 제한된 메모리 큐(최대 100개·30분)는 같은 ID로 재시도하며 계정 전환·삭제 시 비운다.
브라우저 종료·장기 오프라인 관측의 완전한 수집을 보장하지 않는다. 지연 전송 시 관측 시각은
최근 30분과 1분 이내 시계 오차 범위에서 검증하며, 미래는 서버 수신 시각으로 제한한다.
계정 생성 시각·원본 보유량으로 구버전의 누락된 화면 방문을 만들어내지 않는다.

`retainedSince`는 현재 보존 중인 자료의 가장 이른 시각이다. 영구적인 최초 설치일이나
모든 앱 버전의 완전 관측을 뜻하지 않는다. 신규 활성화·첫 저장 코호트는 이 경계 이후 생성된
계정에 한정한다. W1은 첫 저장 후 7~13일, W4는 28~34일이고 코호트 전체가 성숙해야 비율을 낸다.

## 적용 순서

1. 새 웹·ops 이미지 빌드와 추가형 마이그레이션 `20261030020000_lifelog_events`를 함께 배포한다.
2. 기존 API의 저장도 서버 성공 사건을 남긴다. 구버전의 진입면·화면 관측은 누락될 수 있다.
3. 새 앱이 출시돼야 앱의 홈·책 읽기·실패·초안·구매 노출 계측이 들어온다. 현재 앱 버전 번호는 이 작업에서 변경하지 않는다.
4. 새 ops 이미지가 설치된 후 [관리자 관측기 설치](./admin-console.md#예약-작업-관측)를 수행한다. 설치 전에는 확인 불가가 정상이다.
5. 데이터가 쌓이면 코호트가 자동으로 성숙한다. 관측 전 과거를 소급 채우거나 현재 약관 원문·승인 해시를 수정하지 않는다.

2026-10-30 로컬 격리 PostgreSQL 11 시험에서 실제 Prisma 파라미터·동시 중복 발생·트랜잭션 롤백,
1,000개 이상 계정의 전체 요약·목록 독립·커서 중복 방지를 확인했다. 기존 Actions PostgreSQL 17
통합 시험에 같은 시나리오를 연결했다. 이 기록은 운영 배포·수집기 설치·실기기 검증을 대신하지 않는다.

## 개발 검증 기록

2026-10-30 개발 PostgreSQL 17에 추가형 마이그레이션을 적용하고 개발 서버를 재시작했다.
개발 `/admin`과 health는 HTTP 200, 미인증 지표·사용자 활동 API는 HTTP 401,
미인증 관측 요청은 클라이언트 프로토콜 보호에서 HTTP 426으로 차단됨을 확인했다.

- 전체 회귀: 756개 중 754개 통과·2개 건너뜀·실패 0개.
- 로컬 PostgreSQL 11 격리 통합: 24개 중 23개 통과·1개 건너뜀. 건너뛴 기존 함께 채우기 스키마 시험은 PostgreSQL 13 이상 대상이다.
- 실제 Prisma 어댑터에서 파라미터·JSON·수치 반환, 동시 재전송 1건 유지와 롤백을 확인했다.
- 타입 검사, 전체 ESLint, Prisma 스키마 검증, 문서 링크와 확정 약관 무결성 검사를 수행했다.
- 정적 렌더에서 미계측 표시와 현재 보유량·단위 구분을 확인했다. 로그인 후 실제 브라우저·실기기 전체 흐름을 검증한 기록은 아니다.
- 릴리스 빌드는 로컬에서 하지 않았다. 운영 배포·Actions 빌드·앱 업로드와 NAS 상태 관측기 설치는 아직 수행하지 않았다.

현재 예약 작업 패널은 systemd 종료 상태 관측이다. 잠금으로 건너뛴 정상 종료도
포함할 수 있으므로 실제 파기·권리 통지 완료·백업 무결성 증빙을 대신하지 않는다.
