# 라이프로그 관리자 지표

기준: 2026-10-30. 구현 브랜치 `feat/admin-lifelog-metrics`.
운영 배포·실제 환경 파일 수정은 이 개발 작업에 포함하지 않는다.

## 기준

- 관리·분석 제외 계정은 제품 지표에서 제외한다. 운영·권리 감사에서는 숨기지 않는다.
- 날짜는 한국 시간, 범위는 `[start, end)`. 현재 시각 뒤 사건은 제외한다.
- 원본 마디·책·참여자·PDF는 서로 다른 단위다. 자동 첫 책 생성은 수동 생성과 구분한다.
- 반복 기록은 최근 30일 서로 다른 2개 저장일의 새 원본 마디다. 사용자가 입력한 방문일은 사용하지 않는다.
- 첫 마디 전환은 동의 후 관측된 신규 계정의 진입 이후 7일 이내 저장이다. 미성숙 코호트는 집계 중이다.
- 실제 공동작성은 최소 2인의 원본이 담긴 책이다. 초대 발급·수락만으로 성공으로 세지 않는다.
- 서버 PDF 보관·기기 내보내기·실물 구매 관심을 분리한다. 현재 주문·매출 기능은 없다.
- 현재 보유량, 새 계측의 성공 사실, 클라이언트 관측을 구분한다. 삭제 전 과거를 소급 복원하지 않는다.
- 구버전·수집 전·분모 없음은 0%가 아니라 미계측 또는 집계 불가로 표시한다.

## 순서와 완료 조건

1. 공통 분석 대상·기간·지표 정의와 경계 시험.
2. 현재 상태 전용 SQL 집계와 관리자 API. 목록 표본을 전체 통계로 사용하지 않는다.
3. 추가형 lifecycle 이벤트·서버 저장 원자성·재시도 중복 방지.
4. 홈·작성·책 펼침·초대·구매 노출, 세션·일별 활동·계정 병합·파기.
5. 기록·초대·작은 여행의 병렬 경로와 성숙한 주차별 코호트.
6. 사업 요약·기록·공동작성·소장 화면. 기존 관광·PDF 사건 의미는 유지한다.
7. NAS 제한 수집기의 예약 작업 상태를 읽기 전용으로 표시한다. 웹에 Docker·sudo·원문 로그 권한을 주지 않는다.
8. 회귀·타입·린트·문서 검사와 Actions 빌드 준비. 단계별 커밋.

계측은 약관·인증 게이트를 우회하지 않는다. 원문·사진·좌표·이메일·초대 토큰을 수집하지 않는다.
제품 사건은 기존 제품 활동과 같은 180일 보관·계정 삭제에 연결한다. 탈퇴 이후에도 개인 사건을
몰래 보존하지 않으며, 잔존 계정 기준의 코호트임을 표시한다.
