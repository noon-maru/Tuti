# LLM 개인화 운영 원칙

> 현재 상태: 장소 의미 프로필 생성만 허용한다. 사용자 행동·기록을 이용한
> 개인화와 기록 본문 분석은 구현·활성화된 기능이 아니다. 아래 사용자 개인화
> 원칙은 향후 기능을 설계할 때의 기준이며, 이 문서만으로 수집이나 분석을
> 시작하지 않는다.

## 역할

Tuti의 LLM은 사용자와 대화하는 챗봇이나 추천 결정을 대신하는 엔진이 아니다.
현재 출시 구성에서는 공개된 관광지 원천정보로 장소의 성격만 낮은 빈도로
구조화한다. 이용자의 질문 답변, 행동 이력, 기록과 위치는 외부 AI로 전송하지
않는다.

추천 API 요청 중에는 LLM을 호출하지 않는다. 오늘 사용자가 명시적으로 고른
시간 범위·이동수단·출발일 등 현재 질문의 답변은 과거의 추정 취향보다 항상
우선한다. 거리 제한, 운영 여부, 이동시간, 체류시간, 추천풀 검수 같은 사실
판단과 최종 추천 순위는 코드와 원천 데이터가 담당한다. LLM이 없어도 추천은
정상적으로 동작해야 한다.

## 개인화 신호의 역할 분리

1. **명시적 선택:** 현재 질문 답변과 사용자가 직접 바꾼 설정을 최우선으로
   적용한다. 과거 기록이나 추정 취향으로 덮어쓰지 않는다.
2. **구조화된 행동:** 저장, 장소 선택, 길찾기, 기록 생성 등 이미 정의된
   이벤트는 LLM에 보내지 않는다. 향후 충분한 동의와 기능이 마련되면 반복성,
   최근성, 신호 강도를 결정론적 규칙으로 집계한다. 한 번의 행동을 장기 취향으로
   단정하지 않고, 추천 노출 자체를 선호의 증거로 취급하지 않는다.
3. **자유문장:** 기록 제목·본문처럼 정형화되지 않은 글의 공간 관련 표현을
   이해할 필요가 있을 때만, 별도 동의하에 LLM 또는 검증된 로컬 모델을
   보조적으로 검토한다. 모델은 글에 명시된 선호·비선호·판단 불가와 근거를
   추출할 뿐, 사용자 프로필이나 최종 추천 결과를 직접 결정하지 않는다.

자유문장의 추출 결과는 여러 기록과 명시적 행동을 코드에서 합산한다. 부정문,
일시적 상황, 동행인의 취향과 사용자의 취향을 혼동하지 않도록 하며, 근거가
부족하거나 서로 충돌하면 `판단 불가`로 남긴다. 단일 기록만으로 장기 취향을
확정하지 않는다. 성격, 건강·심리 상태, 민감한 특성은 추론하거나 저장하지
않는다.

## 프로필과 현재 구현

- `place_meaning_profiles`: 관광지 상세·소개정보를 quietness, openness,
  walkability, sensoryIntensity, soloFriendliness, decisionBurden,
  stayBurden, novelty의 0~1 값으로 구조화한다. 원천 지문이 바뀐 장소만 다시
  생성한다.
- `user_signal_profiles`: 향후 명시적 동의·철회·기존 데이터 삭제 기능을 갖춘
  뒤에만 다시 검토할 보류 기능이다. 현재 데이터는 배포 마이그레이션에서
  삭제하며 `TUTI_USER_AI_PROFILING_ENABLED=false`로 생성을 차단한다.
  현재 구현된 생성기는 집계된 행동을 LLM으로 해석하지만 실행이 비활성화되어
  있다. 향후 행동 프로필은 규칙 기반으로 전환하고, 자유문장 추출 기능은
  별도 설계·검증한다. 기존 생성기를 그대로 켜서 운영하지 않는다.

프로필에는 생성 방식·규칙 또는 모델 버전, 생성시각, 신뢰도와 원천 커서를
저장한다. 추출 모델이 실패하거나 없어도 기존 추천은 그대로 동작한다.

## 자유문장 분석 도입 조건

- 기록을 남기는 행위와 AI 취향 분석 동의는 분리한다. 목적, 처리 대상,
  외부 API 전송 여부를 알리고 사용자가 명시적으로 선택할 수 있게 한다.
  미동의 기록, 기존 기록의 일괄 소급 분석, 위치 좌표와 식별정보 전송은
  기본적으로 허용하지 않는다.
- 동의 철회 시 후속 분석을 멈추고, 분석으로 생성된 신호·프로필을 삭제하거나
  재계산할 수 있어야 한다. 계정 삭제와 계정 병합에서도 원천 기록과 파생
  신호의 소유권·삭제 범위를 일치시킨다.
- 외부 API와 로컬 모델은 동일한 한국어 평가셋으로 비교한다. 먼저 작은 모델의
  짧은 구조화 추출을 시험하고, 부정·반어·복합 감정·제3자 언급·근거 없음에서
  오판율과 판단 보류율을 측정한다. 큰 모델은 작은 모델이 품질 기준을 통과하지
  못할 때만 검토한다. 로컬 모델은 별도 자원에서 검증하며 운영 NAS의 추천
  응답성과 안정성을 희생하지 않는다.
- 모델 출력에는 제한된 공간 취향 범주, 방향, 신뢰도, 입력 내 근거만 허용한다.
  원문을 응답·운영 로그에 복제하지 않으며, 저장되는 근거도 필요한 최소 범위로
  제한한다. 코드에서 스키마와 근거를 검증하고 신뢰도가 낮으면 적용하지 않는다.
- 적용 전에는 동의·철회·삭제 동작, 모델 품질, 추천 다양성, 실제 길찾기·기록
  전환을 검증한다. 작은 모델의 비용이나 로컬 실행 가능성만으로 도입을 결정하지
  않는다.

## 적용 단계

`TUTI_PERSONALIZATION_MODE`로 적용 범위를 제어한다.

- `off`: 프로필을 조회하지 않는다.
- `shadow`: 별도 검증 환경에서 기존 결과를 그대로 반환하고 가상의 개인화 순위만
  `recommendation_runs.personalization`에 기록한다.
- `active`: 충분한 비교 검증 후에만 사용한다. 이미 통과한 후보의 원래 순위를
  기준으로 최대 약 두 칸의 동점권 보정만 허용한다.

출시 기본값은 `off`다. shadow 비교에서는 추천 결과 다양성, 길찾기 전환,
기록 전환과 특정 장소의 과노출을 함께 확인한다. 현재 프로필 신뢰도가
0.35 미만이면 순위를 계산하지 않는다. 사용자 개인화 활성화는 별도 구현,
동의 및 검증을 마친 뒤에만 검토한다.

## 배치 실행

운영 명령을 다시 설치한 뒤 아래 명령을 스케줄러에서 실행한다.

```sh
sudo sh scripts/ops/install-tuti-operations.sh
sudo -n /usr/local/sbin/tuti-llm-profile-refresh
```

기본 실행은 개발·운영 DB에서 변경된 장소 100곳만 처리한다.
`TUTI_LLM_PLACE_LIMIT`로 한도를 조절할 수 있다. 장소 상세정보 보강 작업 뒤
매일 한 차례 실행하는 구성이 적당하다. 사용자 프로필 명령은
`TUTI_USER_AI_PROFILING_ENABLED=true`가 아니면 실행을 거부한다.

## 계정 병합과 삭제

익명 상태에서 기존 계정에 로그인할 때 사용자가 `병합`을 명시한 경우에만
추천 실행과 행동 신호를 계정으로 옮긴다. `기존 계정 사용`을 고르면 익명
신호는 익명 사용자 삭제와 함께 제거된다. 현재 출시 구성에서는 사용자 AI
프로필을 생성하거나 추천에 적용하지 않는다.
