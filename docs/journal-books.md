# 기록집 제작과 계정 보관

현재 구현 범위는 진입, 기록 선택, 표지·편지 입력, 서버 PDF 생성·미리보기,
완성본의 계정 보관과 PDF 저장·공유, 현재 기기의 초안 복원이다. 디지털 기록집은
무료이며 결제·실물 제작·공개 링크는 제공하지 않는다.

## 사용자 흐름

`지나간 공간 → 기록집 만들기 → 기록 고르기 → 표지와 글 → 미리보기 → 완성`

- 남긴 기록, 만들던 초안 또는 완성한 기록집이 있으면 `지나간 공간`에서 진입한다.
  성별·동행 조건은 사용하지 않는다.
- 초안이 있으면 버튼이 `만들던 기록집`으로 바뀐다. 기록이 모두 삭제되어도 초안에 접근해 정리할 수 있다.
- `/journal/book`은 기존 기록 스택의 제스처와 분리된 스크롤 화면이다.
- 1~12개 기록을 선택하며 기본 순서는 날짜순이다. 날짜 필터를 바꾸어도 선택은 유지한다.
- 제목은 최대 80자, 선택적인 첫 장 글은 최대 1,200자다.
- 표지는 선택한 기록의 사진 또는 글만 있는 표지 중에서 고른다.
- 사진은 전체가 보이게 배치한다. 긴 본문은 페이지를 추가해 이어 쓰며 원본 기록을 수정하지 않는다.
- 생성 PDF에는 쪽 번호를 넣지 않고, 화면 미리보기에서만 각 페이지 아래에 작은
  숫자로 순서를 표시한다.
- 미리보기에는 표지·편지·본문 전체와 페이지 수를 표시한다. 각 페이지의 글을 별도로 읽을 수 있다.
- `기록집 완성하기`를 누르면 서버에서 PDF를 다시 검증·생성해 계정에 보관한다.
- 완성한 기록집은 같은 계정으로 로그인한 웹·iOS·Android에서 다시 열 수 있다.
- 웹에서는 PDF를 내려받고 앱에서는 운영체제 저장·공유 화면으로 전달한다.
- 완성한 기록집은 사용자가 직접 삭제할 수 있으며 원본 기록을 지워도 완성 PDF는 유지된다.
- 없는 기록을 초안에서 발견하면 알리고, 해당 기록을 제외하는 동작을 제공한다.
- 자동 저장 실패와 PDF 생성 실패에는 재시도 동작을 제공한다.

## 초안 저장

Capacitor Preferences에 사용자 ID별로 한 개의 초안을 저장한다. 웹에서는
동일 플러그인의 브라우저 저장소를 사용한다. 저장 키는
`tuti-journal-book-v1:<userId>`다.

초안에는 선택한 기록 ID, 표지 기록 ID, 제목, 편지, 날짜 필터, 현재 단계만
포함한다. 원본 기록의 본문·사진과 생성 PDF는 로컬 초안에 복사하지 않는다.
연속 입력의 저장 순서가 바뀌지 않도록 사용자별 쓰기를 직렬화한다.

같은 기기·같은 사용자로 다시 열면 이어 만들 수 있다. 초안은 기기 간 동기화하지
않지만, 완성한 기록집은 서버에 보관되어 같은 계정의 모든 기기에서 볼 수 있다.
익명 사용자에서 다른 계정으로의 초안 이전과 여러 초안 관리는 현재 범위에 없다.
앱 데이터 삭제·재설치·브라우저 저장소 삭제 시 초안이 사라질 수 있다.
계정 삭제 흐름에서는 해당 기기의 초안도 삭제한다.

## PDF 요청과 데이터 접근

`POST /api/journal-books/preview`는 기존 Bearer 세션과 CORS 규칙을 사용한다.
본문은 선택한 기록 ID, 제목, 편지, 표지 기록 ID로 제한하며 사용자 ID나
원본 본문·사진 URL을 신뢰하지 않는다.

서버는 인증한 사용자 소유 기록만 DB에서 조회한다. 요청한 모든 기록이
조회되지 않으면 404를 반환하고 PDF를 만들지 않는다. 이미지도 조회한 기록의
내부 저장소 키로만 읽는다. 요청자가 지정한 URL을 서버에서 가져오지 않는다.
기록집 화면의 조회 캐시도 사용자 ID별로 분리한다.

- 요청 본문 최대 16 KiB, 기록 최대 12개, 원본 텍스트 합계 최대 60,000자
- 이미지당 최대 5 MiB, 디코딩 최대 16,000,000픽셀
- sharp로 방향·크기를 정리하고 JPEG로 변환
- 기존 API 제한에 미리보기 분당 6회 정책 추가
- 서버 프로세스당 PDF 생성 1건, 작업 중 새 요청에는 429 반환
- 생성 실패 후 처리 슬롯을 반환해 재시도 가능
- 응답은 `application/pdf`, `Cache-Control: private, no-store`

미리보기 PDF는 저장하지 않는다. 사용자가 완성을 요청하면 서버가 소유권을 다시
검증해 PDF를 생성하고 `journal-books/<ownerId>/<bookId>.pdf`에 비공개로 보관한다.
DB에는 소유자, 제목, 선택 기록 ID, 페이지 수와 저장 키만 둔다. 파일 조회·삭제
API는 인증된 소유자에게만 허용한다. 계정 병합 시 완성본 소유권도 함께 이동하며,
계정 삭제 시 저장 PDF도 함께 삭제한다.

## 폰트와 PDF.js

[PDF 폰트 설정](pdf-fonts.md)의 Pretendard를 서버에서 등록한다. 지원하지
않는 글리프는 PDF에서 `□`로 대체하며 미리보기 화면에 안내한다. 원본 글은
변경하지 않는다. 컬러 이모지를 충실히 표시하려면 별도의 후속 작업이 필요하다.

PDF.js는 미리보기에서 동적으로 로드한다. Worker·표준 폰트·WASM 파일은
`pnpm pdf:assets`로 설치된 `pdfjs-dist` 버전에서 복사한다. 외부 CDN이나
사용자 기록을 받는 외부 PDF 서비스는 사용하지 않는다.

생성 경로는 `public/pdfjs/<version>/`이며 Git에서 제외한다. `dev`,
`build:web`, `build:app` 명령이 준비 스크립트를 자동 실행한다. 앱 정적
산출물에도 같은 파일이 포함되므로 Worker가 WebView와 같은 출처에서 로드된다.

페이지는 화면 주변에서만 캔버스로 렌더링하고 멀어지면 캔버스 버퍼를 비운다.
기기 픽셀 비율은 최대 2로 제한하며 화면 폭 변경에 맞춰 다시 렌더링한다.

## 검증

- `test/journal-book.test.ts`: 입력 제한, 다른 사용자의 기록 거부, 비공개 응답,
  작업 중복 제한·실패 복구, 초안 저장 순서·사용자 분리·재진입·삭제,
  긴 한글·사진 유무·편지·글리프 대체를 포함한 실제 PDF 생성·텍스트 추출
- `pnpm test`: 기존 동작 회귀 검사
- `pnpm build:web`, `pnpm build:app`: 웹 서버 및 Capacitor 정적 산출물 검사
- 브라우저 검증에는 합성 기록·PDF만 사용한다. 운영 고객 기록은 조회하지 않는다.
- 개발 환경에서 임시 계정으로 완성본 생성, 목록 재조회, PDF 파일 조회, 기록집
  삭제와 계정 삭제까지 실제 API·DB·오브젝트 스토리지 통합 흐름을 확인했다.
- Chromium에서 진입·기록 선택·사진 표지·제목과 편지 편집·새로고침 복원·
  실제 PDF 렌더링·재진입·삭제된 기록 처리와 320px/768px 화면 폭을 확인했다.

실기기에서는 키보드가 열린 상태의 입력·뒤로가기, 앱 강제 종료 후 초안 복원,
iOS·Android WebView의 Worker·캔버스 표시를 추가 확인해야 한다.
