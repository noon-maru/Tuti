# 기록집 제작과 계정 보관

현재 구현 범위는 진입, 기록 선택, 표지·첫 장 글 입력, 서버 PDF 생성·미리보기,
완성본의 계정 보관과 PDF 저장·공유, 현재 기기의 초안 복원이다. 디지털 기록집은
무료이며 결제·실물 제작·공개 링크는 제공하지 않는다.

실물 기록집 단건 판매는 이 무료 기반 위에서 가장 먼저 검증할 BM 가설이다.
기관 연계 프로그램은 개인 상품 검증 뒤의 후순위 기회다. 제품 방향은
[제품 방향과 우선 고객 가설](product-direction.md), 구현·검증 순서는
[기록집 BM 적용·검증 계획](journal-book-bm-validation-plan.md)을 따른다.

## 사용자 흐름

`지나간 공간 → 기록집 만들기 → 기록 고르기 → 표지 → 이 공간에 남기는 말(선택) → 미리보기 → 완성`

- 남긴 기록, 만들던 초안 또는 완성한 기록집이 있으면 `지나간 공간`에서 진입한다.
  성별·동행 조건은 사용하지 않는다.
- 초안이 있으면 버튼이 `만들던 기록집`으로 바뀐다. 기록이 모두 삭제되어도 초안에 접근해 정리할 수 있다.
- `/journal/book`은 기존 기록 스택의 제스처와 분리된 스크롤 화면이다.
- 1~12개 기록을 선택하며 기본 순서는 날짜순이다. 날짜 필터를 바꾸어도 선택은 유지한다.
- 제목은 최대 80자, 선택적인 첫 장 글은 최대 1,200자다. 글을 비워두면
  첫 장 글 페이지는 PDF에 넣지 않는다.
- 표지는 흰색·연녹색 배경을 먼저 고르고, 사진 포함 여부를 다음에 고른다.
  사진이 없는 기록은 선택한 배경에 맞는 색 면으로 대신한다.
- 사진은 전체가 보이게 배치한다. 긴 본문은 페이지를 추가해 이어 쓰며 원본 기록을 수정하지 않는다.
- 생성 PDF에는 쪽 번호를 넣지 않고, 화면 미리보기에서만 각 페이지 아래에 작은
  숫자로 순서를 표시한다.
- 미리보기에는 표지·편지·본문 전체와 페이지 수를 표시한다. 각 페이지의 글을 별도로 읽을 수 있다.
- `기록집 완성하기`를 누르면 서버에서 PDF를 다시 검증·생성해 계정에 보관한다.
- 완성한 기록집은 같은 계정으로 로그인한 웹·iOS·Android에서 다시 열 수 있다.
- 웹에서는 PDF를 내려받고 앱에서는 운영체제 저장·공유 화면으로 전달한다.
- 완성한 기록집은 사용자가 직접 삭제할 수 있으며 원본 기록을 지워도 완성 PDF는 유지된다.
- 없는 기록을 초안에서 발견하면 알리고, 해당 기록을 제외하는 동작을 제공한다.
- 자동 저장 실패와 PDF 생성 실패에는 재시도 동작을 제공한다.

## 초안 저장

Capacitor Preferences에 사용자 ID별로 한 개의 초안을 저장한다. 웹에서는
동일 플러그인의 브라우저 저장소를 사용한다. 저장 키는
`tuti-journal-book-v1:<userId>`다.

초안에는 선택한 기록 ID, 표지 기록 ID, 제목, 편지, 날짜 필터, 현재 단계만
포함한다. 원본 기록의 본문·사진과 생성 PDF는 로컬 초안에 복사하지 않는다.
연속 입력의 저장 순서가 바뀌지 않도록 사용자별 쓰기를 직렬화한다.

같은 기기·같은 사용자로 다시 열면 이어 만들 수 있다. 초안은 기기 간 동기화하지
않지만, 완성한 기록집은 서버에 보관되어 같은 계정의 모든 기기에서 볼 수 있다.
익명 사용자에서 다른 계정으로의 초안 이전과 여러 초안 관리는 현재 범위에 없다.
앱 데이터 삭제·재설치·브라우저 저장소 삭제 시 초안이 사라질 수 있다.
계정 삭제 흐름에서는 해당 기기의 초안도 삭제한다.

## PDF 요청과 데이터 접근

`POST /api/journal-books/preview`는 기존 Bearer 세션과 CORS 규칙을 사용한다.
본문은 선택한 기록 ID, 제목, 첫 장 글, 표지 스타일·기록 ID로 제한하며 사용자 ID나
원본 본문·사진 URL을 신뢰하지 않는다.

서버는 인증한 사용자 소유 기록만 DB에서 조회한다. 요청한 모든 기록이
조회되지 않으면 404를 반환하고 PDF를 만들지 않는다. 이미지도 조회한 기록의
내부 저장소 키로만 읽는다. 요청자가 지정한 URL을 서버에서 가져오지 않는다.
기록집 화면의 조회 캐시도 사용자 ID별로 분리한다.

- 요청 본문 최대 16 KiB, 기록 최대 12개, 원본 텍스트 합계 최대 60,000자
- 이미지당 최대 5 MiB, 디코딩 최대 16,000,000픽셀
- sharp로 방향·크기를 정리하고 JPEG로 변환
- 기존 API 제한에 미리보기 분당 6회 정책 추가
- 서버 프로세스당 PDF 생성 1건, 작업 중 새 요청에는 429 반환
- 생성 실패 후 처리 슬롯을 반환해 재시도 가능
- 응답은 `application/pdf`, `Cache-Control: private, no-store`

미리보기 PDF는 저장하지 않는다. 사용자가 완성을 요청하면 서버가 소유권을 다시
검증해 PDF를 생성하고 `journal-books/<ownerId>/<bookId>.pdf`에 비공개로 보관한다.
DB에는 소유자, 제목, 선택 기록 ID, 페이지 수와 저장 키만 둔다. 파일 조회·삭제
API는 인증된 소유자에게만 허용한다. 계정 병합 시 완성본 소유권도 함께 이동하며,
계정 삭제 시 저장 PDF도 함께 삭제한다.

## 폰트와 PDF.js

[PDF 폰트 설정](pdf-fonts.md)의 Pretendard를 서버에서 등록한다. 지원하지
않는 글리프는 PDF에서 `□`로 대체하며 미리보기 화면에 안내한다. 원본 글은
변경하지 않는다. 컬러 이모지를 충실히 표시하려면 별도의 후속 작업이 필요하다.

PDF.js는 미리보기에서 동적으로 로드한다. Worker·표준 폰트·WASM 파일은
`pnpm pdf:assets`로 설치된 `pdfjs-dist` 버전에서 복사한다. 외부 CDN이나
사용자 기록을 받는 외부 PDF 서비스는 사용하지 않는다.

생성 경로는 `public/pdfjs/<version>/`이며 Git에서 제외한다. `dev`,
`build:web`, `build:app` 명령이 준비 스크립트를 자동 실행한다. 앱 정적
산출물에도 같은 파일이 포함되므로 Worker가 WebView와 같은 출처에서 로드된다.

페이지는 화면 주변에서만 캔버스로 렌더링하고 멀어지면 캔버스 버퍼를 비운다.
기기 픽셀 비율은 최대 2로 제한하며 화면 폭 변경에 맞춰 다시 렌더링한다.

## 검증

- `test/journal-book.test.ts`: 입력 제한, 다른 사용자의 기록 거부, 비공개 응답,
  작업 중복 제한·실패 복구, 초안 저장 순서·사용자 분리·재진입·삭제,
  긴 한글·사진 유무·편지·글리프 대체를 포함한 실제 PDF 생성·텍스트 추출
- `pnpm test`: 기존 동작 회귀 검사
- `pnpm build:web`, `pnpm build:app`: 웹 서버 및 Capacitor 정적 산출물 검사
- 브라우저 검증에는 합성 기록·PDF만 사용한다. 운영 고객 기록은 조회하지 않는다.
- 개발 환경에서 임시 계정으로 완성본 생성, 목록 재조회, PDF 파일 조회, 기록집
  삭제와 계정 삭제까지 실제 API·DB·오브젝트 스토리지 통합 흐름을 확인했다.
- Chromium에서 진입·기록 선택·사진 표지·제목과 편지 편집·새로고침 복원·
  실제 PDF 렌더링·재진입·삭제된 기록 처리와 320px/768px 화면 폭을 확인했다.

실기기에서는 키보드가 열린 상태의 입력·뒤로가기, 앱 강제 종료 후 초안 복원,
iOS·Android WebView의 Worker·캔버스 표시를 추가 확인해야 한다.

## 첫 진입과 실물 기록집 관심 계측 (개발 브랜치)

- 신규 사용자의 `/entry`는 `함께한 순간들이, 한 권의 추억이 되도록.` 메시지와 실제 A5 기록집 양식의 본문 예시 한 장만 보여준다. 표지는 펼쳐보기에서 제공한다. 주요 행동은 `우리의 첫 페이지 만들기`다. 기존 추천 이용자는 기존 메인 진입을 유지한다.
- 본문 예시는 약 3.8초 주기로 12px 떠올랐다 가볍게 한 번 더 튀는 애니메이션으로 조작 가능함을 알린다. `눌러서 펼쳐보기` 표시는 페이지 아래에 분리하며 본문과 겹치지 않는다. 버튼의 클릭 영역은 고정하며 마우스 오버·키보드 포커스 시에는 멈춘다. 동작 줄이기 설정에서는 애니메이션 없이 표시만 유지한다.
- 엔트리는 스크롤 없이 헤더·메시지·중앙 비주얼·하단 버튼을 한 화면에 표시한다. `기록은 어떻게 남기나요?`는 `/entry?mode=guide&step=0`으로 이동하며, 사진·이야기·기록집을 각각 별도 화면에서 안내한다. 각 안내도 스크롤 없이 표시하고 이전/다음 및 브라우저·안드로이드 뒤로가기를 지원한다.
- `가까운 공간 둘러보기`는 첫 화면과 마지막 안내 화면의 보조 진입으로 유지한다. 설명을 모두 읽거나 질문에 먼저 답해야 기록을 시작할 수 있는 구조는 아니다.
- 첫 기록은 `/journal/new?from=welcome`에서 사진 선택(앨범·카메라·글로 시작) → 짧은 이야기와 날짜·선택 장소 → 기록집 페이지 모양 미리보기 → 기존 API 저장 → 첫 페이지 완성으로 이어진다. 혼잡도·난이도·테마는 묻지 않고 기존 구조의 `미정`으로 저장한다.
- 첫 기록에는 외출 질문·현재 위치 권한·로그인을 요구하지 않는다. 사진의 GPS는 읽지 않고 촬영일만 선택적으로 사용한다. 기존 일반 기록 편집 화면의 사진 위치 동의·분류 기능은 유지한다. 첫 기록은 서버가 저장 성공을 반환해야 완성 화면으로 전환되며, 실패하면 입력과 미리보기를 유지하고 재시도할 수 있다.
- 완성 후에는 `내 기록 모음 보기`와 `새로운 추억 남기기`를 제공하고 구매를 권하지 않는다. 추천 질문을 완료하지 않았어도 저장한 기록이 있는 기기의 루트 진입은 기록 모음으로 연결한다. 기존 추천 이용자의 루트 진입과 일반 기록 편집 화면은 유지한다.
- 장소 탐색을 선택한 경우에만 `/entry?mode=questions`에서 기존 시간·차량 질문과 위치 안내로 이어진다. 첫 질문의 뒤로가기는 신규 첫 화면으로 복귀한다.
- 첫 화면의 생성형 포토북 목업과 `기록집 콘셉트 · 실물 제작 준비 중` 문구는 제거했다. 기록집 예시는 `WelcomeBookSample` HTML 컴포넌트로 표지·날짜·사진·제목·본문·쪽번호를 배치한다. A5 PDF의 비율·42pt 본문 여백·250pt 사진·66pt 짧은 글 간격·10pt 세미볼드 제목·9pt 본문을 기준으로 크기에 맞게 비례 조정한다. 전체 페이지 스크린샷과 생성 스크립트는 제거했으며 사진만 이미지다. 첫 진입 시 PDF 생성이나 사용자 기록 조회는 없고, 첫 화면과 펼쳐보기에서 같은 컴포넌트를 사용한다.
- 예시의 글은 샘플 데이터이고, 사진은 기존 AI 생성 예시를 사용한다. 실제 사용자 기록이나 판매 중인 실물 상품으로 표시하지 않는다. 사진 생성 프롬프트와 과거 목업 이력은 `assets/welcome-generation.json`에 기록하며, 펼쳐보기에서도 예시 사진임을 알린다.
- 첫 화면과 예시 기록집에는 구매 버튼을 노출하지 않는다. 기록집 비주얼을 누르면 `/entry?mode=book&page=1`의 별도 화면으로 이동한다. 눌렀던 본문 페이지의 위치·크기에서 확대되고 제본선을 따라 펼쳐지는 약 760ms 애니메이션을 재생한다. 표지(0)·사진과 글 예시(1)·글만 남긴 예시(2)·마지막 CTA(3)의 총 4페이지다. 추가 예시는 실제 기록집의 짧은 글 레이아웃을 따른다. 마지막에는 `다음 페이지는, 우리 이야기로.`와 `우리의 첫 페이지 만들기`만 배치한다. 해당 CTA는 첫 기록 화면으로 이동하고 기존 `welcome_record_started`를 집계한다. 작은 세로 화면에서도 스크롤 없이 보이고 낮은 가로 화면은 문구·CTA를 2열로 배치한다. 화면의 뒤로가기·Escape·안드로이드 뒤로가기는 원래 첫 화면/마지막 이용 안내로 돌아가고, 브라우저 뒤로가기도 지원한다. 직접 URL 진입은 위치 정보 없이 펼침 애니메이션을 사용하며 동작 줄이기에서는 즉시 전환한다.
- 이전·다음 쪽 모두 왼쪽 회전축·18도 범위·520ms를 공유하며 프레임과 가속 곡선을 정확히 역재생한다. 다음 쪽은 새 페이지를 아래에 고정하고 현재 페이지가 0도→-18도·불투명도 1→0으로 사라진다(45% 지점 -8도·0.65). 이전 쪽은 현재 페이지를 아래에 유지하고 이전 페이지가 위에서 -18도→0도·불투명도 0→1로 펼쳐진다(55% 지점 -8도·0.65). 배경 페이지가 없어지는 공백을 만들지 않는다. 양쪽 모두 넘기는 중 연속 쪽 이동을 막고 보존 레이어를 접근성 트리·탭·클릭에서 제외한 뒤 종료/취소 시 제거한다. 최초 확대 진입·닫기·동작 줄이기는 별도로 유지한다.
- 기록집 페이지의 왼쪽 22%·오른쪽 22% 영역도 각각 이전·다음 쪽 이동을 지원한다. 중앙은 넘김 영역이 아니며, 구매 등 본문 내 실제 버튼이 겹치면 해당 버튼이 우선한다. 첫 쪽의 왼쪽과 마지막 쪽의 오른쪽은 비활성화하고, 넘김 애니메이션 중에는 양쪽 영역 모두 비활성화한다. 하단 텍스트 버튼은 그대로 유지하며 영역 버튼도 키보드 포커스·접근성 이름을 제공한다.
- `실물 기록집 구매하기`는 기존 작은 기록집의 완성 화면에서만 유지한다. 첫 진입 예시의 구매 클릭은 실제 소장 의향과 구분하기 어려워 제거했으며, 신규 구매 관심 집계는 `surface=completed_book`에서만 발생한다. 인접한 문구로 준비 중임을 알리고, 누르면 준비 중 모달만 열리며 주문·결제·배송정보 입력은 발생하지 않는다. 디지털 기록집과 PDF 기능은 유지한다.
- `welcome_viewed`, `welcome_record_started`, `welcome_explore_started`, `journal_book_purchase_clicked`를 기존 시스템 로그의 `product` 범주에 저장한다. 추가 DB 마이그레이션은 필요 없다.
- 클릭마다 별도 UUID를 사용하며, 같은 이벤트의 네트워크 재전송은 동일 ID로 멱등 처리한다. 구매 버튼을 다시 누르면 별도 클릭으로 저장한다. 화면 노출은 페이지 실행 중 계정별 중복을 제거한다.
- 전송에 실패한 큐는 최대 100건·7일 동안 로컬에 보관하고 다음 실행·온라인 복귀 시 재전송한다. 계정이 바뀌면 이전 계정의 대기 항목은 전송하지 않는다. 세션 생성 자체가 실패했으면 모달의 `다시 전송`으로 재시도한다. 연결 복구·재실행 전에 앱 삭제/저장소 삭제가 발생한 경우에는 복구할 수 없다.
- 서버에는 계정 식별자·행동·진입 화면·플랫폼·서버 수신시각만 저장한다. 새 계측에 기록 본문·사진·원본 IP·User-Agent는 포함하지 않는다. 180일이 지난 항목은 기존 인증자료 파기 작업에서 삭제한다.
- 관리자 `사업 지표 → 첫 화면과 실물 기록집 관심`에서 선택 기간의 고유 계정 수와 구매 버튼 클릭 횟수를 확인한다. 과거 예시 기록집 구매 클릭(`surface=welcome`)은 삭제하거나 완성한 기록집 클릭으로 재분류하지 않고 별도 이력으로 유지한다. 관리자와 통계 제외 계정은 기존 기준대로 제외한다.
- 구매 버튼 클릭은 관심 신호일 뿐 구매·결제 전환이나 지불의사 확정값이 아니다. 익명 계정 수는 실제 사람 수와 다를 수 있으며, 지연 재전송은 서버 수신일 기준으로 집계된다.
- 이번 변경이 배포된 이후의 새 이벤트만 집계한다. 과거 방문을 새 첫 화면 노출·구매 버튼 선택으로 소급 생성하지 않는다. 현재 작업은 `feat/lifelog-first-entry` 브랜치에 분리되어 있으며 운영 반영 전이다.

### 통합 점검 및 리팩토링

- 기록 시작 버튼은 첫 화면·예시 마지막 CTA에서 같은 진입/계측 함수를 사용한다. 기록집의 좌우 터치와 하단 버튼도 하나의 페이지 경계 규칙을 사용한다.
- 첫 기록의 화면 버튼·안드로이드 뒤로가기는 같은 단계 전환 함수를 사용한다. 사진 촬영일은 자르기 확정 뒤에만 반영하며 취소·재선택·화면 이탈 후에는 오래된 비동기 결과를 무시한다. GPS는 계속 읽지 않는다.
- 관심 계측 큐는 저장·만료·재전송 정책을 별도 모듈로 분리했다. 인증 헤더는 해당 이벤트 소유자의 세션으로 고정하고 401을 다른 계정으로 자동 재전송하지 않는다. 매 전송마다 계정·7일 만료 여부를 재검사하며 복원 시 허용 필드만 남긴다.
- 관리자 관심 지표는 선택한 기간에 필요한 이벤트만 조회하며 제거한 첫 화면 구매 버튼은 과거 수집 이력으로 표시한다. 기존 이력은 삭제하거나 실제 구매로 재해석하지 않는다.
- 전체 자동 테스트 281개와 타입 검사, 브라우저의 텍스트/사진 기록 저장·저장 실패 재시도·사진 선택 취소·예시 넘김·CTA 연결을 확인했다. 운영 배포와 네이티브 실기기 검증은 별도다.
