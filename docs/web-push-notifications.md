# 웹·PWA 알림

2026-11-04 구현 기준. 코드 구현과 운영 활성화·실제 기기 수신은 구분한다.
Android·iOS 네이티브 푸시는 [Android](./android-push-notifications.md)·[iOS](./ios-push-notifications.md),
종류·시간·예약 발송은 [알림 공통 동작](./local-notifications.md)을 따른다.

## 사용자 경험

- 웹에서도 설정 → 알림 설정을 제공한다. 지원 여부는 브라우저 기능으로 판단한다.
- HTTPS 지원 브라우저에서 사용자 동작으로 권한을 요청한다. 기본 수신 선택은 꺼짐이다.
- iPhone·iPad는 iOS/iPadOS 16.4 이상에서 홈 화면 웹 앱으로 열어야 한다. 일반 탭에서는
  공유 메뉴 → 홈 화면에 추가 → Tuti 아이콘으로 열기 순서를 안내한다.
- 수신 종류·시간·시간대는 계정 설정을 공유하지만 각 브라우저·앱의 권한과 구독은 별도다.
- 최초 동의의 선택 알림도 사용자 동작에서 브라우저 권한을 요청하고, 필수 약관 저장 뒤에만
  서버 구독을 등록한다. 거절·등록 실패가 필수 동의와 서비스 진입을 막지 않는다.
- 기록 권유·공동작성 소식은 기존 예약 발송기를 재사용한다. 브라우저·운영체제의 제한이나
  오프라인 상태가 있으므로 정확한 도착 시각과 수신을 보장하지 않는다.

## 구현과 보안 경계

- `PushPlatform.web` 추가형 마이그레이션을 적용한다. 별도 사용자 기기 테이블을 만들지 않아
  기존 계정 삭제·병합·복원 후 푸시 초기화·무효 기기 정리 경로를 재사용한다.
- 인증된 `GET /api/push/web`는 준비 여부와 공개 VAPID 키만 반환한다. 비밀 키는 서버에만 둔다.
- `/api/push/devices`는 표준 `PushSubscription`의 endpoint·p256dh·auth를 정규화해서 등록한다.
  주소의 해시로 설치 ID를 정하고 계정당 웹 구독은 최대 20개다. 다른 계정의 구독을 덮어쓰지 않는다.
- 서버의 외부 요청이므로 HTTPS·기본 포트만 허용하고 Google·Mozilla·Apple·Microsoft의
  알려진 푸시 제공자 호스트만 받는다. 새로운 제공자는 공식 주소를 확인하고 허용 목록을 수정한다.
- 계정 전환·로그아웃·해제는 표시된 알림과 워커 수신 표식을 먼저 정리하고 구독을 해제한다.
  늦게 도착한 등록·발송은 계정·세대 검사를 통과해야 한다. 실패한 서버 철회는 기기에 남겨 재시도한다.
- 계정 전환 후에도 브라우저가 보유한 **전체 구독 자격 증명(auth 포함)**과 설치 ID가 일치할 때만
  해당 웹 구독을 철회할 수 있다. 설치 ID만으로 타 계정 기기를 삭제하거나 네이티브 토큰을 철회할 수 없다.
- 워커는 계정의 해시 표식만 Cache Storage에 보관한다. 인증 토큰·사진·본문·페이지·API 응답은
  저장하지 않으며 `fetch` 가로채기나 오프라인 캐시를 설치하지 않는다. 계정 표식이 다르면 표시·클릭을 무시한다.
- 표시 문구는 공통 발송기의 일반 문구다. 사진·본문·장소·책 제목은 넣지 않는다. 클릭은 정해진
  같은 출처 화면으로만 이동하며 실제 내용 조회는 기존 인증·책 접근 권한 검사를 다시 거친다.
- 제공자 전송은 `web-push`의 암호화·VAPID 구현을 사용한다. TTL은 1시간, 요청 제한은 10초다.
  404·410 및 손상된 구독만 제거하며 인증·일시 장애를 구독 만료로 취급하지 않는다.
- 구독 URL·키·제공자 오류 원문은 로그·관리자 목록에 출력하지 않는다. 관리자 ‘알림 전달’에서
  웹 플랫폼의 준비 여부·기기·전송 성공/실패를 본다. 전송 성공은 화면 표시·읽음 확인이 아니다.

## 운영 활성화

실제 env 원문은 자동 조회하거나 수정하지 않는다. 운영자가 다음을 설정한다.

```dotenv
WEB_PUSH_ENABLED=true
WEB_PUSH_VAPID_PUBLIC_KEY=생성한-공개-키
WEB_PUSH_VAPID_PRIVATE_KEY=생성한-비밀-키
WEB_PUSH_VAPID_SUBJECT=mailto:admin@tuti.today
```

키가 없을 때 NAS에서 `pnpm exec tsx scripts/generate-web-push-vapid.ts --generate`를 한 번 실행한다.
출력은 비밀 키를 포함하므로 채팅·이슈·로그에 공유하지 않는다. 키를 매 배포마다 생성하지 않으며
실제 env·백업의 보호 대상으로 보관한다. 키를 바꾸면 기존 브라우저 등록을 정리하고 다시 켜야 한다.

1. 위 서버 전용 env를 설정한다. `NEXT_PUBLIC_` 키로 비밀 키를 전달하지 않는다.
2. Actions에서 앱·작업 이미지를 빌드하고 추가형 마이그레이션과 함께 운영 배포한다. NAS 로컬 빌드는 하지 않는다.
3. env를 바꿨다면 작업 컨테이너의 `tuti-ops-workers --refresh`도 관리자 권한으로 실행해 같은 키를 적용한다.
4. 기존 `tuti-notifications.timer`를 재사용한다. 웹용 타이머를 중복 설치하지 않는다.
5. HTTPS 브라우저와 iPhone 홈 화면에서 각각 수신·열기·끄기·계정 전환을 실제 시험한다.

브라우저 제공자에 따라 Google·Apple·Mozilla·Microsoft의 푸시 서비스를 경유하므로 운영 활성화 전
개인정보 처리 안내와 외부 처리 목록에 endpoint·구독 키·일반화된 문구·내부 이동 식별값의 전달을 대조한다.
기존 확정 약관 원문·동의 해시는 이 기능 작업에서 임의로 변경하지 않는다.

## 검증 범위

- 단위: 제공자 주소 제한·키 형식·VAPID 짝 검증·실패/만료 분리·로그 최소화·등록 계정과 철회 증명.
- 합성 브라우저: 명시적 권한 요청·구독·해제·등록 실패 후 정리·OS 권한 철회·iPhone 설치 조건.
- 워커 VM: 현재 계정 표시·해제 뒤 늦은 알림 무시·내부 클릭 경로·페이지 캐시 없음.
- 격리 PostgreSQL: enum 추가의 재적용과 기존 플랫폼 보존·웹 기기 삭제 연쇄.
- **미검증:** 실제 브라우저 푸시 제공자와 실기기의 종단 간 수신·표시·배터리/백그라운드 동작.
