# 함께 채우기

## 함께 남길 경험과 소장

하루마디 이름으로 여행·계절·취미 같은 주제를 자유롭게 표현한다. 새 책에서는 이름 예시를
선택적으로 펼쳐 고를 수 있고, `담고 싶은 기간`도 선택적으로 설정한다. 기간은 첫날·마지막 날을
함께 저장하거나 함께 비우며 기존 책에는 소급 지정하지 않는다. 기간 밖 마디도 담을 수 있고
기간 경과는 초대·작성·열람·참여 종료 조건이 아니다.

선택 기간은 담긴 마디로 계산한 실제 날짜 범위와 다르다. 기존 표지·PDF의 날짜를 기간으로
덮어쓰지 않는다. 만든 사람만 기존 설정 권한·리비전 검증으로 수정하며 초대 수락 전에 책 이름과
기간을 확인할 수 있다. 공유 본문은 책 맥락 뒤 빈 줄에 URL을 한 번 넣고 토큰 뒤에는 문구를 붙이지 않는다.

여러 사람이 함께 채우는 책에 마디가 있으면 `한 권으로 남기기`로 기존 PDF 미리보기·보관에
연결한다. PDF 사본을 만든 뒤에도 원래 책은 계속 채운다. 이는 `함께 채우기 종료`와 다르며
자동 마감·쓰기 잠금·초대 취소·참여 해제·완성 독촉 알림을 추가하지 않는다.

DB 변경은 `20261111010000_add_harumadi_memory_period`의 nullable DATE 열 두 개와 쌍·순서
제약이다. 먼저 서버 마이그레이션을 적용한 뒤 해당 앱을 배포한다. 기간을 생략한 기존 요청은
기존 값을 보존하고, 명시적 null 쌍으로만 기간을 해제한다.

기준: 2026-10-29. main에 반영하고 개발·운영 DB에 적용했다. 1.6.0 운영 배포와 양 스토어 업로드를 마쳤으며 실기기 검증은 별도다.
현재 제공 중인 개인 하루마디는 [하루마디](./harumadi.md)를 따른다.

## 진입 화면

2026-10-30 가시성 개선·전체 종료 구현 기준이며, 이번 변경의 운영·스토어 반영은 별도다.

- 책장에서는 별도 `함께 채우기` 버튼을 표시하지 않고, 각 책의 점 세 개 메뉴에서만 연다.
- 책장 점 세 개는 팝오버를 열고 `함께 채우기 시작` 또는 `하루마디 설정`을 선택한다. 공유 중이면 참여자 관리로 안내한다.
- 책을 펼친 화면 상단에서도 초대·참여자 관리로 바로 진입한다. 참여자에게 소유자 전용 설정은 표시하지 않는다.
- 진입만으로 공유 상태를 변경하지 않는다. 기존 공개 범위 안내를 확인한 뒤 만든 사람이 `초대 링크 보내기`를 눌러야 초대를 생성한다.
- 오프라인 읽기 사본에서는 최신 접근권을 확인하기 전 공동작성 조작을 허용하지 않는다.

## 계약

하루마디는 만든 사람 소유의 단일 책이고 참여자는 여러 명이다. 각 마디의 소유자는 작성자로 유지한다.

함께 채우기 관리에서는 계정의 표시 이름과 역할을 구분한다. 표시 이름이 없으면 본인은 `나`,
다른 참여자는 `이름 미설정`으로 표시하고 만든 사람·참여자 역할을 별도 행으로 보여준다.
역할 대체 문구의 첫 글자로 아바타를 만들거나 실명처럼 표시하지 않는다. 표시 이름이 있는 본인은
이름 옆 `나`로 구분한다. API는 기존 `name` 문자열을 유지하면서 `nameAvailable`로 실제 이름 설정 여부를 알린다.
공유 범위 안내는 초대 버튼 앞에 유지하고, 대기 중 초대·사람 목록·마디/신고 관리·종료를 분리한다.

다른 책·전체 마디 목록은 공유하지 않는다. 추가와 빼기는 연결 전체 교체와 분리한다.

- 공동작성 나가기·내보내기: 그 사람의 마디 연결과 댓글 본문을 해당 책에서 제거한다. 계정 원본은 유지한다.
- 만든 사람의 `함께 채우기 종료`: 모든 초대를 취소하고 모든 참여를 종료한다. 다른 작성자의 마디 연결을 해제하고 전체 공유 댓글 본문을 삭제해 개인 하루마디로 되돌린다. 각자의 원본 마디와 이미 저장한 PDF는 유지한다. 다시 함께 채우려면 새 초대를 보내야 한다.
- 참여자 계정 탈퇴: 본인 원본·사진은 기존 계정 삭제 절차로 삭제한다. 다른 저장자의 PDF 사본은 유지한다.
- 만든 사람의 계정 탈퇴·책 삭제: 모든 참여자의 책장에서 제거한다. 다른 작성자 원본과 다른 저장자 PDF는 유지한다.
- 부모 댓글 삭제는 다른 작성자의 답글을 삭제하지 않는다. 삭제 자리에는 원문·작성자를 전송하지 않는다.
- PDF 저장자의 계정 삭제·독립적인 권리 침해 대응은 별도 통제다. 다운로드 사본은 원격 회수하지 못한다.

## 서버 기반

`HarumadiMember`, `HarumadiInvite`, `HarumadiComment`와 세대별 연결 ID를 추가한다.
1회용 초대는 7일 만료·취소 가능하며 원문 대신 SHA-256 해시만 DB에 저장한다.
참여는 로그인·명시 수락이 필요하다. 링크를 전달받은 사람도 수락할 수 있다는 점을 안내한다.
동시에 여러 명이 수락해도 같은 링크는 한 명만 사용한다. 참여 인원 수에 대한 고정 제품 제한은 없다.
미사용 링크 50개와 요청 빈도는 남용 방지용 제한이며 마디·참여 인원 제한이 아니다.

원본 마디 편집은 본인만 가능하다. 책 관리·초대·내보내기는 만든 사람만 가능하다.
마디의 전체 읽기 순서 역시 만든 사람만 `순서 바꾸기`로 변경하며 참여자에게 같은 순서로 표시한다.
순서 변경은 마디 원본·작성자·연결 세대와 이미 저장한 PDF를 변경하지 않는다.
공유 책의 개인 목록 교체 PATCH는 차단하고 추가·빼기 API로 직렬화한다.
공유 책은 영속 읽기 캐시를 사용하지 않으며 사진은 참여 상태·책 권한 버전을 확인하는 15분 티켓으로 제공한다.
계정 삭제 시 댓글을 지우는 DB 트리거와 새 원장 종류를 추가한다. 예전 세대 철회가 재참여를 지우지 않게 한다.

## 전환과 남은 검증

초대 수락 화면은 `/harumadi/invite`이며 원문 토큰은 query 대신 fragment로 전달한다.
필수 약관·로그인 이후 저장해 둔 초대 의도로 복귀하되 자동 수락하지 않는다.
웹에서 참여하거나 `앱에서 열기`로 기존 custom scheme을 사용한다. 검증된 HTTPS 앱 링크와
설치 후 자동 복귀를 보장하지 않으며 초대 URL을 다시 열어야 할 수 있다.
공유 책은 기존 책장에 표시하고, 작성·선택은 자기 마디만 추가한다. 다른 사람 마디는 전체 교체하지 않는다.
책장·담을 책 선택·작성 화면의 공유 안내는 현재 참여자 중 본인을 제외한 대상에 맞춘다.
표시에는 대표 이름 하나와 나머지 인원수만 사용하며, 이름 미설정은 인원수로 안내한다.
아직 혼자 참여 중이면 현재 수신자가 있는 것처럼 표시하지 않고 향후 참여자에게도 보임을 알린다.
이 정보는 접근 가능한 책의 현재 멤버십에서 계산하며 초대 대기·종료된 참여나 이메일을 포함하지 않는다.
전체 종료는 소유자만 실행하며 앱 영역 안의 모달로 명시적 확인을 받는다. 내보내기·나가기·마디 빼기도 같은 확인 모달을 사용한다. 초대·참여자·댓글의 세대별 철회와 개인 상태 전환을 복원 방지 원장에 남긴다.
원장 준비 중 참여 대상이 바뀌면 종료하지 않고 재확인을 요청한다. 실패한 준비 기록은 기존 미완료 원장 점검·재시도 통제를 따른다.
새 원장 종류를 기록한 뒤 복구할 때는 이를 이해하는 최신 작업 이미지를 사용해야 한다. 구형 도구는 미지원 종류에서 복원을 중단한다.
PDF 승인은 원본 책·리비전·접근 버전을 서명에 포함하고 최종 저장 트랜잭션에서 재확인한다.
이미 확정된 다른 저장자의 PDF는 원본 책 접근권을 다시 요구하지 않는다.

## 댓글·안전·정리

책 읽기의 상단 `댓글·답글`에서 별도 화면으로 연다. 지면과 PDF에는 댓글을 삽입하지 않는다.
댓글·답글 1단계, 본인 수정·삭제, 만든 사람의 삭제, 20개씩 커서 조회와 요청 ID 재시도를 지원한다.
삭제 부모의 타인 답글은 남기고 원문·작성자를 제거한다. 신고는 해당 마디·댓글 또는 참여자만 대상으로 한다.
신고된 댓글의 최소 증거를 기존 관리자 신고함에 연결하며, 운영자는 공유 대상만 제거한다.
신고 접수·단어 필터가 모든 사진·맥락의 사전 검토나 스토어 심사 통과를 보장하지 않는다.

차단은 두 사람이 함께하던 책들의 참여 관계도 종료한다. 내가 만든 책에서는 상대를 내보내고,
다른 사람이 만든 책에서는 내가 나간다. 제3자의 원본은 삭제하지 않는다. 차단 해제는 참여를 복구하지 않는다.
차단/해제와 세대별 참여 종료는 백업 복원 원장에 연결한다. 차단 후 새 초대 수락도 제한한다.

초대 만료 후 30일·참여 종료 후 30일의 메타데이터와, 삭제 후 30일이 지난 본문 없는 댓글 중
답글이 없는 행을 개인정보 정기 작업에서 정리한다. 기본은 조회이며 기존 `--apply` 예약 작업에서 적용한다.
마이그레이션 전이면 설치 여부만 조회하고 건너뛴다. 활성 참여자·살아 있는 댓글·원본·PDF는 대상이 아니다.
개인정보 처리 대장은 신규 3개 모델을 **비활성 전환 대기**로 분류하며 과거 법적 승인 수치를 고쳐 쓰지 않는다.
운영 플래그 활성화 확인과 실제 다중 계정 검증을 마쳤다고 간주하지 않는다.

`HARUMADI_TOGETHER_ENABLED=true`일 때만 신규 공유 API·참여자 조회를 허용한다. 기본값은 비활성이다.
DB 마이그레이션, 서버·앱 연결, 신고·차단 운영, 약관·개인정보 안내 대조와 다중 계정 시험을 마친 뒤 활성화한다.
확정 법률 원문은 이 작업에서 수정하지 않는다. 로컬 웹·네이티브 빌드는 하지 않고 Actions로 검증한다.

## 검증 기록

2026-10-29 개발 PostgreSQL 17에 두 추가형 마이그레이션을 적용하고 개발 서버를 재시작했다.
이 개발 적용 과정에서 기존 마디·사진·PDF를 삭제하지 않았다. 실제 env 원문은 열거나 수정하지 않았다.
개발 초대 URL은 개발 API origin을 따르며 운영으로 보내지 않는다. 개발 웹에는 운영 앱 열기를 표시하지 않는다.
공유 시트 재시도는 같은 미사용 초대를 재사용해 중복 발급을 줄인다.

단위·회귀 검사, 타입·린트·문서·확정 약관 무결성 검사를 수행했다. 개발 초대 페이지는 HTTP 200,
미인증 책장 API는 HTTP 401로 확인했다. iOS·Android 실기기 공유/복귀와 실제 다중 로그인 사용성은 별도다.
로컬 PostgreSQL 11 격리 시험에서 실제 Prisma 잠금 반환값을 확인했다. 신규 스키마의 계정 탈퇴·
타인 PDF 보존 시험은 PostgreSQL 13 이상에서 실행하며, 기존 Actions의 PostgreSQL 17 검증에 연결했다.
최종 전체 회귀 검사는 742개 중 740개 통과·2개 건너뜀·실패 0개다. 타입·린트와 확정 약관 무결성 검사를 통과했다.

## 2026-11-04 관리 화면 개편

관리 화면은 현재 책 이름을 표시하고 실제 참여 관계에 따라 중심을 전환한다.
만든 사람 혼자라면 초대 문장·큰 초대 버튼을 먼저 보여주고, 미수락 초대가 있으면 수락 대기 상태를 알린다.
초대를 만들었다는 이유만으로 함께하는 사람이 생겼다고 표시하지 않는다. 다른 사람이 참여하면 실제 사람 목록을
먼저 보여주고 초대는 보조 행동으로 낮춘다. 만든 사람의 참여자 더보기에서 내보내기를 요청하며 기존 확인창을 거친다.
보낸 초대와 마디·신고 관리는 접어 두고 알림·종료는 별도 행으로 제공한다. 조회 중·오류에는 관리 행동을 표시하지 않는다.
공유를 취소한 뒤 재시도할 때는 아직 보유한 초대 링크를 재사용한다. 정상 전송·복사 후 새로 초대하면 새 링크를 만든다.
화면은 `HarumadiTogetherView`, 요청·확인·캐시 정리는 `HarumadiTogetherPanel`로 나누어 상태별 렌더를 검증한다.
화면 렌더 테스트와 실제 모바일·목업 시각 검증은 구분한다.
이번 독립 소스 리뷰에서 새로운 권한·파괴적 확인 우회는 발견되지 않았다. 브라우저 캡처가 없어 리뷰 판정은
`recapture`(시각 검증 미완료)다. 특히 320px·짧은 화면과 두 줄 책 제목에서 공유 안내 뒤 초대 버튼의 배치를 확인해야 한다.
구현 커밋은 운영 배포·앱 업로드를 의미하지 않는다.
