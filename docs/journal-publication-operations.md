# 기록 웹 공개 운영 지침

이 문서는 Tuti의 기록 웹 링크 공유를 내부 검증, 제한 베타, 정식 제공하는 동안
관리자가 확인하고 조치할 항목을 정리한다. 공개 기록 원본을 임의로 내려받거나
운영 목적 밖으로 이용하지 않는다.

## 담당과 확인 주기

- 운영 책임자: 눈마루 대표자 겸 Tuti 관리자
- 문의·신고 경로: 앱 1:1 문의, 공개 기록의 신고 기능,
  `admin@tuti.today`, `010-2724-4307`
- 관리자 콘솔의 `신고/기록 검토` 화면을 영업일마다 최소 한 번 확인한다.
- 개인정보 노출, 불법 촬영물 의심, 명백한 위해 위협처럼 긴급한 신고는 확인 즉시
  우선 숨김 처리하고 필요한 경우 관계기관 신고와 증거 보존 여부를 판단한다.
- 일반 공개 검토는 24시간 이내, 일반 신고는 2영업일 이내 첫 조치를 목표로 한다.
  이는 내부 운영 목표이며 자동 삭제나 신고 내용의 사실 확정을 뜻하지 않는다.

## 공개 검토 순서

1. 공개 대기 사유와 기록 원문·이미지만 필요한 범위에서 확인한다.
2. 타인의 개인정보·초상, 연락처, 외부 유도 링크, 불법·유해 표현, 반복 광고,
   저작권 침해 가능성을 확인한다.
3. 문제가 없으면 공개를 승인한다. 판단이 어렵거나 보완이 필요하면 공개를
   거절하고 운영 메모에 객관적인 사유를 남긴다.
4. 필터 결과만으로 기록 원본을 삭제하지 않는다. 사용자의 비공개 원본은 보존하고
   인터넷 노출 상태만 조치한다.

## 신고 처리 순서

1. 신고 대상 기록이 현재 공개 중이면 위험도에 따라 먼저 숨김 처리한다.
2. 신고 사유, 상세 내용, 원문과 기존 조치 이력을 함께 확인한다.
3. 오신고면 공개를 복원하고 신고를 종결한다. 위반이면 숨김을 유지하거나 기록을
   강제 삭제하고 처리 메모를 남긴다.
4. 반복·중대 위반이면 작성자의 기존 공개 기록을 숨기고 추가 공개를 제한한다.
5. 사용자가 이의를 제기하면 기존 담당자의 메모와 원문을 다시 확인하고 복원,
   제한 해제 또는 기존 조치 유지 결과를 안내한다.

## 자동 운영상태 점검

운영 명령을 다시 설치한 뒤 다음 명령으로 개발·운영 DB를 함께 점검한다.

```bash
sudo sh scripts/ops/install-tuti-operations.sh
sudo -n /usr/local/sbin/tuti-journal-publication-audit
```

결과는 `.ops-state/journal-publication-audit/<실행시각>/`에 개발·운영 JSON과
SHA-256 검증값으로 저장된다. 다음 항목을 확인한다.

- 상태별 기록과 신고 건수
- 24시간을 넘긴 공개 검토 및 미종결 신고
- 공개 제한 계정과 작성자 차단 건수
- DB 공개 상태 제약 위반 여부
- 현재 공개 정책이 아닌 동의 버전으로 남은 활성 기록 여부
- 최근 7일 공개·신고·숨김·복원·삭제·제재 감사 이벤트

점검 결과의 `passed`가 `false`이면 정식 공개 범위를 넓히지 않는다. `attention`은
데이터 무결성 실패가 아니라 담당자가 확인해야 할 지연 업무다.

## 단계별 기능 플래그

기능은 빌드 시점 환경변수로 고정된다. 값을 바꾼 뒤에는 반드시 새 이미지를
빌드해 배포한다.

```dotenv
# 내부 검증: 관리자 계정만 공개 메뉴 표시
NEXT_PUBLIC_JOURNAL_PUBLICATION_ENABLED=true
NEXT_PUBLIC_JOURNAL_PUBLICATION_AUDIENCE=internal

# 제한 베타 이후: 연결 계정 전체에 공개 메뉴 표시
NEXT_PUBLIC_JOURNAL_PUBLICATION_ENABLED=true
NEXT_PUBLIC_JOURNAL_PUBLICATION_AUDIENCE=public
```

긴급 중단 시 `NEXT_PUBLIC_JOURNAL_PUBLICATION_ENABLED=false`로 다시 빌드·배포한다.
서버 API와 공개 조회도 함께 차단되므로 기존 공개 주소는 404를 반환한다.

## 내부 검증 시나리오

- 공개 동의 미체크 상태에서는 공개 버튼이 비활성인지 확인
- 현재 정책 버전 없는 직접 API 공개 요청이 400인지 확인
- 이미지 없는 안전한 기록은 즉시 공개되고 이미지가 있는 기록은 검토 대기인지 확인
- 검토 승인 전 공개 주소와 이미지가 404인지 확인
- 승인 뒤 다른 브라우저에서 본문·이미지가 보이고 검색엔진 `noindex`인지 확인
- 작성자 차단 뒤 같은 브라우저에서 본문·이미지가 모두 보이지 않는지 확인
- 공개 중지 뒤 기존 주소가 즉시 404이고 재공개 주소가 달라지는지 확인
- 신고, 숨김, 복원, 강제 삭제, 작성자 제한·해제 후 감사 로그가 남는지 확인
- 기록 삭제 및 계정 삭제 뒤 원본 이미지와 공개 주소에 접근할 수 없는지 확인
- 웹, Android, iOS에서 정책 링크·동의·복사·공개 중지 흐름을 각각 확인

위 시나리오와 운영상태 점검을 모두 통과하고, 개인정보 처리방침 개정 시행일이
지난 뒤에만 제한 베타 또는 정식 제공으로 공개 범위를 확대한다.
