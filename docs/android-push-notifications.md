# Tuti Android 서버 푸시

Android 서버 푸시는 Capacitor Push Notifications와 Firebase Cloud Messaging
HTTP v1을 사용한다. 현재 첫 사용처는 사용자가 직접 남긴 1:1 문의의 답변
도착 알림이며 광고성·홍보성 메시지는 보내지 않는다.

## 자격증명

- 앱 설정: `android/app/google-services.json`
- 서버 서비스 계정:
  `/var/services/homes/Tutiadmin/.tuti-secrets/firebase/tuti-push-sender.json`
- 컨테이너 내부 경로:
  `/run/secrets/tuti-firebase-service-account.json`
- 서버 활성화 환경변수: `FCM_PUSH_ENABLED=true`
- 시행 전 내부 QA 허용 목록: `FCM_PUSH_TEST_EMAILS=admin@tuti.today`

서비스 계정 파일은 Git, 앱 번들, Docker 이미지에 포함하지 않는다. 호스트에서는
`root:administrators`, 디렉터리 `0750`, 파일 `0640`으로 보관한다. 개발·운영
컨테이너에는 읽기 전용으로 마운트하고 `administrators`의 숫자 GID만 추가한다.

운영 전체 활성화 전에는 `FCM_PUSH_ENABLED=false`를 유지하면서
`FCM_PUSH_TEST_EMAILS`에 명시한 로그인 계정만 기기 등록과 알림 발송을 허용한다.
익명 사용자와 다른 계정에는 적용되지 않으며 내부 QA가 끝나면 허용 목록을 비운다.

## 사용자 흐름

1. Android 앱의 `알림 설정`에서 `문의 답변`을 직접 활성화
2. 운영체제 알림 권한 확인 후 FCM 토큰 발급
3. Preferences에 생성한 설치 식별값과 토큰을 현재 Tuti 사용자에게 연결
4. 로그인·로그아웃으로 세션 사용자가 바뀌면 같은 설치를 새 사용자에게 재연결
5. 관리자가 문의 답변을 새로 저장하면 해당 사용자의 활성 Android 기기에 전송
6. 알림 선택 시 `/inquiry?view=history`로 이동
7. 사용자가 알림을 끄면 서버 연결과 FCM 토큰을 함께 해제

계정 삭제 시 외래키 cascade로 기기 정보도 삭제된다. FCM이 만료된 토큰을
`UNREGISTERED`로 응답하면 해당 기기를 자동으로 비활성화한다. 발송 오류는 문의
답변 저장을 취소하지 않으며 원문 토큰이나 서비스 계정 내용은 로그에 남기지 않는다.

- 이름: `Tuti 소식`
- 중요도: 기본
- 작은 아이콘: `tuti_notification_icon`
- 강조색: brand 500 `#8CBDEF`

## 실기기 확인

1. 새 디버그 APK 설치
2. 메인 메뉴의 `알림 설정`에서 `문의 답변` 활성화
3. 시스템 알림 권한 허용
4. 개발 DB `push_devices`에 현재 설치 1건이 연결됐는지 확인
5. 같은 사용자로 문의를 남기고 관리자 화면에서 답변 및 `답변 완료` 저장
6. 앱이 전면·백그라운드·종료된 상태에서 각각 알림 표시 확인
7. 알림 선택 시 내 문의 탭과 답변 표시 확인
8. 설정을 끈 뒤 같은 문의를 다시 수정해도 알림이 오지 않는지 확인
9. 로그아웃·다른 계정 로그인·앱 재설치 후 잘못된 계정으로 발송되지 않는지 확인

운영 배포 전 개인정보 처리방침의 Firebase Cloud Messaging 처리 항목을 다시
검토하고, 광고성 알림을 추가할 경우 서비스 알림과 분리된 명시적 사전 동의 및
간편한 수신거부 절차를 별도로 구현한다.

문의 답변 알림의 제목과 본문에는 문의 제목·본문·답변 내용을 넣지 않는다. 잠금
화면과 외부 메시징 구간에는 일반화된 답변 도착 문구만 표시하고, 사용자가 알림을
선택한 뒤 인증된 앱 화면에서 실제 답변을 조회한다.

개인정보 처리방침 변경 초안에는 다음 내용을 포함한다.

- 처리 항목: 앱 설치 식별값, FCM 토큰, 플랫폼, 앱 버전, 언어, 활성화·갱신·무효화 시각
- 처리 목적: 사용자가 요청한 문의 답변 도착 안내
- 외부 서비스: Google Firebase Cloud Messaging
- 외부 전달 항목: 푸시 토큰, 일반화된 알림 제목·본문, 앱 내부 이동 경로
- 보유기간: 알림 해제·계정 삭제 또는 토큰 무효화 시까지
- 이용자 통제: 앱 설정에서 로그인 없이 즉시 해제

현재 개인정보 처리방침은 중요한 변경을 시행 30일 전부터 알리도록 정하고
있다. 2026년 8월 31일 개정안을 공개하고 2026년 10월 1일 시행하기 전에는 운영
환경의 `FCM_PUSH_ENABLED`를 `false`로 유지한다. 고지 기간의 실기기 검증은
`tuti-android-debug-build --development`로 만든 개발 API 전용 APK에서 진행한다.

## 운영 활성화 일정

2026년 8월 31일 개정안을 운영 서비스에 공개해 30일 사전 고지를 시작한다.
따라서 일반 사용자를 대상으로 한 문의 답변 푸시는 2026년 10월 1일부터 활성화할
수 있다. 날짜가 되었다고 자동으로 활성화되는 것은 아니며, 아래 절차를 모두
마친 뒤 운영자가 직접 전환한다.

1. `/legal/privacy/2026-10-01` 개정안을 현행 개인정보 처리방침으로 전환
2. Google Play 데이터 보안 항목과 운영 개인정보 안내의 일치 여부 확인
3. 푸시 기능이 포함된 Android 앱 버전 배포 및 사용자 직접 동의 UI 확인
4. 운영 DB의 `push_devices` 마이그레이션 적용 상태 확인
5. `.env.production`의 `FCM_PUSH_ENABLED=true` 설정
6. 운영 재배포 후 전면·백그라운드·종료 상태 수신과 알림 해제 검증

시행일 전에 운영 푸시를 발송하지 않으며, 개발·내부 검증은 운영 사용자와 분리된
개발 API 및 테스트 계정에서만 진행한다.

## 2026-10-20 초기 수집·정리 보강 — 로컬 구현

- 신규 설치는 `firebase_messaging_auto_init_enabled=false`와 Analytics 수집 비활성으로 시작한다.
- 등록은 앱 전용 `TutiPushPrivacy` 브리지의 수동 getToken으로 수행한다. 기존 플러그인의
  register는 자동 초기화를 켜므로 Android 등록에는 사용하지 않는다.
- 같은 브리지의 단일 작업 큐에서 토큰 발급, FCM 토큰 삭제, Firebase 설치 ID 삭제를
  순서대로 완료 확인한다. UI 스레드에서 SDK 완료를 기다리지 않는다.
- 클라이언트는 등록·동기화·해제 순서를 직렬화하고, 해제 의도와 실패 대기를 저장한다.
  삭제를 시작하면 늦게 도착한 토큰은 서버에 등록하지 않는다. 계정에 고정된 요청은
  401 응답이나 계정 변경 후 새 익명 계정으로 재전송하지 않는다.
- 서버·기기 정리가 모두 끝나야 비활성 완료로 기록한다. 성공하면 Tuti 자체 설치 식별값도
  제거한다. 네트워크·SDK 실패/30초 응답 대기는 정리 대기로 남겨 앱 재실행·온라인 복귀에 재시도한다.
- 계정 삭제 API 성공은 서버 삭제 완료이며, 현재 기기 정리 실패는 별도 안내한다.
  다음 실행은 삭제 계정의 인증으로 서버 해제를 다시 보내지 않고 네이티브 정리만 재시도한다.
- 기존 설치에 새 정리 상태가 없으면 기존 등록을 정리하고 알림을 명시적으로 다시 켜야 한다.
  새 브리지가 없는 구버전 앱은 정리 완료로 표시하지 않고 업데이트를 안내한다.

**검증 전 한계:** 웹 배포만으로 네이티브 코드는 반영되지 않는다. 버전은 이번 작업에서
변경하지 않았다. NAS에서는 무거운 앱 빌드를 실행하지 않았다. 기존 SDK의 저장된 자동
초기화 설정은 새 매니페스트보다 우선할 수 있으므로 업그레이드 첫 실행·백그라운드
시작의 통신은 실기기에서 확인해야 한다. 다른 기기·Google 운영/백업 자료까지 즉시
모두 파기됐다는 의미가 아니며, 국외 이전 근거·고지 확정도 별도다.

실기기 회귀 확인:

1. 새 설치 후 알림을 켜지 않은 상태의 Firebase 토큰/FID 생성·통신 여부
2. 기존 알림 켠 버전에서 업그레이드한 첫 실행과 백그라운드 시작
3. 알림 켜기 → 수신 → 끄기 → 재실행 시 서버 재등록 없음
4. 토큰 발급 중 끄기, 오프라인 해제 → 온라인 복귀, 앱 강제 종료 후 정리 재개
5. 계정 삭제 성공/실패와 네이티브 삭제 실패를 구분하고 새 익명 계정의 오등록 없음
6. 정리 완료 후 명시적으로 다시 켜면 새 설치 ID/토큰으로 수신 가능
