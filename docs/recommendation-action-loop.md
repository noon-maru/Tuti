# 추천 이후 행동 루프

## 목적

추천을 본 횟수만으로 성과를 판단하지 않고, 사용자가 출발 준비를 확인하고
길찾기를 시작한 뒤 실제 기록까지 남겼는지를 하나의 흐름으로 연결한다.

## 흐름

1. 추천 API가 매 응답에 `recommendationId`를 발급한다.
2. 카드 선택, 상세·출발 준비 열기와 길찾기 시작을 같은 ID로 기록한다.
3. 길찾기 시작 시 선택한 장소와 이동수단, 시작 시각을 Preferences 기반
   Zustand 저장소에 보관한다.
4. 예상 이동시간에 30분을 더한 시점부터 앱이 다시 활성화되면 복귀 확인
   바텀시트를 표시한다. 최소 대기시간은 30분, 최대 대기시간은 4시간이다.
5. `다녀왔어요`는 장소가 미리 선택된 기록 작성 화면으로 연결한다.
   `아직이에요`는 하루 뒤 다시 확인하고, `다음에 갈 곳으로 남겨두기`는
   기기 저장소의 후보 목록에 보관한다. 보관한 장소는 메인 메뉴의
   `다음에 갈 곳`에서 다시 출발 준비를 열거나 삭제할 수 있다.

## 수집 이벤트

추천 전 진입 흐름은 `product_activity_events`에서 클라이언트 세션별로 한 번씩
기록한다.

- `session_started`: 새 브라우저 탭 또는 앱 WebView 실행
- `entry_started`: 초기 질문 화면 도달
- `entry_completed`: 초기 질문 응답 완료
- `entry_skipped`: 질문 없이 둘러보기 선택
- `main_viewed`: 유효한 초기 상태를 가진 메인 화면 도달

제품 활동에는 무작위 클라이언트 세션 ID, 웹·Android·iOS 구분과 네이티브 앱
버전만 저장한다. IP 주소, 전체 User-Agent, 현재 좌표, 화면 내용은 저장하지
않는다. 같은 사용자·세션·이벤트 조합은 한 번만 저장하고 원본 이벤트는 180일
후 자동 파기한다. 활동 기록 실패는 화면 이동과 추천 이용을 막지 않는다.

추천 이후에는 다음 이벤트를 `recommendation_actions`에 기록한다.

- `recommendation_shown`
- `place_selected`
- `departure_peek_opened` (이전 피크 시트에서 사용한 이벤트명)
- `departure_plan_expanded`
- `navigation_started`
- `return_confirmed`
- `return_dismissed`
- `return_deferred`
- `journal_started`
- `journal_created`

이벤트는 `recommendation_actions`에 사용자 ID, 추천 실행 ID, 장소 ID,
이동수단, 시각과 제한된 부가정보만 저장한다. 현재 위치 좌표와 이동 경로
원문은 저장하지 않는다. 익명 사용자도 기존 Tuti 세션으로 동일하게 기록한다.

추천 응답은 `recommendation_runs`에 당시의 응답, 해석된 상태, 후보 순서,
추천 이유, 피로도 점수, 거리와 혼잡도 근거, 알고리즘 버전을 함께 보관한다.
정확한 위치 좌표와 사용자가 입력한 상태 문장은 저장하지 않고, 위치와 상태
문장의 사용 여부만 불리언으로 남긴다. 스냅샷 저장 실패는 추천 응답을 막지
않는다.

## 관리자 지표

관리자 콘솔의 `추천 퍼널`은 최근 7일, 30일, 90일 기준으로 다음 흐름을
추천 실행 ID별 중복을 제거해 보여준다.

`추천 노출 → 장소 선택 → 출발 준비 열기 → 길찾기 시작
→ 다녀옴 확인 → 기록 남김`

함께 보여주는 지표는 위치 기반 추천 비율, 알고리즘 버전별 실행 수, 길찾기와
기록으로 이어진 상위 장소다. 퍼널은 운영 판단을 위한 관측 지표이며 현재
추천 점수를 자동으로 변경하지 않는다.

## 플랫폼 연결

- 웹과 앱의 대중교통·도보·자전거는 카카오맵 길찾기 링크를 사용한다.
- 웹의 자동차 경로는 카카오맵 링크를 사용한다.
- Capacitor 앱의 자동차 경로는 `kakaonavi://navigate` 딥링크를 사용한다.

## LLM 개인화 연결

이벤트 원문을 추천 요청 중에 LLM으로 보내지 않는다. 현재 사용자 개인화는
비활성화되어 있다. 향후 동의 및 삭제 기능을 갖춘 뒤 구조화된 행동은 규칙으로
집계하고, 동의한 자유문장의 공간 취향 표현만 모델로 추출할지 검토한다.
추출 결과와 장소 의미 프로필의 추천 반영은 shadow 검증을 먼저 거친다.
세부 기준과 현재 운영 상태는 [LLM 개인화 운영 원칙](./llm-personalization.md)을
따른다.

추천 장소 모아보기와 기타 미구현 아이디어는
[향후 검토 사양](./future-product-specs.md)에서 관리한다.
