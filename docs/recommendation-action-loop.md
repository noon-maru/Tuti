# 추천 이후 행동 루프

## 목적

추천을 본 횟수만으로 성과를 판단하지 않고, 사용자가 출발 준비를 확인하고
길찾기를 시작한 뒤 실제 기록까지 남겼는지를 하나의 흐름으로 연결한다.

## 흐름

1. 추천 API가 매 응답에 `recommendationId`를 발급한다.
2. 카드 선택, 피크 시트 열기, 출발 계획 확장과 길찾기 시작을 같은 ID로
   기록한다.
3. 길찾기 시작 시 선택한 장소와 이동수단, 시작 시각을 Preferences 기반
   Zustand 저장소에 보관한다.
4. 예상 이동시간에 30분을 더한 시점부터 앱이 다시 활성화되면 복귀 확인
   바텀시트를 표시한다. 최소 대기시간은 30분, 최대 대기시간은 4시간이다.
5. `다녀왔어요`는 장소가 미리 선택된 기록 작성 화면으로 연결한다.
   `아직이에요`는 하루 뒤 다시 확인하고, `다음에 갈 곳으로 남겨두기`는
   기기 저장소의 후보 목록에 보관한다. 보관한 장소는 메인 메뉴의
   `다음에 갈 곳`에서 다시 출발 준비를 열거나 삭제할 수 있다.

## 수집 이벤트

추천 전 진입 흐름은 `product_activity_events`에서 클라이언트 세션별로 한 번씩
기록한다.

- `session_started`: 새 브라우저 탭 또는 앱 WebView 실행
- `entry_started`: 초기 질문 화면 도달
- `entry_completed`: 초기 질문 응답 완료
- `entry_skipped`: 질문 없이 둘러보기 선택
- `main_viewed`: 유효한 초기 상태를 가진 메인 화면 도달

제품 활동에는 무작위 클라이언트 세션 ID, 웹·Android·iOS 구분과 네이티브 앱
버전만 저장한다. IP 주소, 전체 User-Agent, 현재 좌표, 화면 내용은 저장하지
않는다. 같은 사용자·세션·이벤트 조합은 한 번만 저장하고 원본 이벤트는 180일
후 자동 파기한다. 활동 기록 실패는 화면 이동과 추천 이용을 막지 않는다.

추천 이후에는 다음 이벤트를 `recommendation_actions`에 기록한다.

- `recommendation_shown`
- `place_selected`
- `departure_peek_opened`
- `departure_plan_expanded`
- `navigation_started`
- `return_confirmed`
- `return_dismissed`
- `return_deferred`
- `journal_started`
- `journal_created`

이벤트는 `recommendation_actions`에 사용자 ID, 추천 실행 ID, 장소 ID,
이동수단, 시각과 제한된 부가정보만 저장한다. 현재 위치 좌표와 이동 경로
원문은 저장하지 않는다. 익명 사용자도 기존 Tuti 세션으로 동일하게 기록한다.

추천 응답은 `recommendation_runs`에 당시의 응답, 해석된 상태, 후보 순서,
추천 이유, 피로도 점수, 거리와 혼잡도 근거, 알고리즘 버전을 함께 보관한다.
정확한 위치 좌표와 사용자가 입력한 상태 문장은 저장하지 않고, 위치와 상태
문장의 사용 여부만 불리언으로 남긴다. 스냅샷 저장 실패는 추천 응답을 막지
않는다.

## 관리자 지표

관리자 콘솔의 `추천 퍼널`은 최근 7일, 30일, 90일 기준으로 다음 흐름을
추천 실행 ID별 중복을 제거해 보여준다.

`추천 노출 → 장소 선택 → 출발 준비 확인 → 출발 정보 펼침 → 길찾기 시작
→ 다녀옴 확인 → 기록 남김`

함께 보여주는 지표는 위치 기반 추천 비율, 알고리즘 버전별 실행 수, 길찾기와
기록으로 이어진 상위 장소다. 퍼널은 운영 판단을 위한 관측 지표이며 현재
추천 점수를 자동으로 변경하지 않는다.

## 플랫폼 연결

- 웹과 앱의 대중교통·도보·자전거는 카카오맵 길찾기 링크를 사용한다.
- 웹의 자동차 경로는 카카오맵 링크를 사용한다.
- Capacitor 앱의 자동차 경로는 `kakaonavi://navigate` 딥링크를 사용한다.

## LLM 개인화 연결

이벤트 원문을 추천 요청 중에 LLM으로 보내지 않는다. 별도 배치가 충분히 쌓인
행동만 집계해 사용자 신호 프로필을 만들고, 장소 상세정보로 만든 장소 의미
프로필과 비교한다. 초기 운영은 기존 결과에 영향을 주지 않는 shadow 모드다.
세부 원칙과 운영 명령은 [LLM 개인화 운영 원칙](./llm-personalization.md)을
따른다.

## 향후 검토 사양: 추천 장소 3×3 모아보기

상태: **테스터 요청에 따른 검토 후보이며 구현 확정 아님**

현재의 한 장씩 넘기는 감각 카드 경험은 장소를 차분히 받아들이게 하는 장점이
있지만, 여러 추천을 한눈에 비교하거나 이전 카드를 다시 찾기에는 불편할 수 있다.
이를 보완하기 위해 Instagram 피드처럼 추천 장소를 최대 9개의 정사각형 카드로
보는 선택형 `모아보기`를 검토한다.

### 제품 원칙

- 기본 화면은 현재의 몰입형 캐러셀로 유지한다.
- 모아보기는 사용자가 명시적으로 전환할 수 있는 보조 탐색 방식으로 제공한다.
- 서로 다른 추천 목록을 만들지 않고 같은 일일 추천 결과와 같은 장소 순서를
  두 화면이 공유한다.
- 단순히 9칸을 채우기 위해 품질 기준을 낮추거나 장소를 반복하지 않는다. 추천
  후보가 9개보다 적으면 확보된 장소만 표시한다.
- 비교를 돕되 평점, 순위, 과도한 필터를 추가하여 결정 피로를 키우지 않는다.

### 예상 사용자 흐름

1. 메인 추천 화면의 보기 전환 버튼으로 `한 장씩 보기`와 `모아보기`를 오간다.
2. 모아보기에는 대표 이미지와 장소를 구별하는 최소한의 텍스트만 표시한다.
3. 카드를 선택하면 해당 장소를 현재 활성 장소로 만들고 기존 피크 시트 또는
   장소 소개 흐름을 연다.
4. 상세 화면을 닫으면 모아보기의 기존 스크롤 위치와 선택 상태로 돌아간다.
5. 보기 방식과 활성 장소 ID는 기존 Preferences 기반 Zustand 저장소에서
   복원하되, 일일 추천 결과가 바뀌면 유효성을 다시 확인한다.

### 구현 시 확인할 사항

- 추천 API가 품질 기준을 만족하는 후보를 최대 9개까지 안정적으로 반환할 수
  있는지 확인
- 9개 이미지 동시 요청이 첫 화면 로딩과 모바일 데이터 사용량에 미치는 영향
- 썸네일용 이미지 크기·포맷과 지연 로딩 정책 분리
- 좁은 휴대전화, 폴드 펼침 화면과 태블릿에서도 3열 구조 및 터치 영역 확보
- 캐러셀과 그리드 사이에서 활성 장소, 피크 시트와 접근성 focus 동기화
- 스크린리더에 이미지 그리드의 순서와 장소명을 명확히 제공
- 캐러셀 전용 제스처 안내가 모아보기에서는 노출되지 않도록 처리

### 채택 판단 기준

제한 베타 또는 A/B 테스트에서 다음 지표를 기존 캐러셀과 비교한다.

- 모아보기 전환율과 반복 사용률
- 추천 노출 후 첫 장소 선택까지 걸린 시간
- 추천을 보다가 아무것도 선택하지 않고 이탈한 비율
- 피크 시트, 장소 소개, 출발 준비와 길찾기로 이어진 비율
- 사용자가 여러 장소를 빠르게 비교할 수 있었다는 정성 피드백
- 선택지가 많아져 오히려 피로하다는 정성 피드백

모아보기가 장소 선택과 출발 전환을 개선하면서도 Tuti의 낮은 결정 피로와 감각적
추천 경험을 해치지 않는 경우에만 정식 기능으로 채택한다. 단순 열람량만 늘고
출발 행동이 줄어든다면 구현하지 않거나 `오늘 다시 고르기`와 같은 제한된
상황에만 제공한다.
