# 관리자 콘솔

관리자 콘솔은 `/admin`에서 접근한다. 화면 표시 여부와 관계없이 모든
`/api/admin/*` 요청은 서버에서 현재 사용자의 DB 권한을 다시 확인한다.

관리자 콘솔은 라이프로그 중심 제품 성과와 운영·관광 데이터 진단을 구분한다. 운영 제공 여부와
수집 시작은 배포·마이그레이션·앱 업데이트와 구분한다. 세부 정의·검증·적용 순서는
[라이프로그 지표](./admin-lifelog-metrics.md)를 따른다.

## 화면 기준

`/admin` 및 관광 데이터·추천 시뮬레이터·권리 보호 하위 화면은 관리자 레이아웃의
`AdminDesignSystem`과 `adminTheme`를 공유한다. 제품 성과의 흰 패널·옅은 녹색 구분선·
담백한 숫자와 표를 기준으로 하며 앱 화면에는 적용하지 않는다. 장식용 제목·그라데이션과
중복 해설은 줄이고, 권한·삭제 확인·개인정보 열람 목적·권리 대응 증빙·장애 상태는 유지한다.
날짜는 한국 시간으로 표시한다. 모바일 표·필터·더보기 메뉴와 키보드 포커스·모션 감소 설정을 유지한다.

## 지표 최신화 (2026-11-02)

- 제품 성과는 `/api/admin/lifelog-metrics`만 사용한다. 추천 실행을 핵심 전환으로 간주하던
  미사용 패널·계산기·타입과 추천 행동 기반의 옛 사용자 단계 판정기를 제거했다. 옛 `/api/admin/business-metrics`는 관리자 인증 후
  410과 새 경로를 반환한다. 예전 응답 형식으로 새 지표를 위장하지 않는다.
- 트래픽·보안의 ‘활동 확인 계정’은 보존 중인 신·구 활동 로그 계정 합집합이다.
  관리자·QA·만료·미래 자료를 제외하고 같은 계정을 중복 계산하지 않는다.
  7·30·90일은 다른 분석 화면과 같은 한국 날짜 범위를 쓴다. 트래픽 식별자 수와는 별개다.
- 사용자 활동은 작성·열람·담기 중심으로 표시하며 환경 자료 누락은 ‘미확인’으로 표시한다.
  구형 ‘전환’·‘수집 전’을 실제 방문·동의 여부로 오해하지 않도록 수정했다.
- 작은 여행 성과는 독립 행동 도달률로 표시하고 순차 단계를 암시하는 번호를 제거했다.
  관광 데이터 수집·추천 진단 지표는 운영에 필요하므로 유지한다.
- 운영 현황의 당일 로그·위치 이용 건수는 서버 운영체제 시간대가 아닌 한국 자정 기준이다.
  분모 없는 트래픽 구성은 0%가 아닌 ‘—’로 표시한다.

이 정리는 원본 이벤트·관광 데이터·동의·감사 자료를 삭제하거나 과거 미계측 활동을 소급하지 않는다.

## 최초 관리자 지정

먼저 관리자 마이그레이션을 적용한다.

```bash
pnpm db:deploy
```

인증 공급자와 연결된 이메일 계정을 관리자로 승격한다.

```bash
pnpm admin:promote admin@tuti.today
```

일반 사용자로 되돌리거나 다른 역할을 명시하려면 다음 명령을 사용한다.

```bash
pnpm admin:role -- --email admin@tuti.today --role user
```

마지막 관리자는 관리자 화면에서 강등할 수 없다. CLI 변경은 비상 복구에도
사용할 수 있으며 모든 변경은 시스템 로그에 남는다.

## 관리 범위

사용자 기록 조회는 [처리 요청 자동 채번](./admin-processing-cases.md)을 사용한다.
등록된 문의·사고·법적 요청을 선택하거나 목적을 골라 새 번호를 발급한 뒤 조회한다.
처리 번호를 임의 입력하지 않으며, 후속 조회는 기존 요청 번호를 재사용한다.

- 운영 현황: 마디·채워진 하루마디·실제 공동작성 보유량, 문의·신고, 알림 실패와 예약 작업 관측
- 제품 성과: 사업 요약, 첫 경험·재기록·재열람, 마디·하루마디, 함께 채우기, PDF·실물 구매 관심
- 사용자 활동: 전체 분석 대상 요약·날짜별 활동과 100개 단위 커서 목록을 분리. 내부·QA 제외 설정 제공
- 작은 여행 성과: 분석 대상 추천 실행과 연결된 독립 행동 도달. 실제 화면 노출·순차 전환·방문 인증으로 해석하지 않음
- 로그: 계정 로그인, 기록 생성·수정·삭제·공개, 신고와 관리자 작업 검색
- 장소: 출처와 공공데이터 ID 확인, 검토 상태와 추천 노출 여부 변경
- 신고: 상태 변경, 신고 대상 기록 강제 삭제
- 1:1 문의: 문의 검색, 상태 변경, 사용자에게 노출할 답변 등록
- 권한: 이메일 또는 사용자 ID 검색, 역할 변경과 계정 강제 삭제
- 설정: 공공데이터 자동 승인, 신고 접수, 서비스 운영 안내 문구
- 추천 시뮬레이터: 위치·지역·질문 응답별 실제 추천 실행과 후보 점수 진단

제품 지표는 관리자·분석 제외 계정을 기본 제외한다. 운영·권리 감사에서는 해당
계정을 숨기지 않는다. 계정 수는 익명 계정 중복 가능성이 있어 실제 사람 수와 같지 않다.
첫 마디로 자동 생성된 하루마디는 별도 선택 성과가 아니며, 구매 버튼 선택은
준비 중 안내를 연 관심 신호다. PDF·실물 구매·매출을 같은 수치로 표시하지 않는다.

## 예약 작업 관측

웹에는 Docker 소켓·sudo·env·원문 로그 접근권을 부여하지 않는다. NAS의 제한된
수집기가 고정 systemd 작업 상태를 확인하고 기존 ops 컨테이너를 통해 정제된 단일
스냅샷만 게시한다. 서비스 정상 종료·실패·예정 시간 초과·관측 불가를 읽기 전용으로 표시한다.
정상 종료는 잠금으로 건너뛴 실행을 포함할 수 있어 실제 파기·통지 완료·백업 무결성의 증거가 아니다.

새 웹·ops 이미지가 배포된 뒤 NAS 관리자가 한 번 설치한다.

```sh
sudo sh scripts/ops/install-job-health-observer --apply
```

앱·DB 재시작, 기존 개인정보 파기 작업 실행이나 env 변경은 하지 않는다. NAS 재부팅
후 타이머가 재개된다. 설치 전·3분 이상 오래된 관측·수집 실패는 정상으로 보지 않는다.
수집기는 기존 실패를 해결하거나 예약 작업을 재시도하는 도구가 아니다.

## 추천 시뮬레이터

`/admin/recommendation-simulator`에서 현재 위치, 위치 없이 선택한 지역 또는
전국 조건을 재현한다. 일반 추천과 같은 `evaluateRecommendations` 경로를 사용한다.
초기 추천은 후보·직선거리·구조화 정보를 우선 사용하며 모든 후보의 실제 대중교통 경로를
먼저 계산하지 않는다. 시뮬레이터 진단의 거리·시간 추정과 실제 길찾기 결과를 구분한다.

결과에는 원천 후보 수, 정밀 비교 후보 수, 최종 추천 6곳과 다음 진단값을
표시한다.

- 초기·최종 순위와 선정 여부
- 직선거리와 계산 가능한 이동시간 근거
- 기본 피로도, 거리, 이동시간, 이동 범위, 분위기, 혼잡도, 에너지 점수
- 사용자에게 표시되는 추천 문구와 세부 근거
- 장소 유형 다양성 또는 최종 순위에 따른 제외 사유
- 추천 알고리즘 버전과 전체 JSON 응답

총점이 낮을수록 현재 사용자 상태에서 부담이 낮은 장소다. 음수 항목은 추천
보너스이고 양수 항목은 부담 가산점이다. 시뮬레이션은 실제 추천 실행이나 행동
퍼널에 저장하지 않는다.

## 공공데이터 장소 입력 규칙

공공데이터 동기화 모듈은 `source`에 공급자 식별자, `sourceId`에 공급자의
원본 장소 ID를 저장한다. 자동 승인이 꺼져 있으면 `reviewStatus`를
`pending`으로 저장해야 한다. 추천 API에는 `approved`이면서 `isActive`인
장소만 포함된다.

관광 데이터의 `장소 원본` 탭에서는 추천 후보로 연결된 TourAPI 장소를 여러 개
선택해 승인·노출 또는 거절할 수 있다. 개별 원본을 열면 추천용 제목, 설명,
대표 이미지, 이동 난이도와 분위기 태그를 보정할 수 있다. 원본에 좌표나 대표
이미지가 없어 후보를 만들 수 없는 항목은 승인 대상에서 제외된다. 승인된 장소의
편집 필드는 이후 원본 동기화에서 덮어쓰지 않는다.

## 로그 범위

관리자 콘솔의 로그는 검색 가능한 애플리케이션 감사 로그다. Docker 표준
출력이나 인프라 로그 전체를 복제하지 않는다. 컨테이너 장애와 런타임 원문
로그는 기존 운영 로그 수집 경로에서 확인한다.

## 계정 강제 삭제

계정 강제 삭제는 현재 로그인한 관리자 본인과 마지막 관리자에게 사용할 수
없다. 사용자 세션, 인증 공급자 연결, 기록은 DB에서 제거되며 기록 이미지도
오브젝트 스토리지에서 함께 삭제한다. 감사 로그와 신고 추적 정보는 목적별 보관기한·최소화·분리 보전 정책을 따른다.
기존 1:1 문의는 운영 이력을 위해 본문을 유지하되 요청자 ID와 이메일을
비식별 처리한다. 이를 이유로 무기한 보존하거나 모든 가명자료를 완전 익명으로 취급하지 않는다.

## 1:1 문의

사용자는 메인 메뉴의 `1:1 문의`에서 문의를 작성하고 `내 문의`에서 처리
상태와 관리자 답변을 확인한다. 웹과 Capacitor 앱 모두 동일한 세션 API를
사용한다. 관리자 답변은 이메일 발송과 별개이며 앱 내 문의 내역에 표시된다.
