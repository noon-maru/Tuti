# Tuti 사업모델 논의 정리

작성일: 2026-09-07
문서 성격: 창업팀과의 논의를 정리한 내부 전략 초안. 확정된 원칙, 선택한 방향, 미검증 제안을 구분한다. 가격과 판매량 예시는 매출 예측이나 시장에서 검증된 견적이 아니다.

## 1. 현재 판단과 의사결정 상태

Tuti는 무료 핵심 경험을 유지하면서, B2B 계열에서는 표준화한 집계 데이터·정기 리포트의 판매 가능성을 검증하고, B2C에서는 사용자가 선택해서 구매할 수 있는 추가 가치를 찾는다. 두 축 모두 아직 반복 매출이 확인된 BM은 아니다.

| 항목 | 현재 상태 | 의미 |
| --- | --- | --- |
| 철학을 훼손하지 않는 수익화 | 사용자 확정 원칙 | 무분별한 광고, 외출 강요, 과도한 선택 부담을 피한다. |
| 3인 팀이 실제 판매·운영할 수 있어야 함 | 사용자 확정 원칙 | 개발 가능성뿐 아니라 고객 확보, 계약, 지원, 유지보수 비용을 판단한다. |
| 고객마다 별도 앱·서비스 개발 금지 | 사용자 확정 원칙 | 공통 핵심 모듈의 분리·설정·패키징은 허용하되 SI로 전환하지 않는다. |
| B2B 계열은 정기 데이터 판매를 우선 | 사용자가 선택한 전략 방향 | 구매 수요·데이터 품질·적법한 공급 가능성은 별도로 검증해야 한다. |
| 서비스·캠페인 공급은 규모가 커진 뒤 검토 | 사용자가 선택한 우선순위 | 이후 반드시 해야 하는 사업은 아니다. |
| B2C는 무료 핵심 + 선택형 단건 상품부터 검토 | 분석상 제안 | 구독을 전제로 기능을 끼워 맞추지 않는다. |
| 전자 기록집을 작은 유료 실험으로 검토 | 가장 최근의 분석상 제안 | 사용자 확정 상품이 아니며, 장기 주력 BM으로 입증되지 않았다. |

## 2. 팀과 서비스의 출발 조건

| 항목 | 확인된 내용 |
| --- | --- |
| 정연한 | 대표·개발 담당. 첫 창업, 20대 후반 개인사업자 |
| 김민형 | 기획·개발 보조. 대학생 |
| 유다혜 | 디자인 담당. 대학생 |
| 출시 상태 | 웹 배포 완료, iOS 출시 완료, Android 프로덕션 액세스 대기 기간 |
| 직접 영업 기반 | 현재 사실상 지역 기반·인맥 없음 |
| 목표 | 최소한 부업으로 삼을 수 있는 정도의 수익. 구체적인 순수익 목표는 미정 |
| 가용 시간 | 주 최대 약 30시간. 본 분석에서는 보수적으로 팀 전체 합산으로 가정했으며 확인 필요 |
| 미확인 지표 | MAU, 재방문율, 반복 추천 이용자 수, 기록 작성자 수·기록 수 분포, 유료 구매 의향 |

지금의 핵심 제약은 팀원의 나이 자체가 아니라 판매 근거와 운영 여력이다. 표준 상품이라도 구매자를 찾고, 품질을 설명하고, 대금을 받고, 환불·문의에 대응하는 시간이 든다. 개발 시간만으로 실행 가능성을 평가하면 안 된다.

## 3. 수익화가 지켜야 할 제품 원칙

Tuti의 중심 가치는 지친 사람이 낮은 부담으로 잠깐 일상 밖의 공기를 접하도록 돕는 것이다. 적은 입력과 적은 후보로 결정 부담을 줄이고, 사용자가 쉬거나 나가지 않는 선택도 존중한다.

- 추천 결과를 광고비나 판매 수수료 때문에 은밀히 바꾸지 않는다.
- 이용 횟수, 연속 출석, 기록량, 외출 성과를 압박하는 방식으로 결제를 유도하지 않는다.
- 기본 추천·기본 기록·기존 기록 열람을 억지로 불편하게 만들어 유료화를 정당화하지 않는다.
- 사용자가 기록하거나 공개하지 않아도 핵심 서비스를 이용할 수 있게 한다.
- 기록 원문, 개별 행동 이력, 정밀 위치를 판매 상품으로 삼지 않는다.
- 상업적 데이터 활용에 관한 안내·선택은 사용자가 이해할 수 있어야 한다. 참여 여부에 따라 무료·유료 상품의 이용 조건을 불리하게 바꾸지 않는 방향을 제안한다.
- 정신건강 진단, 치료 효과, 임직원 상태 평가처럼 현재 서비스가 입증하지 않은 가치를 판매하지 않는다.

데이터 BM 역시 철학의 예외가 아니다. 이용자를 구매자가 원하는 행동으로 유도하거나, 데이터 수집을 위해 답변과 외출을 강요하면 제품의 중심이 바뀐다.

## 4. B2B·B2G·간접 공급을 다시 판단한 이유

논의 초반에는 영업 기반과 운영 시간을 고려해 B2C를 우선했다. 이후 고객별 개발 금지와 데이터 판매 가능성을 반영해, 모든 B2B 계열을 배제하는 판단은 수정했다. 거래 상대의 명칭보다 무엇을 표준 상품으로 팔고, 누가 실제 구매·재판매를 담당하는지가 중요하다.

| 경로 | 공급 예시 | 지금의 적합성·부담 |
| --- | --- | --- |
| B2C | 개인이 추가 상품 구매 | 앱 안에서 판매할 수 있지만 구매할 이용자와 유료 가치가 필요하다. 출시 자체가 매출을 보장하지 않는다. |
| 직접 B2B | 기업·조사사에 정기 집계 리포트 공급 | 현재 검증할 우선 경로. 표본 품질과 구매 목적을 설명할 근거가 필요하다. |
| 직접 B2G | 공공기관에 데이터·리포트 직접 공급 | 조달 요건, 실적, 계약·검수 부담으로 초기 주력에 불리하다. 소액 거래까지 모두 불가능하다는 뜻은 아니다. |
| B2B2B | 조사·컨설팅 업체가 기업 고객 분석에 Tuti 통계 활용 | 기존 구매 관계를 활용할 수 있다. 중간 업체의 수요, 이용권 범위, 재판매 조건이 관건이다. |
| B2B2G | 공공사업 수행 업체가 기관 보고서에 Tuti 통계 활용 | 직접 조달 부담을 줄일 여지가 있지만 원계약의 외부 데이터 이용·재공급·하도급 제한 확인이 필요하다. |

첫 접촉 후보는 관광·여가·생활권 관련 조사·기획을 수행하는 소규모 전문 업체다. 이는 접근 가설이며, 실제 구매 의사나 예산이 확인된 고객군은 아니다. 중간 업체도 원자료 규모, 검증 가능한 방법론, 납기와 계약 책임을 요구할 수 있다.

## 5. B2B 계열의 우선 상품: 정기 집계 데이터·리포트

### 팔 수 있는 가치

Tuti가 차별화할 가능성이 있는 부분은 방문 이후의 이동·소비 결과만이 아니라, 외출을 고민하는 순간의 조건과 추천에 대한 반응이다. 예를 들어 사용자가 허용한 이동 범위, 원하는 공간 분위기, 혼잡도 선호, 동행 조건과 이후 반응 사이의 관계를 관찰할 수 있다.

다만 현재 데이터를 곧바로 “사람들이 언제 나가고 언제 안 나가는지”를 보여 주는 데이터라고 판매하면 과장이다. 정확한 출발점은 **Tuti 이용자가 외출을 고민할 때 표현한 조건과 앱 내 행동 데이터**다. 실제 외출·비외출은 별도의 응답과 측정 설계가 필요하다.

구매 가치 가설은 “어느 장소를 몇 명이 방문했는가”를 넘어 “어떤 조건에서 제안이 선택되거나 보류되는가”를 설명하는 것이다. 통신·내비게이션·카드 데이터나 무료 관광 통계를 대체하기보다, 이들이 직접 설명하기 어려운 의사결정 맥락을 보완할 가능성을 검증한다.

### 첫 상품 형태

- 동일한 주기와 정의로 만드는 분기 리포트 PDF
- 보고서에 대응하는 집계표와 데이터 사전
- 표본 수, 응답률, 미확인 비율, 수집 방식, 분석 한계를 담은 방법론
- 기관 내부 사용 또는 고객 보고서 인용 등 범위를 정한 비독점 이용권

초기에는 실시간 API보다 같은 보고서를 여러 고객에게 공급하는 형태가 운영하기 쉽다. 고객마다 별도 조사·분석·앱 개발을 해주는 구조는 피한다. 계절 비교는 실제 여러 기간의 데이터가 쌓이고 비교 조건이 맞을 때만 제공한다.

가능한 보고서 질문은 다음과 같다. 모두 지금 답할 수 있다는 뜻은 아니다.

| 구매자가 관심을 가질 수 있는 질문 | 필요한 관측·주의점 |
| --- | --- |
| 이동 범위에 따라 조용한 공간 선호가 달라지는가? | 실제 입력과 기본값·재사용 응답을 구분한다. |
| 혼잡도·날씨·이동 부담이 선택과 어떤 관련이 있는가? | 추천 시점의 조건과 정보 출처·시각을 남겨야 한다. 인과관계로 표현하지 않는다. |
| 어떤 조건에서 외출을 보류했다고 응답하는가? | 자발적인 결과·이유 응답이 필요하다. 화면을 닫은 행동만으로 판정하지 않는다. |
| 추천 장소 대신 다른 곳으로 나간 경우는 얼마나 되는가? | 앱 밖 행동을 직접 알 수 없으므로 선택형 후속 응답이 필요하다. |

### 현재 데이터가 말해 주는 것과 말해 주지 않는 것

앞선 코드 검토를 기준으로 정리했다. 실제 운영 설정이나 운영 DB의 표본 수를 확인한 결과는 아니다.

| 관측 항목 | 해석 가능한 범위 | 금지할 해석 |
| --- | --- | --- |
| 이동 범위·공간 분위기·밀도 선호 등 입력 | 추천 요청 시 표현한 조건 | 전체 국민의 성향, 심리 상태 진단 |
| `answered` / `reused` / `skipped` | 새 입력·재사용·건너뜀 구분 | 모두 새로 응답한 선호로 합산 |
| 추천 결과·순위·알고리즘 버전 | 제시한 후보와 추천 맥락 일부 | 모든 카드가 실제로 보였다는 단정 |
| `place_selected` | 카드 선택·전환 반응. 스와이프 포함 | 방문 의사 확정 |
| `navigation_started` | 지도·길찾기 시작 동작 | 실제 출발·방문 완료 |
| `return_confirmed` | 이용자의 복귀 자기보고 | 위치로 검증한 방문, 건강 개선 |
| `return_dismissed` | 확인창 닫기 등. ESC·배경 클릭 포함 | 외출하지 않음 |
| `return_deferred` | 나중으로 미룬 반응 | 최종 비외출 확정 |
| 이후 이벤트 없음 | 결과 미확인 | 비외출·이탈 이유 확정 |

추가 해석 제한도 있다.

- 예산 입력은 입장료 기준이다. 교통·식비를 포함한 총 외출 예산이 아니다.
- 내부 에너지 값은 이동 범위 등으로 해석한 값이며 독립적으로 응답한 심리 지표가 아니다.
- 장소의 행정구역은 목적지 정보다. 이용자 거주지를 뜻하지 않는다.
- 현재 사용자 모델에서 연령·성별·직업·거주지를 확보했다고 볼 근거는 없다.
- 추천 스냅샷에 당시 전체 후보군과 날씨·운영시간·이동 가능성의 모든 원자료가 보존되는 것은 아니다.
- 같은 사용자의 반복 기록, 재사용된 추천 실행 ID, 나중에 저장 장소에서 시작한 행동을 별도 사람·새 추천으로 세면 왜곡된다.
- 관리자 퍼널은 집계 기간과 분모를 상품 목적에 맞게 다시 정의해야 한다. 관리자 화면 숫자를 그대로 판매하지 않는다.

### 상품화 전에 필요한 보완

결과 확인은 선택 사항으로 두되, 길찾기를 누르지 않은 이용자의 결과도 응답할 수 있게 설계한다. 예시는 “추천 장소에 다녀옴 / 다른 곳에 다녀옴 / 나가지 않음 / 아직 결정하지 않음”이며, 응답이 없으면 미확인으로 남긴다. 이유는 시간·이동 부담·비용·날씨·마음에 드는 곳 없음·쉬기로 함 등에서 선택할 수 있다.

앱을 열지 않은 날의 행동은 여전히 알 수 없다. 그것까지 연구하려면 별도의 자발적 조사 참여 구조가 필요하며, 일상적인 사용 흐름에 의무 질문을 추가하지 않는다.

추천 시점의 날씨 구간, 이동 시간 구간, 정보 미확인 여부, 출처·시각 등을 최소한으로 남기는 방안을 검토한다. 이를 위해 정밀 좌표나 기록 원문까지 장기 보관할 필요가 있다고 가정하지 않는다.

보고서에는 이용자 수와 응답 수를 구분하고, 기간별 표본 변화·응답률·알고리즘 변경을 표시한다. 세부 지역·시간대·조건으로 나눌수록 표본이 작아지므로 공개 범위를 줄이거나 통합해야 한다. 모든 분석에 통하는 단일 최소 표본 수나 익명성 기준을 임의로 정하지 않는다.

### 개인정보와 신뢰

상업적 집계 통계 공급이 일률적으로 금지되는 것은 아니다. 그러나 가명정보는 여전히 개인정보이며, 통계·연구 목적에 관한 규정이 모든 판매나 재이용을 자동 허용하는 것도 아니다. 익명정보 판단은 다른 정보와의 결합을 포함한 합리적인 재식별 가능성을 검토해야 한다.

기존 처리방침에 따른 서비스 운영·개선 목적만으로 상업적 외부 제공이 모두 허용된다고 가정하지 않는다. 처리 근거, 목적, 제공 항목, 이용권, 재식별 위험과 보존·삭제 방침을 실제 공급 방식에 맞게 검토해야 한다. 처리방침 문구를 고치는 것만으로 과거 데이터의 이용 권한이 자동 확장되지는 않는다.

제품 철학 측면에서는 상업적 연구 참여를 명확히 안내하고 선택권을 제공하는 방향을 제안한다. 이는 모든 익명 통계에 개별 동의가 법적으로 필수라는 단정과 구분한다. 외부 공급에는 개인별 행, 식별자, 정확한 시각, 기록 원문을 포함하지 않는 방향으로 설계한다.

## 6. 서비스·캠페인·모듈 공급은 후순위로 보관

| 후보 | 표준 상품으로 가능한 범위 | 지금 미루는 이유 |
| --- | --- | --- |
| 장소·프로그램 전용 추천 링크·QR | 공통 엔진에 출발점·장소 목록·문구 설정 | 무료 안내 도구와 차별화해야 하며 고객 확보·목록 관리가 필요하다. |
| 추천 위젯·API | 공통 장소 규격·추천 엔진 제공 | 인증, 과금, 버전, 장애 지원, 외부 데이터 이용권 정리가 필요하다. |
| 캠페인 공급 | 같은 참여 흐름에 기간·대상·콘텐츠 설정 | 모집·운영·성과 설명이 고객별 대행 업무로 커질 수 있다. |
| 유료 B2C 이용권 일괄 판매 | 동일 상품의 이용권 공급 | 개인이 실제 구매할 유료 상품이 먼저 있어야 한다. |

공통 핵심 모듈은 재사용 가능성이 있지만 현재 내부 API를 그대로 외부 판매할 수 있다는 뜻은 아니다. 장소 소스 결합, 고객별 접근 경계, 운영 설정, 라이선스 범위를 정리해야 한다. 운영시간·시간 예산·입장료 조건도 현재의 점수 조정과 정보 미확인 처리를 넘어, 어떤 조건을 보장하고 어떤 조건은 참고인지 명확히 해야 한다.

고객 요구는 공통 제품의 개선으로 수용할 수 있는지 먼저 판단한다. 고객별 코드 분기, 별도 앱 배포, 별도 업무 시스템 개발이 필요하면 현재 사업 범위에서 제외한다.

## 7. B2C: 무료 핵심 경험 + 선택형 추가 상품

### 무엇에 돈을 받을 것인가

현재 제안은 추천 이용 횟수나 기존 기록 접근을 제한하는 구독보다, 사용자가 결과물을 보고 필요할 때 구매하는 추가 상품을 먼저 검증하는 것이다. 기본 이용자가 존재한다는 사실과 유료 구매자가 존재한다는 사실은 다르다.

| 후보 | 구매 가치 | 팀의 판매·운영 가능성 | 현재 판단 |
| --- | --- | --- | --- |
| 전자 기록집 | 흩어진 내 외출 기록을 한 권의 결과물로 보관 | 앱 안 미리보기·자동 생성으로 표준화 가능. 기록을 충분히 남긴 이용자만 대상 | 작은 첫 유료 실험 후보 |
| 개인 저장 장소를 현재 조건에 맞게 다시 추천 | 이미 관심 있는 후보 중 선택 부담 감소 | 반복 이용 가치가 있을 수 있지만 기존 무료 추천과 차이를 입증해야 함 | 후속 핵심 유료 가치 후보 |
| 출발 전 조건 재확인 | 예정한 외출의 날씨·운영·이동 조건을 다시 확인 | 정확성, 정보 누락, 알림 실패, 무료 대체재 문제가 큼 | 앞선 우선 제안에서 순위를 낮춤 |
| 테마·외형 꾸미기 | 개인 취향 표현 | 운영 부담은 상대적으로 작지만 지불 동기·반복 구매 근거가 약함 | 보조 후보 |
| 월·연 구독 | 지속적으로 반복되는 추가 효용 | 매달 돈 낼 이유와 유지율이 아직 확인되지 않음 | 현시점 선행 도입 보류 |

전자 기록집은 Tuti의 핵심 추천 가치 자체에 과금하는 상품은 아니다. 철학 적합성과 작은 실험의 실행 가능성 때문에 제안했으며, 구매 빈도가 낮고 대상도 좁아 이것만으로 부업 수익을 달성한다고 가정하지 않는다.

### 첫 실험 후보: 나의 작은 외출책

기록을 여러 개 남긴 사용자가 자신의 글과 사진을 묶어 디지털 PDF로 구매한다. 기록을 더 쓰도록 압박하지 않고, 이미 남긴 기록을 원하는 형태로 소유하는 가치를 판다.

최소 범위는 기록 6~12개 선택, 제목 입력, 단일 판형·디자인, 전체 미리보기, 단건 결제, 다운로드·재다운로드다. 기록 원문을 임의로 AI가 해석하거나 감정을 진단하지 않는다. 고객별 편집 대행, 실물 인쇄·배송, 무제한 템플릿 제작은 초기 범위에서 제외한다.

논의한 **권당 5,900원은 가격 실험 가설**이다. 현재 단일 기록 PNG 공유는 존재하지만 다중 기록 PDF, 페이지 조판, 결제·구매 권한, 재다운로드는 별도 구현이 필요하다. 저장 이미지의 해상도에도 한계가 있어 고해상도 실물 사진책 품질을 약속하지 않는다.

무료 기록 열람·기존 공유는 유지하고, 완성된 미리보기를 보고 구매하게 한다. 상업적 데이터 활용 참여 여부를 구매 조건이나 할인 조건으로 묶지 않는 방향을 제안한다.

### 실제로 팔 수 있는지 확인하는 방법

첫 대상은 일반 앱 설치자가 아니라 기록을 여러 개 남긴 기존 이용자다. 먼저 해당 사용자가 있는지 집계로 확인한다. 대상이 거의 없다면 전자 기록집 결제 기능 개발을 시작할 근거가 약하다.

동의받은 기록이나 명확히 표시한 예시 기록으로 샘플을 만들고, 기록 보유 이용자에게 결과물과 가격을 함께 보여 준다. 디자인 호감과 실제 구매를 구분한다. “기록 8개 이상 보유한 이용자 20명 중 3명 구매”처럼 내부 실험 기준을 둘 수 있지만, 이 숫자는 논의용 예시일 뿐 통계적 검증 기준이나 전체 이용자 전환율이 아니다.

결제 기능이 없는 상태에서는 완성 예시와 구매 의향 확인까지 할 수 있다. 실제 유료 검증에서는 전달할 상품, 결제·환불 조건, 지원 가능한 플랫폼을 갖춰야 한다. 화면에서 구매 버튼을 눌렀다는 이유만으로 매출이 검증됐다고 표현하지 않는다.

주요 지표는 구매 대상 이용자 수, 미리보기 이용률, 실제 결제율, 환불·생성 실패율, 주문당 지원 시간이다. PDF가 많이 팔리는 것뿐 아니라 핵심 추천과 기록 사용에 부담을 주는지도 본다.

## 8. 수익 예시를 해석하는 법

아래 숫자는 규모를 이해하기 위한 산술 예시다. 현재 고객 수나 구매율을 근거로 한 전망이 아니다.

| 예시 | 단순 계산 | 제외된 항목 |
| --- | --- | --- |
| 전자 기록집 월 100권, 권당 5,900원 | 월 총결제액 59만원 | 플랫폼·결제 수수료, 세금, 환불, 저장·생성 비용, 팀 노동 |
| 분기 리포트 50만원, 구매 기관 6곳 | 분기 총매출 300만원, 월 환산 100만원 | 영업·집계·검수·계약 비용, 세금, 갱신 실패 |

분기 매출의 월 환산치는 매월 들어오는 현금이 아니다. B2B와 B2C 예시를 단순히 합쳐 확정 수입으로 취급하지 않는다. 부업으로 성립하는지는 총매출보다 비용을 뺀 금액, 반복 구매·갱신, 소요 시간을 함께 봐야 한다.

플랫폼 수수료는 프로그램 자격·가입 상태·지역·결제 방식 등에 따라 달라질 수 있으므로 고정 비율을 가정해 순수익을 확정하지 않는다. 구체적인 과금 구현 단계에서 적용 조건을 확인한다.

## 9. 다음 실행 순서와 역할 제안

기능 두 개를 동시에 크게 만드는 대신, B2B는 구매자의 질문을 확인하고 B2C는 실제 구매 대상과 결과물을 확인한다. 아래는 앞으로의 제안이며 아직 수행·승인된 개발 계획이 아니다.

| 순서 | B2B 계열 | B2C |
| --- | --- | --- |
| 1. 현재 자산 확인 | 집계 가능한 표본·기간·응답 정의·미확인 비율 파악 | 기록 보유 이용자 수와 기록 수 분포 파악 |
| 2. 판매 제안 구체화 | 동일한 목차·지표·이용 범위를 가진 샘플 리포트 제작 | 단일 디자인 전자 기록집 샘플과 가격 제시 |
| 3. 수요 확인 | 구매 담당자가 어떤 의사결정에 쓰는지, 예산·주기·유료 파일럿 의사 확인 | 대상 이용자의 구매 의향 확인 후 소규모 실제 결제 검증 |
| 4. 필요한 부분만 구현 | 실제 필요한 수집 보완·집계 품질·공급 근거 정리 | 생성·결제·다운로드·환불 등 공통 흐름 구현 |
| 5. 지속 여부 판단 | 재구매·갱신과 고객당 대응 시간 확인 | 실제 구매율·주문당 비용·지원 시간 확인 |

합성 데이터로 만든 리포트는 예시라고 명시한다. 표본이 없거나 부족한 상태에서 실제 시장 조사 결과처럼 판매하지 않는다. 구매 인터뷰에서 요구되는 것이 계속 맞춤 설문·분석 대행이라면, 정기 표준 데이터 상품에 대한 수요와 구분한다.

역할은 정연한이 데이터 정의·품질과 공통 구현, 김민형이 구매자 조사·이용자 인터뷰·요구 정리, 유다혜가 샘플 리포트·기록집의 정보 표현과 디자인을 맡는 구성을 제안한다. 계약과 개인정보 관련 판단은 대표가 책임지고 필요한 전문 검토 범위를 정한다.

매주 서비스 유지보수 시간을 먼저 확보한 뒤 실험 시간을 배정한다. 학기 중 가용 시간과 기존 운영 부담을 반영해, 동시에 개발하는 유료 상품은 하나로 제한하는 편이 적절하다.

## 10. 아직 답이 없는 질문

- 부업 수준의 목표는 팀 전체 월 순수익 얼마이며, 언제까지 달성해야 하는가?
- 주 30시간은 팀 전체인가, 대표 개인 기준인가?
- 현재 반복 이용자와 충분한 기록 보유 이용자는 얼마나 되는가?
- Tuti 데이터가 필요한 구매자는 어떤 의사결정에 얼마의 예산을 쓰는가?
- 판매할 수 있을 만큼 안정적인 표본과 후속 응답을 확보할 수 있는가?
- 무료 관광 통계·기존 조사 대비 독립적인 추가 가치가 있는가?
- 전자 기록집은 실제 유료 구매로 이어지는가, 작은 부가 상품에 머무는가?
- 핵심 추천 경험에서 사용자가 반복적으로 돈을 낼 만큼 절약되는 수고는 무엇인가?

이 질문이 남아 있다는 것은 사업을 포기해야 한다는 뜻이 아니다. 다만 정기 데이터 판매와 B2C 상품을 이미 검증된 수익원으로 전제하고 인력·개발 범위를 늘릴 단계는 아니다.
