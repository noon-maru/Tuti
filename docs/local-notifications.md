# Tuti 알림 개편과 구형 로컬 예약 정리

2026-11-03 구현 기준. 아직 운영 배포·기기 시험·예약 발송기 활성화를 뜻하지 않는다.

## 사용자 설정

- 함께 채우기·서비스 소식: 새 마디, 초대 수락, 내 댓글의 답글, 문의 답변.
- 마디 기록 알림: 기본 매일 19:00, 사용자가 시간 변경·on/off 가능.
- 두 선택은 기본 꺼짐. 최초 필수약관 동의 버튼은 알림 선택을 자동 체크하지 않는다.
- 최초 화면의 선택 알림은 위 두 종류와 기본 시간을 설명한다. 선택한 경우에만 필수약관 저장 후 OS 권한을 요청한다. 거절·등록 실패가 서비스 진입을 막지 않는다.
- 시간·시간대·두 수신 설정은 계정에 저장한다. 앱 업데이트 때 사용자의 시간을 초기화하지 않는다. 웹·PWA도 지원 환경에서 별도로 권한·구독을 등록한다. [웹 알림의 조건과 운영 준비](./web-push-notifications.md)를 따른다.
- 하루마디별 소식 끄기는 함께 채우기 관리에서 제공한다. 전체 소식 선택과 별개다.

## 발송

`notification_jobs`에 도메인 변경과 같은 트랜잭션으로 적재한다. 새 마디는 3분간 모아 하루마디별 한 번으로 보낸다. 이는 초기 실험값이다. 공유 링크 자체에는 수신자가 없으므로 최초 초대 전달은 메신저, 수락 소식은 만든 사람에게 전달한다. 일반 댓글 전체 알림은 제공하지 않고 내 댓글의 답글만 보낸다.

기록 알림은 선택 시간대의 실제 생성일 기준으로 오늘 작성 여부를 확인한다. 방문일을 과거로 설정한 오늘의 작성도 알림을 생략한다. 작성 화면의 짧은 생존 신호가 있으면 생략하고, 알림을 누르면 마디 작성으로 이동한다. 오프라인 작성은 서버 저장 완료 전에는 확인할 수 없다.

발송 전 현재 수신 설정·참여·차단·책별 음소거·원본 존재를 다시 확인한다. 책을 보고 있거나 작성 중인 상태는 30초마다 갱신하고 90초 후 만료한다. 현재 페이지에서 푸시 대신 강제 팝업을 띄우지 않으며 공유 책의 기존 새로고침 동작을 유지한다.

발송 큐는 제공자 호출 전에 처리 표시를 커밋한다. 모호한 전송 실패는 중복 알림 대신 누락을 허용하며 자동 재발송하지 않는다. 단말별 수신을 보장하지 않는다. 오늘의 알림을 무시했다고 다시 보내지 않으며 장애 중 놓친 시각도 소급 발송하지 않는다. FCM/APNs 만료는 한 시간이다.

사진·글·장소·책 제목은 알림에 넣지 않는다. 내부 이동에 필요한 책·발송 식별값은 전송한다. 관련 내용 조회 API는 열 때도 접근 권한을 확인한다.

## 구형 앱 예약

새 앱에서 기존 로컬 예약 10001·시험 예약 10002를 취소한다. 종전 ‘오늘의 Tuti’, 조용히/팝업 선택, 외출 상태 확인 이동은 제거했다. 예전 앱의 수신 선택을 새 종류에 자동 전환하지 않는다. 로컬 알림 플러그인은 기존 예약 정리를 위해 유지한다.

## 운영 반영 순서

1. DB 마이그레이션과 웹·작업 이미지, 새 네이티브 앱을 Actions로 빌드·배포한다. NAS 로컬 빌드 금지.
2. 실제 env에서 `FCM_PUSH_TEST_EMAILS`, `APNS_PUSH_TEST_EMAILS`를 제거한다. 코드·example에서는 이미 제거했다. 전체 플랫폼 스위치 `FCM_PUSH_ENABLED`, `APNS_PUSH_ENABLED`는 필요한 플랫폼에 true로 설정한다. 원문을 출력하지 않는다.
3. 개인정보 처리 안내를 확정한다. 현재 확정본은 문의 답변 중심이므로 아래 변경 항목을 반영할 별도 방침 개정 검토가 필요하다. 확정 원문·기존 동의 해시는 이 작업에서 수정하지 않는다.
4. 새 작업 이미지 배포 후 NAS에서 `sudo sh scripts/ops/install-notifications --apply` 실행. 기존 유지보수·복원 대기 잠금과 실패 알림을 재사용한다. 이 설치는 ops 설정을 새로 반영하지만 앱·DB를 재시작하지 않는다.
5. `sudo /usr/local/sbin/tuti-notifications-dispatch`는 조회, `--apply`는 실제 발송이다. 타이머는 매분 점검한다. 관리자 알림 화면의 마지막 점검·오류·대기 건수를 확인한다.

## 보유와 고지 검토 항목

수신 설정·시간대는 해제 후에도 다음 선택을 위해 계정 삭제 전까지 보관한다. 책별 선택은 책·계정 삭제 시 함께 지운다. 생존 신호는 90초, 발송·열기·작성 관측과 큐는 30일 이내 정리한다. 계정 탈퇴 시 외래키로 삭제한다. 삭제 원장 재반영 절차를 우회하지 않는다. 국외 전달 목적에 기록 권유와 공동작성 소식, 일반화된 문구·내부 이동 식별값을 포함하는지 검토해야 한다.

관리자 지표는 계정별 수신 설정·대기·종류별 제공자 전송·앱 보고 열기와 알림을 통해 시작한 작성이다. 최근 24시간 앱에서 관측한 OS 권한 요청·허용·거절 계정, 수신 끄기 계정도 별도 집계한다. 기존 권한이 허용되어 있으면 새 팝업 요청 없이 허용 확인만 생기므로 이 수치를 단순한 전환 퍼널로 나누지 않는다. 제공자 성공은 실제 전달·표시·읽음이 아니다. OS 권한 허용·등록 실패·기기 차단 상태의 전체 모집단을 임의로 추정하지 않는다.

## 검증

단위 시험: 시간 형식·기본값·사용자 시간대. 격리 PostgreSQL: 묶음, 자기 행동 제외, 음소거, 참여 종료·차단 재검사, 오늘 작성·작성 중 억제, 하루 중복 방지, 삭제 연쇄 파기.

실기기에서 최초 선택/미선택, OS 거절과 재허용, 앱 재시작·계정 변경, 예약 시각의 포그라운드/백그라운드, 다른 기기 작성 후 억제, 링크 이동·접근 철회를 추가 확인한다. 실제 기기 수신 시험은 코드 시험으로 대체하지 않는다.
