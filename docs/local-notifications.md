# Tuti 로컬 알림

Tuti의 첫 알림은 서버 푸시가 아닌 기기 내 로컬 알림으로 제공한다. 사용자가 앱의
`알림 설정`에서 직접 켠 경우에만 권한을 요청하고, 선택한 현지 시각에 하루 한 번
`오늘의 Tuti`를 표시한다.

## 현재 범위

- iOS와 Android 네이티브 앱 지원
- 기본 비활성화 및 사용자 명시적 활성화
- 기본 제안 시간 오전 10시
- 사용자가 선택한 기기 현지 시각에 일일 반복
- 앱 시작 시 Preferences 설정과 실제 예약 상태 재동기화
- 알림 선택 시 루트로 이동하고 오늘 상태 확인 흐름 표시
- 설정 화면에서 5초 뒤 테스트 알림 제공
- 웹/PWA에서는 설정 메뉴 미노출 및 직접 접근 시 미지원 안내

## Android 설정

- 채널 ID: `daily_tuti`
- 채널명: `오늘의 Tuti`
- 작은 아이콘: `res/drawable/tuti_notification_icon.png`
- 아이콘 색상: brand 500 `#8CBDEF`
- 알림 LED 색상: secondary 500 `#C7EA86`
- 정확 알람 미사용

Tuti 알림은 분 단위 정확성이 핵심 기능이 아니므로
`SCHEDULE_EXACT_ALARM`과 `USE_EXACT_ALARM` 권한을 추가하지 않는다. 예약에는
`isExactNotification: false`를 명시하며 기기의 절전 상태에 따라 알림이 몇 분
늦어질 수 있음을 설정 화면에서 안내한다.

Android 13 이상에서는 사용자가 알림을 처음 켜는 순간 시스템 알림 권한을
요청한다. 권한이 거부되면 Tuti 설정값을 활성화하지 않고 시스템 설정에서 다시
허용하도록 안내한다.

## iOS 설정

iOS는 별도 알림 아이콘을 사용하지 않고 앱 아이콘을 자동으로 표시한다. 앱이
열려 있을 때에도 배너, 소리와 알림 센터 표시를 허용하도록 Capacitor의
`presentationOptions`를 설정한다.

## 데이터와 수명주기

활성화 여부와 알림 시각은 기존 Capacitor Preferences 기반 `tuti-ui` 저장소에만
보관한다. 서버 계정 데이터에는 저장하지 않는다. 앱을 시작하거나 설정이
변경되면 고정 ID `10001`의 기존 예약을 취소한 뒤 다시 예약해 중복을 방지한다.

테스트 알림은 ID `10002`를 사용하며 새 테스트 또는 알림 비활성화 시 이전 테스트
예약도 취소한다.

## 실기기 확인

1. 앱 메인 메뉴에서 `알림 설정` 진입
2. `오늘의 Tuti` 활성화 후 시스템 권한 허용
3. `5초 뒤 테스트 알림 받기` 선택 후 앱을 백그라운드로 전환
4. 알림 아이콘, 제목, 본문과 표시 여부 확인
5. 알림 선택 시 앱 루트와 오늘 상태 시트 표시 확인
6. 시간을 2~3분 뒤로 바꿔 일반 반복 예약 확인
7. 알림을 끄고 해당 시각에 더 이상 도착하지 않는지 확인
8. 권한 거부, 시스템 설정 재허용, 앱 재시작과 기기 재부팅 후 각각 재확인

네이티브 플러그인이 추가되었으므로 테스트 빌드 전 `pnpm android:sync` 또는
`pnpm ios:sync`를 반드시 실행한다. iOS 로컬 알림은 APNs 인증키나 Push
Notifications Capability가 필요하지 않으며, Mac과 Xcode에서 동기화한 새 앱
빌드를 설치한 뒤 실기기에서 권한·예약·알림 선택 동작을 확인한다.
