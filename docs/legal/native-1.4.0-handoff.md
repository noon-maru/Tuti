# 1.4.0 앱 업로드와 약관 서버 전환

## 이번 빌드

- Android 1.4.0 (12), iOS 1.4.0 (12).
- `release/` 승인 원문 네 개를 `src/shared/legal/finalizedDocuments.json`으로 포함한다.
- 앱 빌드 전 승인 원문·해시·묶음 전체가 일치하는지 검사한다.
- 일반약관은 서버가 제공하는 실제 적용 원문·해시로 동의한다. 알려진 확정 버전의 다른 원문은 거부한다.
- 새 방침·위치약관·공개정책과 별도 동의 버전은 서버의 적용 메타데이터로 함께 선택한다.

## 앱 심사 전

운영 서버를 바꾸지 않는다. 운영의 구서버 응답에는 새 메타데이터가 없으므로 기존 방침과 위치·공개 동의 버전으로 동작한다. 새 앱 설치·스토어 업로드 자체가 새 약관 시행이나 동의가 아니다.

스토어 업로드는 Android 내부 테스트 트랙과 App Store Connect 빌드 업로드까지다. 심사 제출·공개 출시는 운영자가 진행한다. 업로드 뒤 위치 허용/거부, 로그인·탈퇴, 기록·공유·기록집을 실제 기기에서 확인하고 심사 정보·개인정보 수집 항목을 대조한다.

심사 메모에는 위치 없이 이용 가능한 흐름과 계정 삭제 경로를 안내하고, 새 일반약관 화면은 앱 출시 후 서버의 적용 원문·강제 설정에 맞춰 전환되는 사실을 설명한다. 이번 업로드가 이미 그 전환을 실행했다고 표시하지 않는다.

## 앱 출시 후 별도 승인할 서버 전환

1. 실제 공고 등록·시행 시점·기존 이용자 처리·필요한 통지를 확인한다. 기존에 정한 공고/시행 준비 절차는 이 파일로 생략하지 않는다.
2. 승인 원문으로 일반약관 실제 적용 릴리스를 등록한다. 공고 모델만 등록한 것은 적용 릴리스가 아니다.
3. 새 앱 보급·권리 행사 경로와 강제 설정을 확인하고 서버 배포 및 전환을 별도 진행한다.
4. 실제 시행 시각 이후에만 서버 환경을 명시적으로 설정한다.

```dotenv
TUTI_LEGAL_POLICY_RELEASE=2026-10-22
TUTI_LEGAL_POLICY_EFFECTIVE_AT=<실제 시행 ISO 시각과 시간대>
```

`2026-10-22`는 원문 편집 버전이다. 그 날짜를 실제 공고일·시행일로 소급하지 않는다. 환경이 비어 있으면 기존 문서·동의 버전이 유지된다. 날짜만 설정하거나 시간이 흐르는 것만으로 전환하지 않는다. 지원하지 않는 버전, 빠진 시행 시각, 미래 시각으로 활성화한 설정은 거부한다. 새 메타데이터는 일반약관 적용 릴리스의 버전·해시와 일치해야 제공된다.

위치 동의 중 또는 공개 동의 중 버전이 변경되면 새 원문에 자동 동의시키지 않는다. 다시 읽고 체크해야 하며, 과거 버전 동의로 새 위치 처리·기록 공개를 허용하지 않는다. 기존 공개 링크에는 새 정책 동의 버전 검사가 적용되므로 기존 공개 기록의 재동의·비공개 처리 범위도 전환 전에 확인한다.

이번 작업은 운영 배포·환경 변경·계정 삭제·공고 등록·심사 제출을 실행하지 않는다. 개인정보 처리방침 원문이 기기에 포함된 것과 해당 방침이 실제 시행된 것은 구분한다.
