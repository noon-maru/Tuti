## 민감정보·국외 이전·운영 이행 보강 — 2026-10-19

운영자는 본인의 비공개 기록·개인용 기록집에 민감정보가 포함되는 이용은 허용하되,
해당 기록의 웹 공개는 제한하는 방향을 확정했다. 개인정보·일반약관·공개 정책 초안에
같은 경계를 반영했다. 비공개 보관도 회사의 개인정보 처리이므로 별도 선택 동의의
항목·목적·기간·거부 영향과 철회·서버 기록집 정리를 분리한다. 공개 전 경고와 공개
동의는 민감정보 처리 동의가 아니며, 본인 기록이라는 사실로 이를 생략하지 않는다.

별도 동의·철회와 공개 제한은 2026-10-20 로컬 구현했으며 기본 비활성이다.

목적·보관기간과 거부 효과를 구분했다. FCM의 기본 메시지 유효기간 최대 4주,
APNs의 미전달 알림 보관 최대 30일과 Firebase 설치 ID 삭제 후 최대 180일은
서로 다른 대상이다. 등록 토큰 해제와 설치 ID 삭제도 별개다. 일반 개인정보의
모든 보관기간이 180일이거나 알림을 끄면 외부 자료가 즉시 전부 지워진다고 쓰지 않는다.
글로벌 처리 국가 목록, 적용 계약과 법적 근거 및 APNs 토큰·운영기록 기간 등은

## 현행 코드에서 별도로 수정한 오류

10월 10일 시행이 끝난 사전 알림을 앱 셸에서 제거했다. 현재 방침은
`privacyPolicyFrom20261010`을 최초 서버 HTML부터 표시하고, 기기 시계에 따라
개정 전 방침으로 돌아가지 않도록 했다. 신규 초안의 시행과는 별개이며,
위치약관 버전·공개 정책 동의 버전은 변경하지 않았다.

2026-10-19 코드 보강은 새 약관 시행과 구분한다.

- 위치 전부 철회 시 해당 이용·제공사실 확인자료와 과거 위치 동의 이력을 같은
  트랜잭션에서 파기한다. 재이용 방지를 위한 현재 철회 상태만 남긴다.
- 구버전 약관으로도 철회·중지를 요청할 수 있다. 구버전의 새 동의는 허용하지 않는다.
- 새 이용 로그와 철회를 DB 사용자 행 잠금으로 직렬화하고, 후속 외부 전달 기록 전
  현재 동의를 재검증한다. 이미 전송을 시작한 외부 요청을 회수하는 기능은 아니다.
- 계정 삭제 때 위치 확인자료를 임의 식별자로 계속 보관하던 처리를 제거했다.
- 위치 요청 결과가 철회 후 도착하면 클라이언트에 반영하지 않고 관련 쿼리를 취소한다.

#### 코드·운영 관측·운영 승인 분리

`pnpm legal:operations:inspect`는 현재 접속한 DB를 읽기 전용 Repeatable Read
트랜잭션으로 조회한다. 개인별 식별값·연락처·문서 본문 없이 다음 집계만 반환한다.

- 일반약관: 활성 설정, 현재/예정 공고 유무, 원문 해시 정합성, 전체 계정 수,
  현재 버전·원문 해시에 일치하고 연령·중요 내용 확인이 있는 동의 수와 미동의 수
- 전환 단계: 비활성 / 공고 없음 / 사전 공고 / 시행했으나 접근 제한 비활성 / 접근 제한 중
- 권리 보호: 기능이 꺼져 있어도 잔존 사건·검토 기한 도래·미완료 통지와 분류 전 신고 수
- 마지막으로 정상 종료한 적용 점검의 시각과 최근 5분 관측 여부. 미래 시각은 인정하지 않음

DB 연결·미적용 테이블 등으로 확인할 수 없으면 `unavailable`과 종료 코드 2를
반환하며 0건으로 숨기지 않는다. 단순 신고를 법정 신청으로 단정하지 않는다.
0건·플래그·최근 실행만으로 UI 제시·법정 통지·담당자 대응을 승인하지 않는다.
`operationalCompletionVerified`, `schedulerInstallationVerified`,
`formalNoticeDeliveryVerified`, `clientRolloutVerified`는 이 도구로 true가 되지 않는다.

`legal:rights:maintain --apply`의 점검 적용과 알림 시도가 정상 반환되면 최신 성공
시각 1건을 시스템 로그에 갱신한다. 조회·실패 실행은 성공 시각을 갱신하지 않는다.
이는 실제 스케줄러 설치나 웹훅·법정 통지의 전달 증거는 아니다. 알림 비활성 상태로
정상 반환한 경우도 있으므로 설정·예약 작업·실제 전달 근거를 별도로 대조한다.

설치·커밋·운영 배포 후에는 root 소유 고정 래퍼
`/usr/local/sbin/tuti-legal-operations-inspect`로 배포된 ops 이미지에서 조회할 수 있다.
임의 인자·마이그레이션·통지·동의 생성은 허용하지 않는다. 로컬 명령이 운영 DB에
연결된다고 추정하지 않으며, 이번 작업에서 운영 설치·활성화·배포는 실행하지 않았다.

일반약관의 공고 전 `SERVICE_TERMS_ENFORCEMENT_ENABLED=false`는 사전 공고를 위한
정상 단계일 수 있다. 이를 동의 전환 완료로 표시하거나 준비 검사를 통과시키기 위해
공고 전에 접근 제한을 강제로 활성화하지 않는다.
실제 공고의 준비 검사는 DB 원문 정합성과 권리 보호 절차의 최근 5분 내 정상 적용
실행도 대조한다. 수동 확인 칸만 true로 바꾸어 최근 실행 누락을 우회하지 않는다.
이 추가 검사를 통과해도 예약 설치·실제 법정 통지·전체 운영 승인을 대신하지 않는다.

이번 보강의 로컬 검증은 단위 시험 357개와 분리 PostgreSQL 11.11 시험 9개 통과다.
실제 ORM의 읽기 전용 관측·최신 실행 기록과 원본 시험 DB 보존도 확인했다.
연결 실패 시에는 `unavailable`·종료 코드 2를 반환하고, 미확정 대장의 엄격 검사는
계속 `ready=false`·종료 코드 2로 차단된다. 운영 PG17·예약 작업·실기기 검증은 아니다.

`pnpm legal:readiness`는 확인 대장과 현재 프로세스의 설정을 대조한다. 비밀키·테스트
이메일·서버 주소는 출력하지 않는다. `--strict`는 미확인 항목이 있으면 실패한다.
이 명령만으로 실행 중 컨테이너·DSM 예약 작업·실제 DB·법률 검토를 검증했다고 하지 않는다.

2026-10-20 후속 수정으로 점검 범위를 분리했다. 기본값은 기존과 같은 전체 검사다.

```sh
pnpm legal:readiness --scope=all --strict
pnpm legal:readiness --scope=service-terms --strict
pnpm legal:readiness --scope=push --strict
```

`ready`는 선택한 범위의 결과이며 `allReady`는 전체 결과다. 각 범위의 차단 사유와
`unresolvedOutsideScope`도 함께 출력해 일반약관만 통과한 것을 전체 준비 완료로 표시하지 않는다.
범위 오타·중복 옵션은 실패하며, 푸시 서버 발송을 끈 것만으로 푸시 확인을 생략하지 않는다.

실제 일반약관 공고 경로는 `service-terms` 범위를 고정해 사용한다. 미확정 Google·Apple
국가·기간·이전 근거는 이 공고만 막는 사유에서 분리하고 공고 결과에 계속 표시한다.
문서 해시·승인 근거, 원장·미완료 요청, DB 제약·최근 권리 보호 점검 등 기존 검사는 유지한다.
`checks` 및 공고 문서의 `readiness`는 일반약관 원문과 이에 필요한 운영·동의 전환의
확인이다. `processorsAndTransfers`는 이 문서가 규정하는 처리 관계, `nativeClientRollout`은
일반약관의 제시·동의·권리 행사 경로를 확인하며, 푸시의 미확인 국가·기기 검증을 승인하지 않는다.
푸시 고지·이전 근거·기기 검증은 `pushTransferReview`로 별도 관리한다.

2026-10-20 FCM 지원 답신과 표준 약관을 대조해 Google LLC, 설치 ID·연결 토큰 삭제,
알림 내용·기술 로그의 서로 다른 보관 기준을 개인정보 초안 7절과 준비 대장에 반영했다.
별도 선택 동의를 우선 설계 경로로 두되 실제 동의 확보나 국가 안내 적정성을 승인한 것은 아니다.
개별 패킷 경유국·정확한 삭제 시각의 전수 확인을 요구하지 않는다. 남은 법률 검토는
확보한 글로벌 처리 설명과 공개 시설 범위를 이용한 국가 고지 방식의 적정성에 한정한다.
이를 이유로 일반약관 공고를 일괄 차단하거나, 반대로 푸시 이전까지 적법성 확인이
완료됐다고 표시하지 않는다. Apple에 Google 답신을 적용하지 않는다.

이 분리는 일반약관 공고가 개인정보방침 개정·민감정보 처리 동의·푸시 국외 이전 동의를
대신한다는 뜻이 아니다. 이미 운영 중인 푸시의 확인 의무를 유예하거나 발송·SDK 설정을
자동으로 변경하지 않는다. 이번 코드 변경에서 수동 확인·승인 해시·환경변수는 변경하지 않았다.

실제 공고 명령에는 `--readiness-file docs/legal/readiness-status.json`이 추가로 필요하다.
최종 승인 원문 해시·승인 근거가 일치해야 하고, 운영 기능 설정·원장 상태·새 테이블과
공고 변경 방지 DB 트리거도 검사한다. 최종 원문이 바뀌면 새 해시로 다시 승인한다.

## 관리자 기록 조회 감사 보존 보강

위치 철회의 파생자료·캐시·지연 요청 및 복원 재반영 보강은
[삭제·철회 복원 방지 운영](privacy-replay-operations.md#위치-철회-파기-보강--2026-10-19)에 정리했다.
로컬 구현·검증과 운영 NAS의 전체 파기 입증은 구분하며, 운영 준비 항목을 자동 승인하지 않는다.

`20261019140000_add_admin_journal_access_audits`는 관리자 기록 조회 증거를 전용
`admin_journal_access_audits` 테이블에 분리한다. User/기록 FK를 두지 않아 대상자나
관리자 계정 삭제가 접근 증거를 함께 지우지 않는다. 기존 일반 로그에서 관리자·대상
식별값, 당시 사유·처리 번호, 조회한 기록 식별값·시각만 복사하고 본문·사진·이메일은
추가 보관하지 않는다. 이미 삭제된 과거 로그를 복구하거나 누락 사유를 만들어 채우지 않는다.

자유 기록의 민감정보 포함 가능성을 고려해 이 접근 증거만 조회 시점부터 보수적으로
2년 보존한다. 계정 삭제·후속 요청으로 기간을 다시 시작하지 않는다. DB는 변경·기간 전
삭제·TRUNCATE를 거절하며, 기존 인증자료 정리 작업이 기간 만료 후 전용 기록과 같은
범위의 구형 일반 로그를 파기한다. 구버전 서버가 일반 로그만 남겨도 INSERT 트리거로
보존본이 생성된다. 최신 조회 API는 보존본 생성 실패 시 기록 내용을 반환하지 않는다.

운영 적용에는 마이그레이션이 필요하며, 실제 설치·예약 실행을 확인한 것은 아니다.
이 보강만으로 법정 접속기록의 전체 항목·보호·점검 의무나 백업 복구 후 보존까지 모두
검증한 것으로 취급하지 않는다. 법정 2년 적용 여부의 확정과 보유기간 고지는 별도 검토한다.

## 일반약관 전환 구현

- `SERVICE_TERMS_WORKFLOW_ENABLED=false`가 기본값. 비활성 시 동의를 요구하지 않고
  새 약관 테이블도 조회하지 않는다. 실제 `.env` 값은 변경하지 않았다.

  공고 후 호환성 장애 시에는 이 제한만 해제하고 WORKFLOW는 유지한다. 공고 문서·
  동의 영수증·동의 저장을 숨기거나 동의한 것으로 바꾸지 않는다. 두 플래그를 지원하지
  않는 최초 도입 이전 리비전은 별도 호환성 확인이 필요하며, 플래그만으로 구버전에

권리 서비스 첫 성공 실행 후 타이머 활성화 순으로 한다. 기존 일반약관·민감정보
플래그나 원장 키는 바꾸지 않는다. 권리 타이머가 보내는 운영 Slack 알림은 당사자에게
법정 서식·첨부를 실제 전달한 통지가 아니므로 전달 시험·공시는 별도 완료해야 한다.

남은 전환 순서는 다음과 같다.

1. 운영 권리 사건·미통지·미분류 신고와 전용 알림 설정 확인.
2. 담당자 연락 공시·법정 서식·첨부 및 통지 전달 시험. 실제 이용자 대상 모의 사건을 만들지 않는다.
3. 권리 workflow·전용 알림·첫 실제 유지보수 성공을 확인한 뒤 권리 타이머 활성화.
4. 웹·신규/기존/구버전 앱의 동의·거절·삭제·문의와 민감정보 전환 실기기 검증.
5. 최종 원문·중요 변경 요약·승인 근거·해시·공고/시행일 승인 후 공고 dry-run.
   추가 전문가 검토 유보를 적법성 검토 완료나 전체 문서 승인으로 바꿔 기록하지 않는다.

새 문서 공고·시행이나 기존 이용자 동의 생성, 운영 권리 플래그 활성화는 이번 검증에서 하지 않았다.

- 현행 문서: `src/shared/legal/`, `src/shared/location/terms.ts`
- 비공개 기록 조회·감사: `src/app/api/admin/user-journals/route.ts`
- 제품 활동 180일: `src/app/api/product-activity/route.ts`
- 보안 식별정보 90일: `src/server/security/trafficSecurity.ts`, `src/server/auth/retention.ts`
- 신고·운영조치 3년: `src/server/journal/moderationRetention.ts`
- 계정 삭제: `src/server/admin/users.ts`
- 백업: [운영 문서](../operations.md#전체-백업과-복구)
- 기록집: [디지털 기록집](../journal-books.md)
- AI: [LLM 개인화 운영 원칙](../llm-personalization.md)

불공정 면책, 부당한 해지·급부 변경, 의사표시 의제와 관할 제한의 검토 기준은
[약관규제법 제7조부터 제14조](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1025032399)다.
공지·동의 절차는 [디지털콘텐츠 표준약관](https://www.law.go.kr/admRulLsInfoP.do?admRulSeq=2100000216089)을
참고하되 서비스 특성에 맞게 검토한다.

처리방침은 수집 동의를 대신하지 않는다. 실제 처리 근거와 공개사항은
[개인정보 보호법 제22조](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020399357),
[제30조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1032645945),
[개인정보위 2026년 작성지침](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS217&mCode=D010030000&nttId=12018)을
기준으로 확인한다. 목적 달성 후 파기와 법정 보존 분리는
[제21조](https://www.law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900078981)를 따른다.

향후 주문제작품의 철회 제한은 주문제작이라는 명칭만으로 성립하지 않는다.
[전자상거래법 시행령 제21조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0021&lsiSeq=288143&urlMode=lsScJoRltInfoR)의
요건과 별도 사전 고지·서면 또는 전자문서 동의를 확인한다.
