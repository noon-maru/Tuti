# 1.4.1 — 세션 정리 및 현행 약관 전용 진입

Android·iOS 모두 1.4.1(13). 스토어에 배포된 1.4.0에서 삭제된 계정의 세션이 남으면 동의 저장이 실패할 수 있었고, 운영자가 Android 재설치 후 정상 동작을 확인했다. 실제 실패 요청의 HTTP 코드는 확보되지 않았으므로 모든 저장 실패가 같은 원인이라고 단정하지 않는다.

## 변경 범위

- 네이티브 첫 세션 조회 전에 `tuti-session`·`tuti-initial-terms-pending`만 정리하고 완료 표시를 남긴다. 동시에 호출되어도 한 번 실행하며, 정리 실패는 완료로 표시하지 않는다. 이후 버전에서도 같은 완료 키를 유지해 반복 로그아웃하지 않는다. 웹에는 이 설치 마이그레이션을 실행하지 않는다.
- 전체 Preferences 초기화·계정 삭제·서버 동의 생성·자동 동의 재전송은 없다. 서버 기록·사진·기록집과 소유자별 로컬 초안·푸시 상태를 지우지 않는다.
- 이 정리는 기존 로그인 세션을 해제한다. 로그인 계정은 재인증하면 서버 자료를 다시 이용할 수 있다. 로그인 수단 없는 익명 계정은 이전 기록에 접근하지 못할 수 있다. 이는 기록을 삭제하지 않는다는 사실과 별개의 위험이며, 이후 업데이트의 일반 정책으로 재사용하지 않는다.
- 이후 동의 POST가 401이면 해당 세션만 비우고 필수 체크를 해제한 뒤 다시 확인하도록 안내한다. 새 계정 생성과 POST 재전송은 자동 수행하지 않는다. 다음 명시적 확인·클릭 때 새 요청을 시작한다. 다른 계정으로 바뀐 응답은 반영하지 않는다.
- 구서버 약관 응답을 통한 진입 허용·규약 협상과 재전송을 제거했다. API 요청은 처음부터 현행 규약·네이티브 버전 헤더를 보낸다. 시행 원문 없이는 통과하지 않으며 서버 강제 플래그가 꺼져도 동의 영수증을 대신하지 않는다.
- 정책 화면·위치 및 기록 공개 동의 버전은 확정 문서만 사용한다. 시행 시각 메타데이터는 계속 실제 서버 값으로 표시하고, 없을 때 편집일을 시행일로 표시하지 않는다. 원문 해시 검증과 현재 계정의 영수증 확인·권리 행사 경로는 유지한다.

## 출시 점검 범위

App Store review 스킬의 성능·로그인·개인정보 항목을 변경 범위에 대조해 재설치를 요구하지 않는 복구, 콘텐츠/초안 보존, 명시적 동의 유지, 로그인·권리 행사 경로를 점검한다. 새 권한·SDK·결제 기능을 추가하지 않는다. 자동 시험이나 코드 검토만으로 실제 iPhone/iPad·Android 업그레이드 시험 또는 심사 승인을 완료했다고 표시하지 않는다.

스토어 제출 전 1.4.0 설치 위에 업데이트하여 최초 1회 로그아웃·재로그인·직접 동의·재실행 시 세션 유지·이후 401 재확인과 익명 기록 접근 영향을 확인한다. 민감정보·위치·공개 동의는 일반약관 동의로 대신하지 않는다. 빌드 업로드와 공개 출시·심사 제출은 구분한다.
