운영자 승인 순서: 기존 기록 보관·검증 → 기존 계정 삭제 → 일반 계정 0개 등 최초 계약 적용 조건과 별도 운영 승인을 확인하여 실제 시행 → 새 심사용 계정 생성·새 약관에 명시적 동의 → 테스트 콘텐츠 신규 등록.

확인된 원본은 `openapi@tuti.today`에 연결된 일반 계정 `f0181f76-8ee4-43cc-b4c4-0d214afc4aeb`이며, 기록 3개·이미지 3개·기록집 0개다. 관리자는 이전·삭제 대상이 아니다. 이 확인 결과만으로 실제 서비스의 일반 계정이 0개라고 판단하지 않는다.

## 현재 구현한 단계: 보관과 검증만

```sh
sudo sh scripts/ops/tuti-reviewer-records-archive export
```

DB는 읽기 전용 트랜잭션으로 지정 ID·이메일·권한과 예상 개수를 확인한다. 기록 본문과 이미지의 별도 사본은 NAS `/volume1/tuti/backups/reviewer-transfer/<사본ID>`에 보관한다. 전용 폴더 0700, 파일 0600으로 제한하며 인증정보·로그인 수단·세션·기존 동의·공개 링크·원본 객체 키는 보관 문서에 넣지 않는다. 출처 기록 ID는 운영자 이전 확인용으로만 포함하고, 새 콘텐츠 생성 때 기존 ID를 재사용하지 않는다.

세 이미지의 바이트 수·SHA-256·전체 이미지 해독을 확인하고, 저장 파일·디렉터리를 fsync한 뒤 사본을 재조회한다. 보관 후 원본 스냅샷 해시도 다시 비교한다. 오류·누락·원본 변경·외부 이미지 URL·민감정보 확인 필요 상태면 실패한다. 새 사본은 기존 사본을 덮어쓰지 않으며 실패 사본도 자동 삭제하지 않는다. 원문·객체 키는 오류 로그에 출력하지 않는다.

```sh
sudo sh scripts/ops/tuti-reviewer-records-archive verify-with-source <사본ID>
sudo sh scripts/ops/tuti-reviewer-records-archive verify <사본ID>
```

첫 명령은 삭제 전 원본과 사본 비교용, 두 번째는 원본 삭제 후에도 가능한 사본 자체 검증용이다. 두 검증 명령의 사본 마운트는 읽기 전용이다. 사본 SHA-256은 실행 결과로 별도 확인한다. 해시는 무결성 대조용이며 서명된 적법성·승인 증거를 대신하지 않는다.

## 이후 별도 실행할 단계

- 삭제 직전에 사본 ID·해시·원본 일치를 다시 확인하고 승인한 계정 ID만 삭제한다. 삭제 원장과 기존 자산·세션 정리 절차를 따른다. DB나 객체를 과거 ID로 복원하지 않는다.
- 기존 심사용 로그인 설정으로 옛 계정이 재생성되거나 다른 일반 계정이 등록되는 경합을 통제하면서 최초 약관 릴리스·운영 준비·고지·동의 전환 조건을 확인한다. 이메일 변경이나 테스트 계정 삭제만으로 법적 요건이 자동 충족되는 것은 아니다.
- 새 심사용 이메일과 인증정보, 계정 생성·명시적 동의 후의 대상 ID를 확정한다. 심사용이라는 이유로 관리자 권한이나 자동 동의를 부여하지 않는다. App Store Connect의 심사 로그인 정보도 실제 새 로그인과 맞춘다.
- 새 기록 ID·새 이미지 객체 키로 비공개 테스트 콘텐츠를 등록한다. 예전 세션·동의·공개 상태·링크·민감정보 동의를 복사하지 않는다. 기존 기록의 저작권·표시 조건을 유지한다. 현재 도구에는 가져오기 기능이 없으며 실제 대상 확인 후 별도 구현·검증한다.
- 신규 등록과 이미지 확인이 끝나면 이전용 사본을 정리한다. 사본의 `reviewBy`는 생성 30일 뒤의 수동 검토 기한이며 자동 파기를 뜻하지 않는다. 이 전용 이전 사본은 기존 full/core 자동 정리 대상이 아니므로 지연 시 운영자가 기한과 필요성을 확인해야 한다.

현재 보관 도구는 계정 삭제·새 계정 생성·환경 변경·새 약관 시행·기록 가져오기를 실행하지 않는다.

## 최초 적용 등록 도구

```sh
sudo sh scripts/ops/tuti-initial-terms-release --check
```

조회 모드는 DB·원장을 변경하지 않는다. 커밋된 승인 기록과 실행 이미지의 묶음 원문·해시, 준비 검사, 미완료 원장, 최근 권리 작업, 불변성/최초 적용 트리거, 일반 계정·릴리스·공고 각 0개를 확인한다. 새 동의나 강제 플래그는 만들지 않는다.

실제 등록은 조회 결과 확인 후 아래 별도 명시적 승인으로만 가능하다.

```sh
sudo sh scripts/ops/tuti-initial-terms-release --apply --approve-initial-contract
```

`--approve-initial-contract`는 단순 실행 옵션이 아니라 운영자가 테스트 이용 종료·기존 계약과 고지/보존 의무 검토·향후 신규 계약에 한정한 최초 적용을 승인한다는 뜻이다. 일반 계정 0개나 자동 검사만으로 이 운영 판단을 대신하지 않는다. 승인하지 않았다면 실행하지 않는다. 실행 시각으로 서비스 이용약관의 최초 적용 릴리스를 등록하므로 과거 편집 날짜로 시행을 소급하지 않는다. 등록 트랜잭션에서 계정 테이블·공고 잠금과 각 건수를 다시 확인한다.

이 도구는 일반약관 적용 릴리스만 등록한다. 네 문서의 별도 공고 기록, 방침 적용 메타데이터, 강제 동의 설정, 관리자/새 심사용 계정의 동의, 실기기 전환 확인은 후속 단계다. 기존 약관·동의 데이터 수정이나 앱 재배포는 수행하지 않는다.
