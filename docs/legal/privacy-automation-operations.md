# 개인정보 보관·민감정보·운영 자동화

기준일: 2026-10-20. 서버 코드는 `13337f4`로 운영 배포되었으나 예약 작업 설치·활성화와
실기기·실제 운영 백업의 복구 시험은 미완료다. 아래 임시 환경 시험과 구분한다.
새 약관 공고·시행, 운영 환경변수 변경과 실제 운영 자료 파기는 실행하지 않았다.

## 1. 푸시 보관·파기

- 무효 응답을 받은 토큰은 `id + 발송 당시 token` 조건으로 삭제한다. 같은 설치가
  새 토큰으로 갱신된 경우 새 등록을 삭제하지 않는다. 무효 결과에는 기기 FK를 남기지 않는다.
- 새 전달 이력에는 문의 ID·제공자 오류 원문을 저장하지 않는다. 플랫폼·제공자·알림 유형,
  결과·허용한 오류 코드·시각과 사용자/기기 연결만 장애 확인 목적으로 저장한다.
- 전달 이력은 생성 후 30일 기준으로 정기 파기한다. 이는 Google·Apple의 보관기간이 아니다.
  계정 삭제에서는 해당 사용자에 연결된 전달 이력도 같은 DB 트랜잭션으로 삭제한다.
- 적용 정리 작업은 과거 비활성/무효 토큰을 삭제하고 남은 이력의 문의 ID·오류 원문을 제거한다.
  단순 조회는 변경하지 않는다. 과거 탈퇴로 사용자 연결을 이미 잃은 자료도 30일 정리 대상이다.
- 실제 실행 전에는 기존 자료가 남아 있다. 백업·외부 제공자 자료까지 즉시 삭제된다고 표시하지 않는다.
- 운영 DB 복원 후 재개 전에는 과거 서버 푸시 등록을 전부 초기화하고 정기 파기·철회 정리를
  실행한다. 알림을 끈 연결을 백업에서 되살리지 않는다. 알림을 켠 최신 앱은 자신의 현재
  선택을 확인한 뒤 재연결한다. 새 스키마·ops가 없거나 정리에 실패하면 재개를 보류한다.

```sh
pnpm push:retention:purge
pnpm push:retention:purge --apply
```

로컬 CLI가 운영 DB에 연결된다고 가정하지 않는다. 운영은 설치된 고정 래퍼를 사용한다.
5분 간격의 정상 실행을 기준으로 하며 장애 시 파기 완료를 보장하지 않는다. 실패 알림 확인이 필요하다.

## 2. 민감정보의 비공개 기록·기록집

`SENSITIVE_JOURNAL_WORKFLOW_ENABLED` 기본값은 false다. `.env.example`만 추가했다.
실제 공고·문서 승인, 백업·원장 준비와 신규/구버전 클라이언트 검증 후 활성화한다.

- 기록 작성·수정에서 본인의 민감정보 포함 여부를 선택한다. 포함하는 경우 항목·목적·기간·
  거부 영향·철회 경로를 알리고 별도 선택 동의를 받는다. 체크는 미리 선택하지 않는다.
- 서버는 해당 기록에 동의 버전·서버 시각을 저장한다. 일반약관·위치·공개 동의와 합치지 않는다.
  미동의·구버전 동의·분류 누락은 저장하지 않는다. 동의 누락은 사진 업로드 준비 전에 거절한다.
- 복원 방지 원장 활성화 없이 민감정보 저장·기록집 제작을 허용하지 않는다.
  환경변수만으로 원장 초기화·서명 검증이 끝났다고 취급하지 않는다.
- 포함한다고 분류한 기록은 웹 공개할 수 없다. 공개 중인 기록을 민감정보 기록으로 수정하면
  같은 DB 쓰기에서 링크를 제거한다. 공개 HTML·본문·이미지 경로가 동일한 조건으로 차단한다.
- 기존 기록의 분류는 NULL로 남긴다. 활성화 후 기존 미확인 기록의 웹 공개와 기록집 재생성은
  확인 전 제한한다. 작성자가 비공개 원본을 열어 수정·확인하거나 삭제할 수는 있다.
- 자동 텍스트 분석·사진 검사·LLM 전송은 추가하지 않았다. 이용자의 표시와 별도 동의에 따른 통제이며,
  허위 표시나 미신고 민감정보를 완벽하게 탐지·차단하는 시스템은 아니다. 신고·수동 검토도 필요하다.
- 타인의 민감정보·고유식별정보는 이 동의에 포함하지 않는다. 일상 감정·일반 사진을 모두
  민감정보로 취급하지 않는다.

### 기록집의 추가 입력과 기존 PDF

표지 제목·‘이 공간에 남기는 말’은 민감정보를 새로 수집하는 별도 동의 화면이 아니다.
해당 입력에 민감정보가 없음을 확인하고, 민감정보는 별도 동의한 기록에서만 가져온다.
민감정보를 기록집 자유 입력에 직접 쓰는 기능은 허용하지 않는다.

새 정책 확인을 거치지 않은 기존 PDF는 활성화 후 바로 열리지 않는다. 원본 기록을 확인하고
기록집을 다시 만들어야 한다. 이 전환은 이용자 영향이 있으므로 사전 안내·구버전 앱 검증 전
활성화하지 않는다. 과거 PDF에 소급 동의를 생성하지 않는다.

미리보기 승인은 버전 2로 변경했다. 렌더 시작 시각과 기록 보호 확인을 서명에 묶고,
완성 시 DB 행 잠금 후 기록의 존재·최신 수정 시각·철회 상태·동의 상태를 재확인한다.
수정·철회 전 PDF의 재업로드나 렌더 중 철회로 서버 기록집을 다시 만들 수 없게 한다.
배포 시 이미 열어 둔 버전 1 미리보기는 다시 생성해야 한다.

### 철회·삭제

기록 상세 메뉴의 ‘민감정보 동의 철회’를 사용한다. 철회와 함께 해당 기록·사진 및
이를 포함한 서버 기록집 전체를 삭제한다는 확인을 먼저 받는다. 문의 창구도 유지한다.

1. 별도 원장에 `journal_sensitive_withdrawn` 의무를 준비한다.
2. DB에 철회 시각을 표시하고 공개를 중지하며 원문·장소·태그는 먼저 지운다.
   파일 정리에 필요한 사진 키·소유자/기록 ID만 남기고 수정·이미지·관리자 본문 조회·기록집 재생성을 막는다.
3. 철회 의무를 원장에 확정한다. 이는 파일 삭제 완료 증명이 아니라 복구 후 재이행할 요청이다.
4. 연관 기록집의 파일·행, 기록 사진과 원본·공유 추적자료를 정리한다.
5. 파일 정리가 실패하면 202 응답과 대기 안내를 반환한다. 철회 상태를 되돌리지 않고
   5분 정리 작업에서 재시도한다. 같은 메뉴에서 수동 재시도할 수도 있다.

현재 기록을 일반 기록으로 재분류해 과거 민감정보 PDF의 동의 근거를 없애지 않는다.
일반 기록으로 바꾸려면 철회·삭제 후 민감정보를 뺀 새 기록으로 남긴다.
이미 다운로드·외부 공유·브라우저에 보관된 사본이나 이미 전송을 시작한 응답은 원격 회수하지 못한다.

복구 재반영은 민감정보 철회 원본과 연관 PDF도 대상으로 한다. 원장에 새 요청 종류가 생기므로
이 요청을 처리하지 못하는 구버전 ops/서버로 단순 롤백하지 않는다. 호환 이미지 유지 또는
서비스 중지 후 재반영이 필요하며, 원장을 비우거나 플래그를 꺼서 우회하지 않는다.

## 3. NAS 예약 작업

운영 도구·unit 원본을 검토·커밋하고 새 서버/ops 이미지·DB 마이그레이션을 배포한 다음 설치한다.
설치기는 미커밋 원본·심볼릭 링크 교체를 거절하고 이전 설치본을 보관한다.
타이머 설치는 실행·활성화와 분리한다. root 작업이 필요하며 이번에는 실행하지 않았다.

```sh
sh scripts/ops/install-legal-compliance-tools
sudo sh scripts/ops/install-legal-compliance-tools --apply
sh scripts/ops/install-legal-compliance-timers
sudo sh scripts/ops/install-legal-compliance-timers --apply
```

| 예약 작업 | 주기 | 실행 내용 |
| --- | --- | --- |
| tuti-journal-rights.timer | 종료 후 1분 | 기존 권리 침해 기한·통지 확인, 담당 알림 |
| tuti-privacy-maintenance.timer | 종료 후 5분 | 무효 토큰·30일 전달 이력 정리, 철회한 기록·PDF 재시도 |
| tuti-backup-retention.timer | 종료 후 1시간 | 전용 백업 manifest 기준 30일 초과 정리 |

작업은 NAS에서 빌드하지 않고 배포된 ops 이미지를 사용한다. 유지보수 잠금과
복원 확인 대기를 존중하고 같은 작업의 중복 실행을 막는다. 30일·5분은 정상 작동 시의
운영 기준이며 처리 시간·중단·실패를 숨긴 엄격한 완료 보장은 아니다.

실패 시 NAS 로그와 실패 unit을 남기고 `LEGAL_RIGHTS_ALERT_WEBHOOK_URL`로 식별정보 없는
고정 실패 알림을 보낸다. Docker 자체가 내려갔거나 네트워크가 끊기면 외부 알림도 실패할 수 있어
NAS 로그 확인이 필요하다. 알림을 수신한 사실은 확인 전 자동 승인하지 않는다.

### 활성화 직전 순서 — 이번 작업에서 실행하지 않음

1. 신규 마이그레이션과 서버/ops 이미지, 신규 앱의 호환성을 확인한다.
2. 원장 소유권·키·초기화 및 백업 경로·잔존 파일을 조회 전용으로 확인한다.
3. 백업 파기 후보 목록을 검토한다. 스냅샷·별도 복제본은 전용 백업 폴더 정리로 삭제되지 않는다.
4. 분리된 환경에서 복구 후 재반영을 확인하고 승인 근거를 남긴다.
5. 권리 침해 서식·담당 절차·실제 전달 수단을 준비하고 알림 수신을 확인한다.
6. 그 후 아래 타이머를 활성화한다. 이 단계는 실제 운영 쓰기·파기를 시작한다.

```sh
sudo systemctl enable tuti-journal-rights.timer tuti-privacy-maintenance.timer tuti-backup-retention.timer
sudo systemctl start tuti-journal-rights.timer tuti-privacy-maintenance.timer tuti-backup-retention.timer
```

## 4. 권리 침해 대응의 담당 작업

담당: 정연한 / 운영 / 대표. 접수: admin@tuti.today. 팩스 없음.
기존 `/admin/journal-rights`에서 실제 소명·서식 확인 후 사건을 등록한다.

| 순서 | 담당자가 확인·보관할 근거 | 자동 처리 |
| --- | --- | --- |
| 접수·분류 | 실제 접수일, 신청인 자격·권리 소명, 해당 공개 기록, 사생활/저작권 구분 | 형식·권한 검사 |
| 공개 제한 | 조치 사유와 적용 절차, 필요한 법정 신청 서식·첨부 | 승인한 사건의 공개 본문·사진 차단 |
| 통지 | 대상, 전달 시각·수단·근거 번호, 필요한 원 신청서 사본·첨부 | 통지 할 일·기한 생성 |
| 재개·이의 | 실제 재개 요청·소 제기 통보, 소명 검토와 필요한 사전 통지 | 통지 확인 조건을 충족한 재개·기한 알림 |
| 종결 | 실제 조치·전달 완료 근거, 사건별 보전 필요성 | 기존 보관·파기 작업과 연동 |

아직 없는 신청·통지 자료를 만든 것처럼 완료 표시하지 않는다. 법정 서식은 해당 법령의
현행 별지 원본을 사용하고, 일반 이메일 문안만으로 갈음하지 않는다. 현행 서식·첨부의
적합성 판단은 보류한 법률 검토와 실제 접수 자료를 통해 확인한다.
일반 SMTP 발송 성공을 법정 통지 완료로 자동 처리하지 않는다.

자동화는 사건 판단·최종 승인·실제 서식 전달을 대신하지 않는다. 운영 담당자가 확인할 수
있는 할 일·재시도·기한 알림을 구현한 것이며 실제 사건 처리 완료를 뜻하지 않는다.

## 5. 검증 보류와 남은 승인

운영 배포의 전체 단위 테스트는 통과했고, 아래 범위의 추가 검증을 수행했다.
운영과 동일한 PostgreSQL 17의 재검증·실기기·실제 NAS 백업 복구와 스케줄러 작동 검증은 별도로 진행한다.
준비 대장의 수동 확인·법률 검토·승인 해시를 true/확정값으로 바꾸지 않는다.
Google·Apple 문의 답변, 나머지 처리 목록·보유기간 확정과 최종 공고·시행 일정도 별도다.

기존 PostgreSQL 17 CI 실행 `39376742373`은 ORM 클라이언트 생성 단계 누락으로 실패했다.
검증 작업에 `pnpm db:generate`를 추가했으며, 이 변경의 커밋·푸시 후 PostgreSQL 17 CI 재실행이 필요하다.
로컬 PostgreSQL 11 성공을 PostgreSQL 17 검증 완료로 갈음하지 않는다.

조회 시점의 운영 환경 파일에는 원장 서명 키와 `LEGAL_RIGHTS_ALERT_WEBHOOK_URL`이 설정되어 있지 않다.
원장 호스트 폴더는 비어 있는 0700, UID 1026 소유이며 앱 UID 1000의 접근 준비가 끝나지 않았다.
새 타이머·조회 도구도 미설치 상태다. 실제 컨테이너 설정과 알림 수신은 설치 후 다시 확인해야 한다.

현재 비밀번호 없는 sudo 허용 목록에는 새 조회 도구·설치기가 없고 Docker 직접 접근도 거절된다.
따라서 운영 DB의 삭제 후보 건수, root 전용 백업 폴더의 30일 초과 목록·잔존 복제본은 조회하지 못했다.
0건 또는 검증 완료로 기록하지 않는다. 운영자 권한으로 검토한 도구를 설치한 후 다음을 인자 없이 실행한다.
아래 명령은 적용·삭제 플래그를 전달하지 않는다.

```sh
sudo /usr/local/sbin/tuti-legal-operations-inspect
sudo /usr/local/sbin/tuti-privacy-data-maintain
sudo /usr/local/sbin/tuti-prod-backup-prune
```

실제 백업 복구·재반영은 운영 DB를 덮어쓰는 `tuti-prod-restore`로 시험하지 않는다.
별도 PostgreSQL 17·격리 객체 저장소·외부와 격리한 알림 설정을 준비하여 추가 확인한다.
이 문서의 임시 자료 삭제는 테스트가 생성한 자료에만 한정되며 실제 사용자 자료·NAS 백업은 삭제하지 않았다.
