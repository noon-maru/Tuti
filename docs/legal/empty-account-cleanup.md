# 기록 없는 일반 계정의 제한적 초기화

2026-10-23 운영자 승인 범위: 조회된 일반 계정 206개 중 기록·기록집이 없는 202개부터 정리한다. 관리자 7개와 기록을 가진 일반 계정 4개는 유지한다. 과거 생성 기준은 조회 목록의 마지막 생성 시각인 `2026-10-22T07:51:55.612Z`로 고정하며 이후 새 계정은 포함하지 않는다.

## 조회

```sh
sudo sh scripts/ops/tuti-empty-account-cleanup --created-before 2026-10-22T07:51:55.612Z --expected-count 202
```

삭제 없는 조회다. 출력된 대상 수와 `planHash`를 확인한다. 수가 다르면 적용하지 않고 다시 목록을 확인한다. 계정·토큰·기록 원문은 출력하지 않는다.

## 적용

배포 전 백업이 정상 생성되었는지 확인하고, 필요하면 기존 백업 도구로 별도 백업을 먼저 생성한다. 조회에서 확인한 해시만 사용한다.

```sh
sudo sh scripts/ops/tuti-empty-account-cleanup --created-before 2026-10-22T07:51:55.612Z --expected-count 202 --plan-hash <조회된해시> --apply
```

실행 도구는 배포와 같은 유지보수 잠금을 사용한다. 적용 직전 대상 수·해시와 삭제 원장의 미해결 항목을 검사한다. 계정별로 사용자 행을 잠그고 관리자 여부·생성 시점·기록·기록집을 다시 검사한다. 사이에 기록이 생기거나 승격된 계정은 건너뛰며, 기존 계정 삭제 경로로 위치 확인자료·인증·관련 이력을 정리한다. 원장 준비는 잠금 후 자격 확인 뒤, 완료 기록은 DB 커밋 뒤 수행한다. 실패하면 후속 대상을 처리하지 않고 중단하며, 원장·DB 상태를 확인하기 전 재실행하지 않는다.

운영 앱 이미지·약관 환경은 바꾸지 않는다. NAS 공유폴더 ACL로 컨테이너 읽기가 거부되는 것을 피하기 위해, 검토·커밋된 두 정리 소스만 root 소유 임시 디렉터리에 복사한다. 폴더는 0755, 파일은 0644로 두고 Git 원문 해시와 대조한 다음 운영 ops 이미지에 읽기 전용으로 연결한다. 저장소 ACL·권한은 바꾸지 않고 실행 계정 UID 1000도 유지한다. 종료 시 해당 임시 코드 파일 두 개와 폴더만 제거한다. 자동 복원·새 약관 시행·기록 보유 계정 삭제는 실행하지 않는다. 관리자 접근 증거 등 기존 분리 보존 자료와 백업·삭제 원장의 보관 및 복원 통제는 유지한다.

같은 이메일을 사용하는 다른 계정의 자료를 삭제하지 않도록, 이 일괄 정리에서는 이메일만으로 조회되는 문의·인증 코드까지 삭제 범위를 넓히지 않는다. 해당 잔여 자료는 기존 보유기간 정리 경로를 따른다.

빈 계정만 정리한 뒤에도 일반 계정 4개가 남으므로 최초 계약 모드의 일반 계정 0개 조건은 충족되지 않는다. 나머지 계정의 처리·동의·공고 경로는 별도로 결정한다.

## 남은 테스트 계정의 기록 포함 삭제 — 추가 승인

실제 빈 계정 정리 결과는 기준 시각 이후 1개가 제외되어 201개 삭제, 일반 계정 5개와 관리자 7개 유지였다. 운영자는 남은 일반 계정도 모두 테스트용임을 확인하고 기록을 포함한 삭제를 추가 승인했다. 관리자와 관리자 기록은 제외한다.

기록 포함 삭제는 기본 모드와 분리된 `--include-records`가 필요하다. 다음 조회로 대상 5개와 기록·기록집 수, 계정 ID 및 계획 해시를 확인한다. 고정 기준 시각 이후 생성된 계정은 포함하지 않는다.

```sh
sudo sh scripts/ops/tuti-empty-account-cleanup --created-before 2026-10-23T00:00:00Z --expected-count 5 --include-records
```

조회 결과와 해시가 확인된 뒤에만 같은 명령에 `--plan-hash <확인한해시> --apply`를 추가한다. 기록 포함 여부·기록 및 기록집 ID/수정 시각도 계획 해시에 포함한다. 사용자와 소유 기록·기록집 행을 잠근 뒤 권한·생성 시각·관련 자산 스냅샷을 다시 확인하며, 변경되면 건너뛴다. 별도 삭제 원장을 준비한 다음 이미지·PDF 정리, DB 삭제 및 커밋 후 원장 완료 순서를 따른다. 자산 삭제·원장·DB 처리 실패 시 중단한다. 부분 실패의 경우 일부 파일이 이미 삭제됐을 수 있으므로 상태 확인 전 재실행하지 않는다. 계정과 관계없는 관리자 접근 증거, 공유 이메일 자료 및 백업 보존 통제는 유지한다.

이 추가 도구는 새 약관 공고·강제 동의 설정을 자동 변경하지 않는다.
