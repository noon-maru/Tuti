# 카페·찻집 추천 후보 확충

기준일: 2026-11-13. 작은 여행에서 산책 외에 잠시 앉아 머무는 경험을 제공한다.
기존 관광지·문화시설·여행코스·레포츠 수집을 음식점 전체 수집으로 바꾸지는 않는다.

## 확인한 원인과 범위

초기 수집 스크립트의 콘텐츠 유형에는 음식점(`39`)이 없었다. 개발 DB 조회에서도
해당 유형 원천 데이터는 0건이었다. 이는 운영 DB 집계가 아니다.

기존 이름 검색 결과 48건을 시설명·저장된 공식 소개로 보수적으로 분류했다.

| 판정 | 건수 | 처리 |
| --- | ---: | --- |
| 카페 매장 후보 | 6 | 기존 추천 2곳, 비활성·반려·이미지 누락 4곳 개별 검토 |
| 관련 명소 | 37 | 카페거리·공원·박물관·농원·동물 체험·족욕 등의 기존 정체성 보존 |
| 판단 보류 | 4 | 커피 이름만으로 공장·체험·매장을 구분하지 않음 |
| 무관한 시설 | 1 | 카페리 터미널을 카페로 처리하지 않음 |

매장 후보는 한옥카페 갤러리 도솔, 마린데크(커피마린협동조합), 카페 방림별곡,
우리글방 북카페, 홍대카페(ㅎㄷ 카페), 천왕산 북카페다. 기존에 추천 가능한 곳은
우리글방 북카페와 천왕산 북카페였다. 카페 방림별곡·홍대카페의 반려/숨김은
자동 해제하지 않았다. 쓰다북스 x 원더러스트커피 등 판단 보류 장소는 개별 검토한다.
이 판정은 현재 영업·좌석·가격·조용함을 보증하지 않는다.

## 분류·추천 규칙

- 관광공사 신분류 `FD050100`(카페), `FD050200`(찻집)만 신규 수집한다.
  `FD050300`(기타음료점), 식당·주점은 자동 수집하지 않는다.
- 구분류 `A05020900`은 기존 원천 데이터 판정에만 활용한다.
  새 수집 API 필터는 신분류와 법정동 코드를 사용한다.
- 카페는 별도 `cafe` 경험 유형이다. 기존 유형 다양화가 카페를 구분할 수 있다.
  분위기·혼잡도·조용함·실내 여부는 카페라는 이유만으로 생성하지 않는다.
- 체류시간 근거가 없을 때 카페 경험 기본값은 최소 15분·대표 30분·최대 90분이다.
  실제 영업 정보나 사용자가 지정한 이동시간을 대체하지 않는다.
- 자연·관광 수요 연계가 없어도 짧게 머무는 카페 경험을 평가한다.
  사진·좌표 결손과 폐업 표현은 기존 제외 조건을 유지하고, 공식 소개가 없으면 보강 대상으로 남긴다.
- 무료 입장 표기만으로 카페를 무료 예산 추천에 넣지 않는다. 음료 가격을 추정하거나 무료라고 안내하지 않는다.
- 후보 평가 `low-burden-v5`, 파생 특성 `place-features-v5`를 사용한다.
  기존 데이터의 값은 별도 후보·체류시간 갱신 전까지 소급 변경되지 않는다.
  요청 시 외부 API나 LLM을 새로 호출하지 않는다.

## 조회·수집 도구

기존 장소 감사는 읽기 전용 트랜잭션이며 외부 API를 호출하지 않는다.

```sh
pnpm exec tsx scripts/audit-tourism-cafes.ts
```

수집은 기본 조회 전용이다. 다음 예시는 서울(법정동 시도 코드 11)의 카페·찻집을
각각 최대 10건 조회한다. 식당 전체를 조회하지 않는다.

```sh
pnpm exec tsx scripts/sync-tourism-cafes.ts --region-code 11 --rows 10
```

출력의 대상·사진 여부·`planHash`를 확인한 뒤 같은 인자에
`--apply --expected-plan-hash <확인한 planHash>`를 추가해야 DB에 저장한다.
API 결과가 바뀌어 해시가 달라지면 쓰기 전에 중단한다. `--pages`, `--start-page`,
`--district-code`로 범위를 정할 수 있으며 한 번에 최대 200건이다.
CLI의 DB 연결은 해당 실행 환경의 설정을 사용하므로 운영·개발 환경을 혼동하지 않는다.

원천·신규 장소·원천 연결·공간 좌표는 한 트랜잭션으로 저장한다. 기존 장소는
사진·문구·승인·숨김·수동 포함/제외를 덮어쓰지 않는다. 신규 장소는
`reviewStatus=pending`, `isActive=false`, `candidateOverride=exclude`로 등록한다.
후보 정기 갱신만으로 검토 잠금이 풀리지는 않는다. 대표 이미지나 좌표가 없으면
장소를 만들지 않고 원천만 보관한다. 잘못된 이미지를 대체 삽입하지 않는다.

## 개발 환경 시험 결과와 공개 전 남은 일

카페·찻집 신분류 API 호출에서 서울 카페 241건·찻집 12건을 확인했다.
이는 해당 시점 API 등록 건수이며 서울 전체 매장 수가 아니다.

- 대상 해시를 확인한 20건을 개발 DB에 저장했다.
- 이미지가 있는 12곳을 비공개·검토 잠금 상태로 등록했다.
- 이미지가 없는 8곳은 원천만 저장했다.
- 기존 장소 변경·반려 해제·추천 공개·운영 DB 반영·사용자 데이터 변경은 하지 않았다.

공개 전에는 저장된 상세 소개·영업·비용 정보를 보강하고, 원문에 근거한 요약과
행동 문구·체류시간을 점검한다. 개별 승인 후에만 검토 잠금을 해제하고 후보를
다시 평가한다. 현재 원천은 있지만 이미지가 없는 장소는 이용 가능한 사진을
확보한 뒤 등록을 재시도한다. 전국 전체 수집이나 카페 일괄 공개는 이 시험 결과에 포함하지 않는다.

### 2026-11-13 상세 보강

개발 DB의 등록된 12곳에 공식 소개·영업시간·휴무·메뉴 정보를 수집하고 원문을
직접 검토해 180자 이내 요약·60자 이내 행동 문구를 작성했다. 건강 효능·무료 이용·
현재 좌석 여유를 추정하지 않는다. 일반 음료 가격은 원천에 없어 12곳 모두 미확정이다.
발레파킹 등 별도 비용 안내는 원천 주차 정보에 유지한다.

요약·행동 문구는 공통 배포 데이터에 포함했고, 검토 원문의 지문은
`data/cafe-editorials/2026-11-13.json`에 고정했다. 다음 도구는 기본 조회 전용이며
`--apply --expected-plan-hash <조회한 해시>`를 지정해야 보강한다.

```sh
pnpm exec tsx scripts/prepare-cafe-editorials.ts
```

원문 변경·반려·숨김·기존 편집 문구·명시 체류시간·수동 체류시간은 자동 덮어쓰지
않는다. 요약·행동·기본 체류시간을 한 트랜잭션에 저장하고 각 행의 동시 변경을 검사한다.
체류시간 원문이 없어 최소 15분·대표 30분·최대 90분의 경험 기본값을 저장했으며
실측이나 LLM 추정으로 표시하지 않는다. 선택 티클래스 예약은 일반 카페 이용 전체의
예약 의무로 확대하지 않는다. 12곳의 공개·승인·검토 잠금은 변경하지 않았다.

공식 데이터 안내: [한국관광공사 국문 관광정보 서비스](https://www.data.go.kr/data/15101578/openapi.do).
분류 코드는 해당 API의 `lclsSystmCode2` 응답으로 확인했다. 사진의 출처·이용조건은
개별 원천 정보를 유지하며 지도·리뷰·사진 크롤링은 사용하지 않는다.
