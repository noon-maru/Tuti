# 저널 기록 공유

저널 상세 화면의 `기록 공유하기`는 현재 화면을 캡처하지 않고 기록 데이터로
별도의 공유 카드를 렌더링한다. 화면 크기와 플랫폼에 관계없이 결과물은 항상
1080×1350의 PNG다.

## 이미지 구성

- 방문 날짜와 기록 제목
- 기록 이미지 또는 브랜드 컬러 대체 배경
- 혼잡도, 장소, 난이도
- 기록 본문 일부
- Tuti 워드마크와 브랜드 문구
- 신고 대응을 위한 짧은 Tuti 추적 코드

공유 카드는 실제 앱 화면과 분리된 1080×1350 DOM으로 렌더링하고
`html-to-image`로 PNG Blob을 만든다. Pretendard의 로딩과 카드 내부 이미지
디코딩, 두 번의 브라우저 페인트가 끝난 뒤 생성하므로 플랫폼별 첫 프레임
차이를 줄인다. PNG는 공유 다이얼로그가 열릴 때 미리 생성되어 사용자가
`공유하기`를 누르는 시점에는 운영체제 공유 UI를 즉시 열 수 있다.

## 플랫폼별 전달

- 웹은 `navigator.canShare({ files })`를 통과하면 Web Share API로 PNG
  파일 하나만 전달한다. 제목, 설명, URL은 같은 payload에 섞지 않는다.
- 파일 공유를 지원하지 않는 웹 브라우저에서는 PNG 다운로드로 대체한다.
- Capacitor 앱은 PNG를 앱 캐시 디렉터리에 잠시 기록하고
  `@capacitor/share`로 iOS·Android 공유 시트에 파일 하나만 전달한다.
- 네이티브 공유가 끝나거나 취소되면 캐시 파일을 정리한다.

네이티브 프로젝트가 생성된 뒤에는 `pnpm cap:sync`로 Filesystem과 Share
플러그인을 반영한다. Filesystem 플러그인의 iOS Privacy Manifest 사유도
앱 프로젝트 생성 단계에서 함께 설정한다.

## 공유 이미지 추적

공유 다이얼로그를 열면 서버가 먼저 32자의 추적 ID와 사람이 읽을 수 있는
짧은 코드를 발급한다. 짧은 코드는 공유 카드 하단에 표시된다. 클라이언트가
1080×1350 PNG를 만든 뒤 원본 PNG를 서버에 전달하면 서버는 다음 작업을 한다.

1. 요청한 사용자가 해당 저널 기록의 소유자인지 확인한다.
2. PNG 형식, 크기, 해상도를 검증한다.
3. 메타데이터 삽입 전 이미지의 SHA-256을 계산한다.
4. 추적 ID, 최초 사용자 ID, 기록 ID, 이미지 해시, 발급 시각을 HMAC으로
   서명한다.
5. 해시와 서명, 완료 시각을 `journal_share_traces`에 저장한다.

최종 PNG에는 국제 문자열을 지원하는 PNG `iTXt` 청크로 다음 정보를 넣는다.

- `Publisher`: Tuti
- `Software`: Tuti
- `Tuti Trace ID`, `Tuti Short Code`
- `Tuti Signature`, `Tuti Image SHA256`
- 생성 시각과 Tuti 서비스 주소

내부 사용자 ID와 기록 ID는 PNG에 직접 노출하지 않고 서버의 감사 기록에만
보관한다. 계정을 병합하면 감사 기록의 `resolved_user_id`도 새 계정으로
이동하지만, 서명에 사용한 최초 사용자 ID는 변경하지 않는다. 계정 또는 저널을
삭제하면 연결된 공유 추적 기록도 함께 삭제한다.

`JOURNAL_SHARE_TRACE_SECRET`이 설정되어 있으면 추적 서명에 사용한다. 비어
있으면 기존 `AUTH_EMAIL_CODE_SECRET`을 용도 문자열로 분리해 사용한다. 두
값 모두 32자 이상이어야 한다.

메신저나 SNS가 PNG를 재인코딩하면 텍스트 메타데이터가 제거될 수 있다.
이때는 이미지에 보이는 짧은 추적 코드를 이용해 서버 기록을 조회한다.

운영 환경에서는 외부 조회 API를 열지 않고 builder 이미지 안의 서버 전용
명령으로 조회한다.

```bash
pnpm journal:trace -- 8C44-6B78-7384
```

결과에는 최초·현재 사용자 ID, 기록 ID, 이미지 해시, 서명 검증 결과와 생성
시각이 포함된다. 이 출력은 내부 감사 정보이므로 외부에 그대로 공유하지 않는다.

## 공개 링크

- 첫 App Store 출시에서는 `NEXT_PUBLIC_JOURNAL_PUBLICATION_ENABLED=false`로
  인터넷 공개 UI와 서버 생성을 모두 차단한다.
- 배포 마이그레이션은 기존 공개 식별자와 공개 시각을 제거하므로 과거 주소와
  공개 이미지 주소도 404를 반환한다.
- PNG 저장과 운영체제 공유는 계속 제공한다.
- 게시 전 필터링, 신고 대응과 사용자 차단을 갖춘 뒤에만 공개 링크를 다시
  활성화한다.

## 향후 구현 사양: 기록 웹 링크 공유 재활성화

공개 링크 공유는 폐기한 기능이 아니라 안전한 공개 운영 체계를 갖춘 뒤
재활성화할 기능이다. 기본 공유 수단은 계속 PNG로 유지하며, 웹 링크는 사용자가
명시적으로 공개한 기록에만 추가로 제공한다.

### 공개 상태 모델

기록 공개 상태는 URL 필드의 유무만으로 판단하지 않고 다음 상태를 명시적으로
저장한다.

- `private`: 비공개. 공개 식별자와 공개 시각이 모두 없다.
- `pending`: 안전 검사 또는 관리자 확인 대기. 공개 식별자는 발급됐지만 외부에서
  조회할 수 없다.
- `published`: 외부 공개 중. 유효한 공개 식별자와 공개 시각이 모두 있다.
- `hidden`: 신고 또는 관리자 조치로 숨김. 기존 식별자는 감사와 처리 이력을 위해
  유지하지만 공개 페이지와 이미지 API는 항상 404를 반환한다.

DB 제약조건과 공개 조회 함수가 이 상태를 함께 검증한다. 사용자가 공개를
중지하면 상태를 `private`으로 바꾸면서 기존 공개 식별자와 공개 시각을 제거한다.
따라서 다시 공개할 때는 과거 주소를 재사용할 수 없다. 관리자 조치로 `hidden`이
된 기록은 소유자가 임의로 재공개할 수 없다.

기록 삭제 시 공유 이미지 추적 레코드는 같은 DB 트랜잭션에서 삭제하고, 접수된
신고는 당시 제목·공개 식별자 스냅샷을 남긴 채 원본 기록 연결만 해제한다.
공개 페이지의 최초 HTML에는 기록 본문과 이미지 주소를 포함하지 않는다. 브라우저가
Tuti 세션으로 공개 API를 호출한 뒤에만 내용을 받으며, 작성자를 차단한 사용자는
같은 링크를 다시 열어도 본문과 인증된 이미지 API 모두 404를 반환한다.

### 제품 원칙

- 모든 기록은 기본적으로 비공개다.
- 계정을 연결한 기록 소유자만 인터넷 공개를 선택할 수 있다.
- 공개 전에 `링크를 아는 사람은 누구나 볼 수 있음`을 명확하게 안내한다.
- 공개 안내에는 실제 접근 조건인 `링크를 받은 사람`과 공개되는 필드,
  공개되지 않는 계정·위치정보를 함께 안내하고 동의 버전과 시각을 기록한다.
- PNG 공유와 인터넷 공개를 하나의 동작으로 묶지 않는다.
- 공개를 중지하거나 기록·계정을 삭제하면 기존 주소와 이미지 접근을 즉시
  차단한다.
- 공개 페이지에는 계정 ID, 이메일, 원본 이미지 메타데이터와 같은 내부 정보를
  노출하지 않는다.
- 초기 재활성화 단계에서는 검색엔진 색인을 허용하지 않고 링크를 전달받은
  사람만 접근하는 형태로 운영한다.

### 사용자 흐름

1. 기록 메뉴에서 `인터넷에 공개`를 선택한다.
2. 공개 범위와 주의사항을 확인하고 명시적으로 동의한다.
3. 서버가 추측하기 어려운 `publicId`를 발급하고 `/shared/{publicId}` 주소를
   생성한다.
4. 공개가 완료된 기록에는 `웹 링크로 공유`, `공유 링크 복사`, `PNG로 공유하기`,
   `공개 중지`를 각각 제공한다. 웹 링크 공유를 지원하지 않는 브라우저에서는
   링크 복사로 대체한다.
5. 공개 중지 후 같은 기록을 다시 공개하면 과거 주소를 재사용하지 않고 새로운
   `publicId`를 발급한다.

현재 공개 설정 API, 공개 페이지, 공개 이미지 API, 링크 복사 UI와 신고 접수
기반은 구현되어 있다. 기능 플래그가 꺼진 출시 빌드에서는 이 UI와 공개 데이터가
노출되지 않는다.

### 재활성화 전 필수 운영 기능

- [x] 공개 전 연락처·외부 링크·위험 표현·반복 홍보 패턴의 로컬 텍스트 검사
- [x] 자동 판정하지 못하는 사용자 이미지를 공개 전 관리자 검토 대상으로 분리
- [x] 관리자 콘솔에서 공개 대기 기록의 원문·이미지·검토 사유 확인 및 승인·거절
- [x] 공개 페이지에서 접근 가능한 신고 기능과 신고 사유 선택
- [x] 관리자 콘솔의 신고 검토, 즉시 숨김, 공개 복원, 강제 삭제와 처리 이력
- [x] 신고 대상 이용자의 기존 공개 기록 숨김 및 추가 공개 제한·해제 상태
- [x] 이용자가 공개 기록 작성자를 차단하고 계정 화면에서 해제할 수 있는 기능
- [x] 반복 공개 요청을 막는 세션 및 IP 기준 rate limit
- [x] 공개, 공개 중지, 신고, 숨김, 삭제, 제재에 대한 감사 로그
- [x] 운영정책, 신고 처리 기준, 문의 경로와 처리 담당자 명시
- [x] 개인정보 처리방침 개정안에 공개 범위와 삭제 정책 반영

기록 공개 운영정책은 `/legal/community-guidelines`, 2026년 10월 1일 시행
개인정보 처리방침 개정안은 `/legal/privacy/2026-10-01`에서 확인한다. 공개
동의 화면과 서버는 `journal-publication-2026-10-01` 버전이 일치할 때만 공개
요청을 허용한다.

자동 필터링 결과만으로 기록을 영구 삭제하지 않는다. 위험도가 높은 콘텐츠는
우선 노출을 보류하고 관리자가 검토하며, 명백한 불법 콘텐츠와 긴급 신고를 위한
별도 대응 절차를 둔다.

### 단계별 재도입

#### 1단계 — 내부 검증

- 운영자가 지정한 테스트 계정에만 공개 기능을 노출한다.
- 공개·중지·삭제 시 주소와 이미지 접근이 즉시 바뀌는지 확인한다.
- 신고부터 관리자 조치까지의 전체 흐름과 감사 로그를 검증한다.

#### 2단계 — 제한 베타

- 로그인한 베타 사용자에게만 공개 기능을 제공한다.
- 검색엔진 색인은 계속 차단한다.
- 신고량, 필터 오탐률, 처리시간과 공개 중지 실패율을 관찰한다.

#### 3단계 — 정식 제공

- 스토어 심사 정보, 이용약관과 개인정보 처리방침을 갱신한다.
- 운영 대응시간과 제재 정책을 확정한 뒤
  `NEXT_PUBLIC_JOURNAL_PUBLICATION_ENABLED=true`로 배포한다.
- 기능 플래그 활성화만으로 끝내지 않고, 활성화 배포 전에 운영 DB 마이그레이션과
  공개 링크 회귀 테스트를 실행한다.

### 완료 기준

- 비공개 기록과 공개 중지된 기록이 공개 API에서 항상 404를 반환한다.
- 계정이 없는 사용자와 기록 소유자가 아닌 사용자는 공개 상태를 변경할 수 없다.
- 신고된 콘텐츠를 관리자가 즉시 숨기고 처리 결과를 기록할 수 있다.
- 작성자 차단 후 해당 작성자의 공개 기록이 차단한 사용자에게 노출되지 않는다.
- 기록·계정 삭제 시 공개 이미지와 관련 신고·추적 데이터가 정의된 정책에 따라
  삭제 또는 법적 보존 상태로 전환된다.
- 웹, iOS, Android에서 링크 열기·복사·공개 중지 흐름을 모두 검증한다.
- App Store와 Google Play의 사용자 생성 콘텐츠 정책 점검을 통과한다.

## 앱과 웹의 주소

- 웹은 현재 서비스의 origin을 기준으로 공개 주소를 만든다.
- Capacitor 앱은 `NEXT_PUBLIC_API_BASE_URL`의 origin을 기준으로 웹 공개
  주소를 만든다.
- 공개 링크가 비활성화된 출시 빌드는 웹 주소를 만들거나 복사하지 않는다.

PNG 공유는 파일만 전달하며 공개 주소를 payload나 PNG 메타데이터에 포함하지
않는다.
