# 장소 체류시간 및 전체 소요시간 전처리

## 목적

사용자가 고른 시간은 이동시간만이 아니라 왕복 이동, 입장 준비, 주차, 체류, 개장 대기를 포함한 전체 시간으로 해석한다. 추천 요청 중에는 LLM을 호출하지 않으며, 공개 관광정보를 오프라인에서 구조화한 결과만 읽는다.

## 2026-10-02 데이터 현황

- 추천 가능 장소: 3,666곳
- 체류시간 원문 보유: 94곳, 2.6%
- LLM이 수치형 원문을 최소·일반·최대로 파싱: 67곳
- LLM이 가변 문구 또는 오염 데이터로 판정: 27곳

- 최종 방문시간 프로필 생성: 3,666곳, 누락 0곳
- 잘못된 시간 범위: 0곳
- 주차정보를 분류하지 못해 안전 기본값을 적용: 824곳

LLM 판정 원본은 `data/place-visit-time-profiles/2026-10-02-explicit-*.jsonl`에 보관한다. `explicit-input` 파일은 당시 사용한 공공데이터 원문을 재현하기 위한 입력 스냅샷이다.

## 2026-10-06 추천 후보 추가에 따른 보완

후보 재평가로 안견기념관(`130109`)이 추천 대상에 추가되어 기존 입력 스냅샷에
없던 체류시간 원문 `약 20분` 때문에 운영 배포의 완전성 검증이 중단되었다.
운영 상세 API에서 공공 관광정보 원문을 확인하고 기존 배치에 입력 스냅샷과
`explicit-d` 결과를 함께 추가했다. `manual_override`로 안내시간 20분을 보존하며,
실측 자료가 없는 최소·최대 편차는 임의로 추정하지 않는다. 누락·원문 변경 검증은 유지한다.

## 부가 전처리

`PlaceVisitTimeProfile`은 다음 정적 정보를 함께 저장한다.

- 체류시간 최소·일반·최대
- 자유 방문·고정 체험·회차형 방문 여부
- 구내 주차·인근 주차·주차 불가·불명
- 자동차 접근 적합성
- 자유 입장·현장 발권·체크인·장비 준비
- 예약 없음·권장·필수
- 선박·케이블카·긴 도보·출입 제한
- 주차와 입장 준비의 최소·일반·최대 여유시간
- 산정 근거, 기본값 적용 필드, 신뢰도, 모델, 버전, 소스 지문

주차와 입장 시간은 LLM이 임의의 숫자를 만들지 않는다. 원문에서 상태를 분류하고 다음 고정표로 시간 범위를 부여한다.

| --- | ---: | ---: | ---: |
| 구내 주차 | 5분 | 10분 | 15분 |
| 인근 주차 | 10분 | 15분 | 25분 |
| 주차 불가 | 15분 | 25분 | 40분 |
| 주차 불명 | 10분 | 20분 | 30분 |

## 요청 시 전체 소요시간

사용자 출발지는 사전 계산할 수 없으므로 이동시간과 개장 대기는 추천 요청 시 계산한다.

```text
최소 총시간 = 왕복 이동 + 개장 대기 + 최소 준비시간 + 최소 체류시간
일반 총시간 = 왕복 이동 + 개장 대기 + 일반 준비시간 + 일반 체류시간
최대 총시간 = 왕복 이동 + 개장 대기 + 최대 준비시간 + 최대 체류시간
```

실제 경로가 아직 없으면 직선거리와 선택 이동수단으로 빠른 이동시간을 추정한다. 최초 추천은 속도를 위해 이 추정값을 사용하고, 카드와 출발 준비 화면에서 조회한 실제 경로는 이동 안내에 사용한다. 실제 경로가 있는 상태에서 실행 가능성을 다시 계산하면 추정값 대신 실제 경로가 우선된다. 위치가 없으면 이동 적합성을 단정하지 않고 `unknown`으로 유지한다.

시간 적합성은 다음처럼 구분한다.

- `comfortable`: 일반 총시간이 가용시간의 85% 이하
- `possible`: 일반 총시간이 가용시간 안에 포함
- `tight`: 최소 총시간만 가용시간 안에 포함
- `unknown`: 위치가 없어 이동시간을 추정할 수 없음
- `impossible`: 최소 총시간도 초과하거나 휴무·접근 불가

`impossible`만 추천 후보에서 제외하고, 나머지는 여유 정도를 순위에 반영한다.

## 반영 절차

```bash
pnpm db:deploy
pnpm places:candidates:refresh
pnpm places:visit-times:import
pnpm places:visit-times:import -- --apply
pnpm places:candidates:evaluate
pnpm recommendations:regression
pnpm recommendations:quality-regression
```

원천 상세정보와 추천 후보를 먼저 갱신한 뒤 프로필을 만든다. 프로필 반영 후의 후보 재평가는 `--skip-enrichment`를 사용하는 `places:candidates:evaluate`로 실행해, 방금 프로필에 사용한 원문이 다시 바뀌지 않게 한다. 재평가로 추천 대상에서 빠진 과거 프로필은 다음 import에서 무시되며, 새 대상에 프로필이 없으면 실행 시 기본표를 안전 대체값으로 사용한다.

기본적으로 `2026-10-02` 배치를 사용한다. 새 원문을 재전처리한 뒤에는 다른 배치와 결과가 섞이지 않도록 `--batch YYYY-MM-DD`를 지정한다. 수동 보정도 DB에 직접 입력하지 않고 해당 배치 JSONL에 `manual_override`로 남겨 재실행 시 유지한다.

```bash
pnpm places:visit-times:import -- --batch 2026-10-02
pnpm places:visit-times:import -- --batch 2026-10-02 --apply
```

체류시간 규칙이나 프로필 버전이 바뀐 경우에도 같은 import를 다시 실행해야 기존 DB 행이 갱신된다. import는 DB에 과거에 저장된 경험 유형을 재사용하지 않고 현재 분류 규칙으로 유형을 다시 계산한다. dry-run 출력의 `defaultProfiles`로 시설 규칙별 적용 건수를 먼저 확인한 뒤 `--apply`하고, 이후 후보 재평가와 회귀 검증을 실행한다.

가져오기 작업은 LLM JSONL의 필드, 중복, 추천 장소 완전성, 정수 범위, `최소 ≤ 일반 ≤ 최대`를 검증한다. DB에도 동일한 CHECK 제약을 적용한다.
추가로 구조화 당시의 `explicit-input` 스냅샷과 현재 체류시간 원문을 비교한다. 원문이 바뀌었으면 이전 LLM 결과를 새 자료처럼 저장하지 않고 재전처리를 요구한다. 현재 추천 대상에서 빠진 과거 결과는 오류로 취급하지 않고 무시한다.
