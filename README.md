# Tuti

**Tuti**는 작은 외출을 발견하고, 함께한 순간을 기록하여, 소장할 수 있는
결과물로 만드는 **라이프로그 서비스**입니다.

멀리 떠나지 않아도 됩니다. 혼자 또는 소중한 사람과 보낸 평범한 하루도
기억하고 싶은 작은 여행이 될 수 있습니다. Tuti는 관광지를 많이 보여주거나
복잡한 여행 계획을 만드는 앱보다, **좋은 하루를 쉽게 시작하고 남기는 경험**을
지향합니다.

`발견 → 외출 → 기록 → 축적 → 소장 → 다시 외출`은 앞으로 검증할 핵심
경험의 흐름입니다. 현재는 장소 추천, 기록, 무료 디지털 기록집을 제공하고
있습니다. 실물 기록집 판매는 아직 제공하지 않습니다.

기존의 `나가고 싶지만 결정하기 어렵다`는 문제도 계속 다룹니다. 여기에
`함께 보낸 순간이 사진첩 속에 흩어진다`는 문제를 더해 외출 이후까지
살펴보려 합니다.

## 서비스 한 줄 소개

**작은 외출을 발견하고, 함께한 순간을 기록하여, 소장할 수 있는 결과물로 만드는 라이프로그 서비스**

여기서 라이프로그는 일상을 자동으로 추적한다는 뜻이 아닙니다. 사용자가
남기고 싶은 사진과 짧은 이야기를 직접 골라 기록하는 경험을 말합니다.
`함께한 순간`은 대표적인 사용 장면이지 이용 조건은 아닙니다. 혼자 보낸
시간도 기록할 수 있습니다. 현재 소장할 수 있는 결과물은 무료 디지털
기록집이며, 실물 기록집은 구매 가설을 검증하는 다음 단계입니다.

## 왜 필요한가

작은 외출도 장소를 고르고 이동을 알아보는 과정에서 미뤄질 수 있습니다.
함께 잘 보낸 하루는 사진으로 남아도, 시간이 지나면 그 순간의 이야기를
찾거나 한 권으로 엮기 어렵습니다.

Tuti는 선택과 기록의 부담을 낮추는 방향을 탐색합니다. 어디로 갈지 가볍게
고르고, 사진과 짧은 글로 남기며, 쌓인 기록을 다시 볼 수 있게 합니다.
기록이나 구매를 강요하지는 않습니다.

실물 기록집은 무료 경험 위에 더할 첫 수익화 가설입니다. 실제 구매가
확인되기 전까지 수요가 검증된 상품으로 소개하지 않습니다.

## 핵심 관점

Tuti의 추천은 목적지가 아니라 다음에 남길 하루를 시작하는 출발점입니다.

> “두 시간 정도 여유 내볼 수 있을까요?”

가까운 곳도 충분합니다. 함께 걷거나 잠깐 머문 시간이 나중에 다시 꺼내 볼
기억이 될 수 있다는 관점을 유지합니다.

## 주요 사용자

**첫 고객 가설은 20~25세 여성**입니다. 연인·친구와 데이트나 나들이를 하고
사진을 자주 남기는 사람, 그중에서도 기념일·생일·여행의 기억을 실물로
간직하고 싶은 커플 고객의 구매 가능성을 먼저 검증합니다.

이는 확정된 최종 타깃이 아닙니다. 다른 연령·성별·관계의 이용자를 배제하지
않고, 앱 전체를 먼저 특정 집단용으로 바꾸지도 않습니다. 실제 정상가 구매,
배송 후 만족과 반복 이용을 확인한 뒤 고객 가설과 제품 방향을 다시 판단합니다.
구분된 가설과 검증 기준은 [제품 방향](docs/product-direction.md)에 정리했습니다.

## 사용자 경험

Tuti는 긴 설문을 요구하지 않습니다. 기본 진입에서는 두 가지를 묻고,
`오늘 하루`를 고르면 출발일을 추가로 묻습니다.

1. 오늘 바깥에 얼마나 시간을 낼 수 있나요?
2. 차로 움직일 수 있나요?
3. `오늘 하루`를 골랐다면 언제 떠날까요?

위치를 허용하거나 시·군·구를 직접 고른 뒤 추천 카드를 둘러볼 수 있습니다.
조건에 맞는 후보가 적으면 개수를 억지로 채우지 않습니다.

## 핵심 기능

### 짧은 질문

시간 범위와 자동차 이용 여부를 짧게 묻습니다. 오늘 하루 외출에는 출발일을
추가로 확인합니다.

### 이동 부담

Tuti의 추천 기준은 단순한 거리만이 아닙니다. 사용자가 고른 시간과
이동수단을 먼저 확인하고, 가능한 범위의 장소를 보여줍니다.

어떤 날은 집 앞 공원이 좋고, 어떤 날은 강변이나 근교까지 갈 수 있습니다.
추천의 역할은 더 멀리 가게 하는 것이 아니라 다음 하루를 시작하기 쉽게 하는
것입니다.

### 감각 카드 추천

추천 결과는 감각 카드로 제공됩니다. 카드를 뒤집어 짧은 설명을 보고,
더 필요할 때 장소 상세와 출발 준비를 엽니다.

- 장소 이름과 짧은 설명
- 이동 시간
- 장소에서 가볍게 할 수 있는 일

### 상세 화면

상세 화면도 관광 정보 나열을 피합니다. 사용자가 “아, 이런 공기구나”라고 느낄 수 있도록 이미지와 짧은 설명을 중심으로 구성합니다.

### 나의 기록

기록 화면은 성취나 성장 관리가 아닙니다. 사진과 짧은 글로 다녀온 순간을
남기고, 선택한 기록으로 무료 디지털 기록집을 만들 수 있습니다. 기록은
기본적으로 비공개이며 사용자가 선택한 기록만 웹 링크로 공개할 수 있습니다.

## Tuti가 하지 않는 것

Tuti는 다음을 지향하지 않습니다.

- 여행 일정 생성
- 관광지 정보 과다 제공
- 리뷰와 평점 경쟁
- SNS 피드
- 성취 시스템
- 생산성 관리
- AI 챗봇형 대화

Tuti는 외출이나 기록을 숙제로 만들지 않습니다. 한 번의 나들이도 부담 없이
시작하고, 기억하고 싶은 순간만 남길 수 있어야 합니다.

## 현재 제공 범위

- 웹과 Capacitor 기반 Android·iOS 앱
- 시간·이동수단과 현재 위치 또는 직접 고른 지역을 이용한 장소 추천
- 장소 상세, 길찾기, 다음에 갈 공간, 기록과 디지털 기록집
- 선택한 기록의 PNG 공유 및 동의 후 웹 링크 공개
- 선택적 계정 연결, 기기 간 기록 불러오기, 1:1 문의와 알림

실물 기록집 주문·결제·배송은 아직 구현되지 않았습니다.

현재 구현과 향후 검토안을 구분한 문서 목록은 [문서 안내](docs/README.md)를
참고합니다.

## 실행 방법

처음 실행할 때는 공통 env와 개발 서버 env를 각각 준비합니다.

```bash
cp .env.example .env
cp .env.development.example .env.development
```

Docker가 설치되어 있다면 다음 명령으로 실행할 수 있습니다.

```bash
docker compose -f docker-compose.dev.yml up
```

브라우저에서 아래 주소로 접속합니다.

```text
http://localhost:5080
```

## 검증 명령

```bash
docker compose -f docker-compose.dev.yml run --rm app sh -lc "pnpm lint"
docker compose -f docker-compose.dev.yml run --rm app sh -lc "pnpm build:web"
docker compose -f docker-compose.dev.yml run --rm app sh -lc "pnpm test"
```

`build:app`은 `.app-build/`에 서버 전용 경로를 제외한 임시 Next.js
프로젝트를 만들고 static export합니다. 원본 Route Handler는 변경하지
않습니다. 네이티브 빌드 절차는 [Android](docs/android-build.md)와
[iOS](docs/ios-build.md) 문서를 따릅니다.

## DB 설정

개발용 Docker Compose는 `.env.development`를 읽어 PostGIS가 포함된
PostgreSQL을 함께 실행합니다. 접속 정보는 각자의 개발 환경 파일을 확인합니다.

마이그레이션과 seed 데이터는 app 컨테이너 안에서 실행합니다.

```bash
docker compose -f docker-compose.dev.yml run --rm app sh -lc "pnpm db:deploy && pnpm db:seed"
```

## 배포 환경

운영 설정은 `.env.production.example`을 참고하되 비밀값을 저장소에 넣지
않습니다. 정식 웹 배포는 NAS에서 직접 빌드하는 방식이 아니라
[운영 명령](docs/operations.md)의 수동 GitHub Actions 배포 절차를 사용합니다.
출시 문구는 [공통 출시 노트](docs/release-notes.md)에서 관리합니다.

Tuti의 목표는 더 많은 여행지를 보여주는 것이 아닙니다.

> 가까운 곳에서 보낸 작은 하루를 발견하고, 기억하고 싶다면 오래 간직할 수 있게 하는 것
